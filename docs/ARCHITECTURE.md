# 架构决策记录

> 本文档记录关键架构决策（ADR: Architecture Decision Records），
> 每一条决策都说明背景、选择、理由与替代方案。
> ADR-001 至 ADR-006 保留早期设计背景，不代表全部已实现。
> 2026-09-28 起，冲突的目标与排期以 ADR-008 和 M2.0 spec 为准。
> 2026-09-29 起，路由、状态和评测后续范围以 ADR-009 与 Harness spec 为准。

## ADR-001: 前后端分离架构

**背景**：项目最终需对接已有决策平台，技术栈与鉴权方案均未知。

**决策**：采用前后端完全分离架构，后端只暴露 RESTful API，
前端为独立的"参考实现"，可被未来平台替换。

**理由**：
- 平台对接时只需替换前端或加 adapter 层，后端零改动
- 便于独立部署、独立扩展
- 利于面试展示（API 可直接用 Postman 演示）

## ADR-002: 用户体系延后实现

**背景**：原平台用户体系开发中，规范未定。

**决策**：MVP 阶段使用匿名 session（cookie 中存 UUID），所有 API 接口
预留 `user_id` 字段。未来对接时实现 `AuthAdapter` 即可接入平台鉴权。

## ADR-003: LLM 选择 DeepSeek

**背景**：需在效果、成本、API 稳定性间权衡。

**决策**：MVP 阶段使用 DeepSeek V3 API。

**理由**：成本远低于 GPT-4 / Claude（中文场景效果接近），月预算可控在百元级。

**替代方案**：未来可在 `llm/` 模块替换为 OpenAI / Claude / 本地模型，
所有调用集中在 `LLMClient` 抽象。

## ADR-004: 向量库选择 Chroma

**背景**：需要本地可运行、易部署的向量库。

**决策**：使用 Chroma，文件持久化模式（不跑独立服务）。

**理由**：零运维、Python 原生、对 90 篇论文规模完全够用。

**替代方案**：用户量增长后可迁移到 Qdrant / Milvus。

## ADR-005: Agent 框架自研而非 LangChain

**背景**：LangChain 抽象重、调试难，对学术研究项目不友好。

**决策**：基于原生 OpenAI 兼容协议自研轻量 Agent 框架，
ReAct 循环 < 200 行代码，所有 prompt 可见、可控、可改。

**理由**：
- 论文写作需要清晰描述算法细节，黑盒框架不利于阐述
- 调试 Agent 决策路径时，自研代码透明度远高于 LangChain
- 90 篇论文 + 单 Agent 场景不需要复杂编排

## ADR-006: WHCNS 接入策略

**背景**：WHCNS 是黑盒可执行模型，输入输出已确认。

**决策**：在 `simulator/` 模块用 mock 实现先占位，定义清晰的接口契约，
真实接入推迟到 M3 阶段。

**接口契约**：
- 输入：标准化的农田参数 dict（土壤、气象、施肥方案）
- 输出：氮淋失量时间序列 + 关键指标
- 调用：异步任务（仿真耗时不可忽略）

## ADR-007: 独立的模型认知与使用助手（2026-09-26，范围已由 ADR-008 替代）

**背景**：M1.6 已形成文献问答闭环。下一阶段的核心问题是初学者是否更理解模型、
更能完成使用任务。原平台与在线仿真不应成为核心演示的依赖。

**决策**：M2.0 聚焦 WHCNS 的用途解释、使用准备和一个真实案例的结果解读。
保留 RAG，补充经审核的模型档案、手册与案例资料、可保存的任务状态、
一种确定性文件工具和轻量评审入口。WHCNS 必须有实质资料和完整案例，
不能只作为模型列表中的名称。

**边界**：独立于原平台运行不等于离线运行；现有 LLM API 依赖继续保留。
在线 WHCNS 执行、任意地块预测、自动校准与施肥决策作为后续可选扩展。
取得版本、输入输出格式、运行条件和材料使用许可后，再定义真实执行接口；
ADR-006 中“输入输出已确认”不作为当前版本已经确认的证据。

**实现原则**：任务状态显式记录用户目标、已知信息、缺项和下一步；
聊天历史及模型生成内容不能自动成为已审核事实。运算、格式与单位校验由程序完成，
专业解释通过审核资料和具体引用支持。不以 ReAct 循环、工具数量或“完整 Agent”验收。

**评测原则**：M1.6 题集用于回归；试评题用于完善流程；独立测试题用于正式比较。
分别衡量专业正确性、完整性、证据支持、可理解性、任务完成和主观满意度。

## ADR-008: 单一对话窗口与确定性文件分析（2026-09-28）

**产品范围**：围绕农业模型问题解决。用户提出问题或提供文件，系统检索、计算或追问，
在同一对话中返回结论、必要解释和依据。不设置三个功能入口，不组织课程或学习流程。
专业解释按问题需要提供；专业评审留在研发验证流程。

**当前链路**：

1. 浏览器将原始文件字节发送到 `POST /api/files?filename=...`。
2. 后端按内容读取 XLS/XLSX，检查格式、可读性与资源限制。
3. 返回随机 `file_id` 和 pending 状态；客户端在原 `POST /api/chat` JSON 中附带该 ID。
   首次文件分析时再校验氮/水平衡字段、单位和连续日序，计算极值及位置。
4. 有附件时，显式字段与整表 min/max 问题返回确定性答案和 `file_evidence`。
   不明确或超出范围则追问，不从历史回答推断文件数值。
5. 文献问题可以保留附件且不触发业务校验；文件过期返回明确错误。

**生命周期**：每次解析使用临时目录并在结束时删除；待分析原件在内存暂存，
总量上限 64 MiB，分析成功或业务校验不通过后释放原件，仅保留摘要或诊断。
最多 32 份、有效 30 分钟，访问时清理过期项；不将原件或全文发送至 LLM。
随机 token 作为临时访问凭据；`session_id` 仍不是身份认证。当前只支持单后端进程，
没有跨进程共享、持久会话或完整用户隔离体系；重启、刷新后需重新上传。
上传上限 10 MiB，限制并行解析、展开大小和单元格数。公开多用户部署前需另行设计
认证、配额、共享存储与更强的解析资源隔离。

**证据**：文件名、SHA-256、字段与单位、运算、日序、值/日序单元格、计算范围、
并列数量和工具/规则版本独立于论文 citation 返回。并列极值展示首次出现并标明数量。
程序日序不推成日期，算术和不推成季节总量；模型版本与输入输出配对尚未确认。

**后续**：将手册标题、页码、版本和审核状态接入检索；再扩展问题分流与回答覆盖。
不以 ReAct、多工具数量或已复现案例为本次最小闭环的验收条件。

## ADR-009: 轻量 Harness 与版本化协作评测（2026-09-29）

保留现有检索、生成、文件解析和计算，将聊天执行接入统一 Runtime。
通过 typed SkillRegistry、RouteDecision、TaskState、Evidence、RunTrace 组织有限步骤。
附件只提供上下文，不再强制文件模式；文件指代仅继承经工具确认且当前有效的指标。
提供保守规则路由和有限语法 COMPOSED 执行，复杂语义分类待后续。
组合回答分文件事实、一般文献机理和局限；证据绑定每条机理，检查引用编号与原文摘录，
不向机理生成传入文件数值。作物限制通过关键词筛选片段，不等于专业适用性审核。
部分失败返回 partial 并保留成功部分；完整因果解释仍需同期天气和管理记录。

运行记录采用 SQLite 追加保存，接口错误也产生同一 run_id 的 Trace。
当前会话/附件仍在单进程内存，刷新或重启不恢复；Trace 不等于长期记忆。
后续评测 Case 保留版本，Review 追加保存，多轮执行关联有序 Run，测试者身份和开发者权限
在服务端校验。第三批已落地独立 `/evaluation` UI 与 `/api/eval` 受保护接口：
静态密钥绑定身份/角色，测试者仅访问自己的执行，开发者读取 Trace。
Case 版本不可覆盖，Review 追加保存并冻结执行。原聊天/临时附件接口仍不是账户隔离体系。

以 [Harness spec](iterations/2026-09-29-agent-harness/spec.md) 区分已实现与计划功能，
旧核验单及标准不改写。分阶段上传、组合回答、评测执行与评分闭环已落地，
第四批落地 Markdown/引用定位/附件拖放，以及开发者回归基线与逐轮版本比较。
`eval_regressions` 冻结原执行、用例、Trace 和已有评分；`eval_replays` 记录后台重跑进度。
重跑另建执行，按原顺序还原支持的事件，不覆盖基线、不生成专业评分；
原附件无法按指纹复原或包含人工步骤时明确受阻。专业审核继续待办。
