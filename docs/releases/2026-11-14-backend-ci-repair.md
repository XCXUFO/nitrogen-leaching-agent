# 2026-11-14 GitHub 后端 CI 修复

封版提交 `ca0a5d2` 的 [CI #22](https://github.com/XCXUFO/nitrogen-leaching-agent/actions/runs/43447074929) 中，前端通过，后端测试结果为 1312 通过、39 跳过、9 失败、8 错误。依赖安装成功，失败发生在 `Run tests`。

## 根因与修复

1. **提交前的资料空白清理破坏了原包校验。** `04-八条审核案例与验收.md` 的 36 个行尾空格被删除，文件从 30902 字节变为 30866 字节，与原 `manifest.json` 不符；交接资料导入及依赖它的复测、任务 Prompt 测试随之失败。第二份 `用户材料快照.md` 的两处空白也破坏了原 V0.2 校验记录。本次恢复两份文件的原始精确字节，哈希分别重新匹配 `c7a930b58ed50bf461440e9010931fd2638aaab5f1a5d7e0e27b3ff94106d4c0` 与 `57a04cd305d5a582db76e662bdb43d9fb7a9226cbce6c86232582b9d27f98db0`。未改写原包清单或绕过导入校验。
2. **就绪测试的替身漏掉 PyTorch 线程设置。** GitHub 只安装基础、dev 和 model-tools 依赖，没有 `torch`。测试虽替换了向量、索引和重排组件，仍在真实 lifespan 的 `import torch` 处失败，导致健康检索场景返回 503。现在将线程设置也替换为可记录调用的替身，并检查线程参数；正常、空库、嵌入、索引和重排失败五种就绪场景继续执行。
3. **真实 Chroma 集成测试没有声明可选依赖。** 标签向量过滤测试在没有 `chromadb` 的精简环境仍构造真实存储。现在按现有其他向量集成测试的规则，仅在该依赖缺失时跳过；安装 `rag` 的本地环境仍运行完整真实向量过滤与重排前范围检查。

两份归档所在目录增加 `.gitattributes` 规则，保留原始换行和空白；其完整性由原校验清单和新增测试约束。新增的两组归档回归覆盖随 Git 发布的原包文件，Finder 元数据 `.DS_Store` 继续按仓库规则排除。

交付清单现纳入两份资料包所在目录及 `.gitattributes`，并有测试确认修改归档或属性规则会被拒绝。启动器默认改为本次修复清单。CI 安装增加 `--locked`，显式要求依赖与锁文件一致。
