## 1. 背景与定位

用户最后确认的方向是前期只开放有限内容，主要目的是让 Skill 能力可视化。现有 SkillRegistry 可导出描述和输入输出 Schema，可作为信息来源；统一管理页面及配置是否已存在需源码确认。

本期做一个轻量列表和详情页，让运营、测评、产品和开发看懂系统有什么能力、何时使用、依赖什么，以及允许调整什么。

## 2. 首期范围与不做事项

首期覆盖现有 7 个聊天 Skill。默认查看为主，只为经过源码梳理的少量解释 Prompt 字段开放编辑。

不做通用 Prompt 平台、模型参数管理、可视化路由修改、拖拽流程、MCP 连接管理、任意工具新增或复杂配置审批。文献 AI 解析和打标等非聊天能力暂不强行注册为聊天 Skill，可在后续扩展同类展示机制。

## 3. Skill 列表

| 字段 | 说明 |
| --- | --- |
| 中文名称 | 如案例与措施解释 |
| 内部标识 | 折叠或次要展示，方便研发定位 |
| 用途简介 | 一句话说明完成什么任务 |
| 当前可用性 | 已注册、依赖可用／不可用／未知，不能仅由注册推断健康 |
| 是否支持 AI 生成 | 便于区分计算、程序文案和 LLM 能力 |
| 配置能力 | 只读或有限可编辑，不显示无效编辑入口 |
| 操作 | 查看详情 |

可按名称查找。仅 7 项时不必增加统计卡片、复杂筛选或多层导航。

## 4. Skill 详情

默认用业务语言展示：用途、适用场景、提问示例、需要的输入、返回内容、依赖、支持范围和限制。

例如案例解释：可解释案例、表格和粘贴文本，支持指定对象比较；材料缺失不补造，不保证提供当前田块的完整执行方案。

技术信息折叠展示：实际注册标识、输入输出 Schema、实际版本、关联实现入口（如适合现有后台）、依赖状态。描述来自注册表或经维护的说明，不能与实际工具契约脱节。

程序生成的澄清、能力引导应说明其性质；WHCNS 说明既定格式和统计范围，不展示为通用 Excel 或仿真能力。

### 4.1 首批七项展示口径

| 标识与中文名称 | 当前主要输入与输出 | 依赖与明确边界 |
| --- | --- | --- |
| `knowledge_search` 文献检索问答 | 问题及可用会话材料 → 有引用的文献回答或可能机理 | 当前注册入口依赖可用 ChatService，其初始化依赖 RAG 与 LLM；不联网检索 |
| `case_reference` 案例与措施参考 | 问题和条件 → 相关案例、做法及结构化来源 | LLM、可用案例；当前整体材料读取有限制，后续扩容见 M04 |
| `case_explanation` 案例与措施解释 | 指定案例或粘贴文本、问题 → 解释与比较 | LLM；粘贴文本无需先入库，缺失数据不补造 |
| `file_inspector` 附件检查 | 附件 → 有效性和解析信息 | 本地工具；业务校验在分析阶段执行 |
| `whcns_analyzer` WHCNS 结果分析 | 既定格式输出表、字段 → 整表极值、日序、单位和原件证据 | 本地工具；不执行仿真，不是任意 Excel 分析器 |
| `clarification` 澄清追问 | 缺失或歧义信息 → 必要追问 | 程序生成，不依赖 LLM |
| `capability_guidance` 能力引导 | 能力咨询或范围外请求 → 支持范围与示例 | 程序生成，不依赖 LLM |

以上为归档基线，页面落地前需与实际注册描述和契约逐项对齐，不以业务说明替代机器输入输出定义。

## 5. 有限编辑范围

初稿建议只对 `case_explanation` 开放以下候选字段，最终以实际模板结构确认：

| 可编辑项 | 示例或约束 |
| --- | --- |
| 默认表达风格 | 简洁易懂、先解释必要术语 |
| 默认详细程度 | 简短／适中／详细，或受限文本配置 |
| 回答组织要求 | 先回应问题，再补必要背景和例子 |

原始专业约束、输入输出变量、来源与数字要求、工具权限、访问范围、计算公式和路由规则只读。默认风格服从本轮用户明确要求，不能覆盖用户要求专业深度的指令。

`case_reference` 和 `knowledge_search` 首期可以仅展示，后续再确定是否开放字段。不存在 LLM Prompt 的工具不提供假的 Prompt 编辑器。

## 6. 操作流程

进入详情 → 查看当前生效值 → 编辑允许字段 → 保存并启用 → 展示成功及生效版本 → 新运行采用新配置。

提供恢复默认操作，恢复后也形成一条基本变更记录。离开未保存页面时提示；失败保留输入。只读区与编辑区有清楚区分。

首期不强制建设独立在线对比测试台，可复用现有评测或会话入口进行验证。若提供测试按钮，测试应显式标为测试运行，不把草稿配置影响正式会话，也不计入线上自动路由指标。

## 7. 配置校验与生效

- 服务端按允许字段白名单校验，页面隐藏不能替代保存校验。
- 必需变量与输出契约由系统保留，不允许因文本修改丢失。
- 控制长度和空值；具体长度由实际模型上下文预算确定，错误定位到字段。
- 保存后生成配置标识，记录修改人、时间和前后值。此为最小追溯，不新增复杂版本比较页面。
- 每次运行固定实际配置；运行中途保存不改写该运行，新运行使用最新生效配置。
- 配置无法读取或不合法时使用明确的内置默认值，并在后台记录降级，不能无声使用未知 Prompt。
- 多人编辑冲突时提示，不以旧页面静默覆盖较新修改。

## 8. 与会话审查的关联

详情可链接已有调用审查结果；会话中可点击查看调用的能力说明。历史会话显示当时配置标识和已采集值，不能用当前配置冒充当时使用内容。

修改 Skill Prompt 不自动修改 M01 意图识别或 M06 路由规则。页面提示本编辑区的实际作用范围，避免用户以为改了“用途介绍”就改变路由。

## 9. 异常与历史兼容

描述缺失时显示待补充，不编造能力；依赖未检查时显示未知，不显示可用。旧 Trace 没有配置版本时显示历史未采集。

能力可用性检查优先复用现有就绪信息，首期不额外执行付费模型请求来证明在线。依赖配置改变后健康状态的刷新机制需实施确认。

## 10. 验收标准

| 编号 | 验收内容 |
| --- | --- |
| V01 | 7 个现有 Skill 均可找到，名称和实际注册一致 |
| V02 | 每项用途、示例、输入输出及边界清楚，不夸大 WHCNS 或联网能力 |
| V03 | 技术详情可折叠，默认业务语言可读 |
| V04 | 只开放确定字段，其他能力无误导性编辑入口 |
| V05 | 保存后刷新仍保留，新运行使用新值，运行中请求不被更改 |
| V06 | 恢复默认生效且有基本修改记录，失败保留输入 |
| V07 | 必需变量、计算规则和访问约束无法通过编辑绕过 |
| V08 | 历史调用可识别当时配置，未知版本如实显示 |

本模块测试运行由可信后台入口标记 source=test，实际执行模式另存；不靠用户填写字段排除正式指标。与会话链接按共享契约的运行归属及后台权限执行。只读能力说明可独立交付，配置编辑接入运行快照后再验收，不要求先实现全部检索与大盘模块。

## 11. 依赖与待确认

依赖注册表导出、实际 Prompt 结构、配置存储和 M06 Trace。首期编辑字段需源码核对后形成最终清单；在此之前可先交付纯展示页，不把“源码有 Prompt”当作已经可后台配置。
