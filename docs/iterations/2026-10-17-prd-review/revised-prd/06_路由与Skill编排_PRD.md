## 1. 背景与现状

现有 AgentRuntime 承担会话状态、规则路由和有界执行，SkillRegistry 提供输入输出校验。已有文件检查到计算、计算后文献机理解释、案例参考后解释等组合。计划 Skill 与实际 `tool_calls` 已有区分。

本期在此基础上完善统一输入、分支和组合规则，并把执行事件同时供前台进度、后台审查与指标使用。开发前核对确认：当前聊天请求缺稳定轮次和幂等提交标识，RunStore 在执行退出时保存最终 Trace，尚无运行受理与逐事件持久化，也没有完整对客响应快照。这些属于本轮新增适配，不因已有 Trace 就认定具备恢复能力。不假定模型自主工具循环、模型原生工具调用或应用 MCP。

## 2. 目标与范围

1. 基于 M01 结果选择适用路径，专业问答优先复用 M02。
2. 支持多个子任务和必要的 Skill 顺序组合，保留部分成功结果。
3. 区分规则、模型判断和用户指定模式，支持审查归因。
4. 统一实际执行状态、证据关联和版本记录。

不做拖拽流程、无限工具循环或任意外部工具自动发现执行。调用次数、重试、上下文和耗时继续受现有预算约束，具体参数由实施评估确定。

## 3. 本轮目标路由与既有路径兼容

下表是新旧能力衔接后的目标行为，不代表每条路径均需新建。文件检查、极值分析、参考后解释和指定模式直接复用；新增点主要在统一输入、星标分支与实时事件。执行前需逐项对照实际字段，仅补缺失信息。

| 任务 | 默认路径 | 说明 |
| --- | --- | --- |
| 一般专业问答 | 星标匹配 → 必要时文献检索问答 | 已有答案只覆盖适用部分 |
| 找相似案例 | 星标适用性判断 → 案例参考 | 不强制收集完整种植条件 |
| 解释指定案例或用户文本 | 确认对象 → 案例解释 | 用户粘贴文本无需先入案例库 |
| 找案例并比较 | 案例参考 → 对候选确认 → 案例解释 | 记录实际比较对象 |
| 文件单字段极值 | 文件检查 → WHCNS 分析 | 限于现有支持结构和统计范围 |
| 文件极值及可能机理 | 文件检查 → 计算 → 文献问答／解释 | 计算事实与推断分开 |
| 能力咨询 | 能力引导 | 无必要时不检索资料 |
| 关键条件或对象不明 | 澄清 | 只问影响执行的必要信息 |
| 混合问题 | 拆分子任务，按依赖执行后整合 | 避免整轮只选单一路由 |

星标匹配本身也是新增应用能力，但本期不强制新增第八个聊天 Skill；可以由前置服务完成，并以可追踪步骤记录。

## 4. 自动与指定模式

自动模式根据问题理解和规则决定能力，可在明确边界内使用模型辅助分类。采用的规则编号或分类结果应可审查。

指定模式保留现有案例能力入口。执行前显示已指定能力；输入不足时澄清，依赖不可用时说明。不能静默换成其他 Skill 后仍声称指定能力完成。若存在必要辅助步骤，应记录并展示实际调用。

指定模式单独标记，不纳入自动路由正确率；可用于相应 Skill 的效果评测。

## 5. 组合执行与结果

- 上一步输出只有通过契约校验且提供必要材料时，才触发依赖它的下一步。
- 无相关案例时不执行空材料案例比较；可说明无案例并按用户任务提供有依据的概念解释。
- 计算成功、文献失败时保留计算结果，明确机理解释未完成。
- 超时、预算不足、取消、无结果、输入不足分别处理，不统一标失败或成功。
- 生成最终回答时对照子任务覆盖情况，避免遗漏尚未处理的问题。
- 用户要求具体决策而依据不足时说明缺口或澄清，不能靠解释 Prompt 扩张工具能力。
- 内部 ID、原始大段工具 JSON 不默认透传给公众；可读名称、进度、必要证据按展示契约输出。

## 6. 执行事件增量契约（产品字段建议）

当前路由、工具状态、错误、耗时、证据和版本已记录，优先映射既有字段。本轮补充实时产生与投递、序号恢复、关联子任务和前后台展示契约；不是重建 Trace 存储。

| 字段 | 用途 |
| --- | --- |
| 归属、会话、轮次、提交、运行 ID | owner 与 conversation_id、turn_id、request_id、run_id 关联；网络重发复用原运行，主动重跑关联原运行 |
| 事件 ID、序号、时间 | 去重、排序及断线后补发 |
| 步骤 ID、父步骤、关联子任务 | 表达先后、依赖及分支 |
| 事件类型 | 计划生成、步骤开始、步骤完成、无结果、失败、重试、跳过、取消、运行结束 |
| 能力标识及可读名称 | 区分 Skill、内部工具、检索和前置服务 |
| 尝试编号 | 重试可归并展示但保留每次事实 |
| 步骤类型、执行状态、业务结果与摘要 | kind 区分 Skill、tool、service、container；正常空结果与执行失败分开，供展示及同层级统计 |
| 证据引用 | 文献、案例、附件、单元格或星标记录关联 |
| 配置与版本 | 实际采用的路由、Prompt、模型、Skill、索引信息 |
| 展示摘要 | 面向公众的简洁说明；后台明细另存 |

实现协议可选 SSE 或现有适用通道，本稿不限定技术栈。事件应在真实动作发生时产生，不能等整轮结束后用最终文本反推“流式”过程。

## 7. 状态一致性

统一采用共享契约第 5 节的双字段状态和计数矩阵：步骤执行状态为待执行、执行中、正常结束、失败、取消、跳过、中断、未知；正常结束的业务结果可为有结果、无结果、需要澄清。重试沿用逻辑 step_id 并新增尝试，不覆盖上一尝试。

运行分别记录执行状态与业务结果。必要澄清是执行正常结束、业务待补充，显示“需要补充信息”；部分分支失败但保留可用回答时标部分回答。取消、中断和未知按实际状态优先展示。合法检索空结果为执行正常结束，不是检索命中；调用成功不自动等于原业务任务已完成。

步骤创建时固定 kind，Skill、底层工具、前置服务和父容器分别统计；只将实际开始且正常结束或失败的 tool 步骤纳入工具执行分母。计划、跳过、取消、未知不混入，历史缺层级单列。共享契约 S01—S06 的手算样本供前后台与大盘共同验收。

开始了才展示执行中，完成了才展示成功。计划中的步骤如果未执行，应保留计划并记录跳过原因，不伪造耗时和调用。

同一运行固定实际采用的配置快照。后台中途修改 Prompt 不改变正在执行的步骤；下一次运行读取新配置。步骤读取资料时另外执行实时可用性校验。

## 8. 追踪与历史兼容

复用现有 SQLite Trace／RunStore，补共享契约第 2 节的持久化受理、唯一幂等约束、运行中事件和完整结果恢复。原同步聊天接口兼容保留时，不声明具备完整恢复。历史没有身份、步骤或版本信息时显示未采集，不套用当前规则补写。

执行工具前先保存受理及 run_id 映射。首个回执丢失可用原 request_id 找回，重发同标识同输入不重复执行、异输入返回冲突；主动重跑使用新提交且关联原轮次及运行。最终引用整理后的完整对客结果、终态与结束事件一并提交，再通知前台。

进度连接独立于执行生命周期；断线不取消任务，恢复查询不触发任务。结果保存失败不能通过重跑工具补做保存；进程重启无法证明已完成动作时标中断或未知，不自动重放。保留期到期返回恢复过期，不能把旧提交当新请求。找回、状态、事件、结果和取消均校验归属，只返回对应权限字段。

前台与后台从同一实际运行记录派生视图。展示文案可以不同，但工具名称、状态和结果不能矛盾。

## 9. 异常及边界

- 依赖缺失在运行前或调用时返回明确不可用原因，不能在注册存在时一律显示健康。
- 工具返回不符合 Schema 的结果记为执行错误，不进入后续模型作为可靠证据。
- 重试受预算约束；多次失败后结束该分支，保留其他成功分支。
- 当前 WHCNS 只支持既定 `Nbal_out`、`WtaBal_out` 等范围，不将逐列算术和解释成季节总量，也不自动将日序映射成日期。
- 请求取消不等同撤销已发生的工具动作；记录实际停止位置和已完成结果。

## 11. 依赖与待确认

依赖 M01—M05 的数据契约、现有运行时和状态存储。实施时确定事件传输与持久化方案、真实可取消范围、预算及保留期数值；幂等、恢复权限和状态语义遵循共享契约，不再作为未定义行为。路由规则可先代码维护；可视化修改路由不是 M08 首期范围。
