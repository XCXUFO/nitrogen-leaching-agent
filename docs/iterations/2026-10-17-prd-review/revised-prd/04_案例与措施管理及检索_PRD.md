# M04｜案例检索扩容与调用衔接 PRD（增量修订）

版本：V0.3｜日期：2026-10-17｜状态：审查修订，待开发验收

V0.3 补齐开发前审查 R01—R05；跨模块规则统一引用[运行、检索与审查契约](14_跨模块运行与审查契约.md)。本次是文档修订，不表示应用功能已实现或验收。

## 1. 已有基础

B1 案例 V1.0／V1.1 已定义案例维护、富文本和表格、AI 解释与人工采用、开放开关、标签筛选、批量打标／开放／关闭、自动与指定能力、简单路由以及多轮比较。B4 盘点确认案例管理、两种 Skill、参考后解释、上下文与需求缺口记录已有实现。

这些功能不重新立项。V1.1 界面或体验细项若未完成，继续归原需求；本轮不重新设计批量弹窗、编辑表单和解释草稿流程。

## 2. 本轮变化

现有案例采用全量可用材料整体传入模型，尚未使用案例向量检索。2026-10-17 源码与独立内存库复核确认：自动范围查询开放、未删除记录并按内容去重后，若超过 30 条或材料 JSON 超过 24000 字符，直接返回 HTTP 413 / case_capacity；并非只取前 30 条。显式指定较小集合仍需通过容量检查。本轮将全量候选搜索与预算内取材分离，避免开放库增大就使整个自动参考分支被拒绝，并接入统一理解、标签映射和执行事件。

核心目标是“相关案例能找到、对象不串位、状态校验不失效”。不要求为扩容先建立独立措施库或统一精细结构。

## 3. 查询与候选规则

M01 的明确问题与比较对象 → M05 辅助条件 → 在全部已开放、未删除案例中找候选 → 排序和取相关正文 → 再校验可用性 → 交给现有参考或解释 Skill。

- 候选搜索覆盖全部有资格的案例，不再以“全库材料能否整体装入本次调用”作为搜索前提；现有条数和字符上限可继续限制单次取材，不能限制候选全集。
- 首先核对当前可用的标题、正文、标签查询能力，仅补充不足的候选搜索与排序。
- 是否采用向量召回按规模、成本和实际召回问题选择，不写死为必须更换基础设施。
- 标签不完整时仍保留正文或语义候选；用户硬条件按共享契约第 4 节核对满足／不满足／未知。标签冲突留痕，未解决不称严格匹配；访问资格不降级。
- 指定案例或上下文已确定案例时按稳定标识取材，不重新检索后换对象。

## 4. 取材与比较

优先取与用户问题相关的内容，同时保留必要背景、分组、表头、单位和单次／合计口径。不能为了适应预算，把表格拆成无法对应的数字串。

预算不足时记录采用片段、版本／指纹、取舍与未采用原因，不把“放不下材料”写成“库中没有案例”。关键内容无法完整取用时说明预算不足，不截断事实或静默换对象，也不要求用户关闭其他真实资料来满足预算。比较多个案例时分别保存对象和证据，维持现有多轮能力。

库内已有人工解释时继续作为参考，正文仍为事实依据。原文与解释矛盾、空白不能补零、不同模式不能混合等均继承原 PRD，列为回归保护而非新增规则平台。

## 5. 与路由和展示衔接

参考／解释／二者组合已经存在；M06 本轮只接统一理解输入、星标未覆盖任务及事件。指定模式继续保留，用于 Skill 测试；不计入自动路由正确率。

延续 V1.1 的对客名称展示要求，后台保留内部 ID。原有简单路由展示不是本轮新建目标，本轮新增的是全链路真实事件与审查关联。

每轮重新检查开放状态的现有机制继续保留。候选生成后关闭的案例应在交给回答前再次排除，避免扩容后绕过原约束。

## 6. 无匹配与缺口

复用已有缺口与重复检查机制，补充实际检索范围、无结果／预算不足／依赖失败的区分。没有案例时不编造，可按用户任务解释有依据的通用内容。

自动提醒、外部自动补库和覆盖看板仍暂缓；本稿不为已经存在的缺口记录再建任务系统。

## 8. 待确认

全量候选策略、排序方法、单次预算和测试集仍按实测确定。先验证条数与字符超限造成的容量拒绝，以及不同排序位置的召回问题；若选定环境未触发瓶颈，可先接统一输入和可观察性。扩容模块交付时必须满足候选与取材分离，不预设必须更换向量基础设施。
