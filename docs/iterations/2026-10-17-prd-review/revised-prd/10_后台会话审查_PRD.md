## 1. 背景与现状

当前已有运行记录、证据、评测、人工评审、审核队列、问题跟踪和回放能力。用户希望在实际会话中看到每轮走了什么路由，并据此判断该改 Prompt、路由、检索、工具还是资料。

本期优先复用已有审查与 Trace，增加问题理解、星标匹配、实际调用和结构化问题归因，不另建一套重复审核平台。开发前核对确认：现有评分绑定评测 execution、要求执行者本人且不覆盖已提交记录；正式 Run 直接审查、逐维度新状态与修订需要新增适配，不能只当页面字段映射。

## 2. 目标与范围

- 从会话到轮次、从轮次到具体步骤定位问题。
- 展示当时真实输入、上下文、检索和回答依据。
- 区分路由合理性、执行成功、检索有效与回答合格。
- 记录人工标注、依据、版本和建议，关联问题跟踪及回归。

不新增内容发布审核，不要求问答必须审查后才对公众展示，不允许编辑历史事实来使链路看似正确。

## 3. 现有审查列表的字段补充

先核对当前页面和接口，已有字段直接复用，仅补实际缺失项。下表是审查所需视图，不是新增一套列表的任务清单。

| 字段 | 内容 |
| --- | --- |
| 会话／轮次摘要 | 用户问题、时间、对话上下文入口 |
| 来源与模式 | 正式、测试、评测；自动或指定 Skill |
| 运行结果 | 完成、部分完成、失败、取消或历史未知 |
| 实际能力 | 工具和 Skill 摘要，不只显示计划列表 |
| 审查状态 | 待审查、已审查、需补充判断 |
| 审查结果 | 路由、检索、回答等独立标签 |
| 版本与耗时 | 可得的实际版本、总耗时 |

筛选建议：日期、自动／指定模式、任务类型、实际 Skill、运行状态、错误类别、审查状态、实际版本。首期优先最常用项，其余折叠，不先建设复杂报表。

进入详情再返回列表保留筛选和页码。测试、评测与真实公众会话可明确区分，不默认混在同一效果分母。

## 4. 会话详情

### 4.1 对话区域

展示用户提问、附件名称、最终回答及前后轮次。当前轮突出显示；可查看本轮继承哪些历史对象。附件访问沿用原规则，不假定过期文件仍可下载。

### 4.2 问题理解

原问题、补全问题、意图、关键词、条件来源、检索 Query、标签候选和实际筛选条件。显示 M01／M05 的实际输出，不由后台临时重新理解代替。

### 4.3 执行链路

按真实执行顺序展示计划、实际步骤、分支与重试，包含开始终止时间、状态、输入输出摘要、依赖关系、跳过原因和错误分类。

首期采用时间线或步骤列表即可，不要求先建设复杂可编辑流程图。点击步骤可以展开结构化明细。

### 4.4 资料与证据

查看星标候选及覆盖判断、检索条件、实际记录到的候选、采用片段、文献和案例来源、文件单元格和单位，以及可追溯的版本或指纹。

当前未记录完整候选时显示未采集，不能将最终采用材料当成所有召回候选。原件不可用时显示当时保留的必要证据和不可用原因。

### 4.5 配置

显示实际采用的路由、Prompt、模型、Skill、词典和索引版本。旧记录缺失时明确未采集，当前能力说明与历史配置分开。

## 5. 审查维度映射与缺失项补充

复用现有评审基础，新增正式 Run 直接审查适配，不伪建评测 execution。最小保存集为路由合理性、回答质量、主因及依据，允许按规则填写无法判断／不适用；问题理解、标签、相关性、充分性与工具结果按任务分别判断。共享契约第 6 节规定结构、兼容和有效审查状态，未填维度不进入对应指标分母。

| 维度 | 可选结果 | 需要记录 |
| --- | --- | --- |
| 问题理解 | 正确、部分正确、错误、无法判断、不适用 | 错误字段及上下文来源 |
| 路由合理性 | 正确、部分正确、错误、无法判断、不适用 | 应有能力、遗漏、多余、顺序错误或合理替代路径 |
| 标签与筛选 | 合理、部分合理、不合理、无法判断、不适用 | 误映射或过严／过松条件 |
| 证据相关性 | 有效、部分有效、无有效证据、无法判断、不适用 | 至少一条相关且可用才记有效；仅相关线索但不可用记部分有效 |
| 证据充分性 | 充分、部分充分、不充分、无法判断、不适用 | 是否足以支持当前任务，不能借相关性结论补齐 |
| 工具结果 | 正确、错误、无法判断、不适用 | 实际计算／解析结果与原件对应情况 |
| 回答质量 | 合格、部分合格、不合格、无法判断、不适用 | 事实、覆盖、引用、条件、易懂性等问题 |
| 主要归因 | 结构化类别，可多选 | 主因一项、次因若干、依据和建议 |

每个维度分别记录适用性、判断状态、结论和依据；“无法判断”须填写原因，未采集不等于不适用。不适用用于本轮没有该任务。相关但不足可记有效＋不充分，两项独立保存。路由允许多条合理路径，执行成功不自动预填路由正确或答案合格。

旧 route_correct 的 yes/no 可映射正确／错误；旧 n.a. 原因不明时保留原值和未采集，不能推断不适用或无法判断。旧 evidence_correct 不同时回填相关性和充分性；旧多 Run 合并评分不复制为多条正式 Run 审查。AI 辅助记录不能自动转成人工审查。

## 6. 归因类别

| 类别 | 典型问题 | 建议关联对象 |
| --- | --- | --- |
| 意图与上下文 | 指代错误、旧条件残留、漏拆子问题 | M01 配置或状态逻辑 |
| 星标匹配与覆盖 | 套用相近答案、空答案终止 | M02 匹配与答案内容 |
| 标签与 Query | 改写变义、过严筛选 | M01／M05 |
| 资料与索引 | 材料缺失、未同步、陈旧片段 | M03／M04 |
| 召回与排序 | 相关资料存在但未找到 | 检索配置 |
| 路由与组合 | 错 Skill、漏调用、顺序错 | M06 |
| 工具与依赖 | 超时、解析错、计算口径错 | 对应工具实现 |
| 解释与表达 | 难懂、过度简化、解释超出证据 | M07／有限 Prompt |
| 引用与证据 | 引用不支持结论、单位或对象错配 | 证据组织与校验 |
| 展示与追踪 | 前台状态错误、实际调用未记录 | M06／M09 |

归因是审查判断，不是系统已证明的根因。允许记录待研发复核，避免按类别自动修改 Prompt。

## 7. 审查与协作流程

选择会话或抽样任务 → 查看完整关联 → 按维度标记 → 填写依据与建议 → 保存 → 必要时关联已有问题跟踪或评测用例。

直接按 run_id 保存正式会话审查，保留轮次与归属关联，不要求审核者是原执行者，但必须具备该会话的后台审查权限；旧评测自评限制继续保留。

提交携带幂等标识与 expected_revision；重复提交返回原记录，并发旧版保存拒绝并保留输入。更正结论时追加修订，记录修改人、身份、时间、原值及依据，原子切换当前版本。每个 Run 仅有一份当前生效人工审查，主运行统计不重复计数；草稿、纯 AI 辅助与冲突待复核不进有效审查覆盖分子。

若审查意见冲突，标记需复核，保留各方依据；未解决前不进入正确率分母及已完成审查覆盖分子。解决后形成新修订。本期复用现有角色与审查机制，不新增双人审批制度，也不修改旧评测的不可覆盖记录。

## 8. 抽样和版本比较

保留异常样本审查，同时增加常规随机抽样入口或标识。每条审查记录抽样来源：随机、失败、用户反馈、指定专题、回归。

问题会话的分布可用于找改进方向，但不能代表全量正确率。大盘按来源分开展示，随机比例由业务量和审查能力确定。

回放必须产生新运行，关联原运行和当时输入。当前配置或索引不同可能改变结果，页面明确回放条件；历史原件缺失时不能声称完整复现。

## 9. 异常与保存规则

- 标注失败保留输入，避免重复提交形成重复统计。
- 缺 Trace 的历史会话仍可审查回答，但路由等维度标无法判断。
- 没有原件时不能仅凭计算成功状态给工具结果正确结论。
- 筛选、查看、标注和回放不修改原始用户问题和原始回答。
- 沿用现有访问控制，前台过程不直接开放后台审查明细。
