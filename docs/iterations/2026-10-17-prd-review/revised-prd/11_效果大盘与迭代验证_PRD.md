## 1. 背景与现状

会话量增加后，需要知道哪些任务经常走错路线、哪些工具失败、哪些资料不足，以及修改后是否改善。现有版本化评测、人工评审、回归基线、回放和版本比较可复用。

本模块不把工具成功率当路由正确率，也不从未经审查的 Trace 自动推断专业正确性。

## 2. 目标与首期范围

- 大盘区分运行事实指标和人工审查指标。
- 每个比例可查看样本量、口径、时间范围和样本来源。
- 按任务、Skill、版本和错误归因定位优先问题。
- 将问题转为固定回归样本，比较修改前后结果。

首期做少量核心指标、趋势和问题分布，不做自动调 Prompt、自动专业评分、复杂实验平台或综合质量总分。

## 3. 统计对象和默认口径

基本单位是正式会话的一次已受理用户提问轮次。本修订采用共享契约第 2、7 节的默认口径：首次已受理运行固定为主运行，网络重发复用原提交和运行，工具内部重试不增轮次，用户主动重跑保留 turn_id 并新建 request_id/run_id 及原运行关联。主运行失败、取消或未知不能被后续成功替换；编辑问题或继续追问是新轮次。预受理校验拒绝另计，不算已受理提问。

后台测试、离线评测、指定 Skill 模式和正式自动模式由可信入口分别标识，不信任普通客户端自报。默认自动路由指标只统计正式自动主运行中适用且已判断的当前有效人工样本；AI 辅助不自动成为人工结论。缺轮次、来源或主运行关联的历史记录单列，不按文本相似猜测归属。

每个 Run 最多一份当前有效人工审查，主运行指标只取主运行对应版本；审查历史保留且不重复计数。统计按该轮首次受理时间归属，步骤／尝试沿用主运行窗口，其他动作时间诊断口径另列。审查补录或修订后更新当前统计，并显示更新时间、口径及审查版本。Skill 分组使用主运行实际开始的能力，多 Skill 分组不能直接相加为唯一提问总量。

取消、历史记录缺失、无法判断及不适用分别展示，不暗中从所有指标统一剔除。

## 4. 运行事实指标

| 指标 | 口径 | 说明 |
| --- | --- | --- |
| 正式提问量 | 选定首次受理时间内按 owner、conversation_id、turn_id 去重的正式轮次数 | 不把工具步骤或重试当提问 |
| 主运行状态分布 | 执行状态与业务结果分别计数，澄清、中断、取消、未知单列 | 待补充不称原任务完成；有回答文本不自动等于成功 |
| 工具执行成功率 | 正常结束的已开始 tool 步骤数／执行状态为正常结束或失败的已开始 tool 步骤数 | kind 固定；跳过、未开始、取消、中断、未知排除并单列；不加入父 Skill 或容器 |
| 工具尝试失败率 | 失败 tool 尝试数／正常结束或失败的 tool 尝试数 | 同逻辑步骤保留每次尝试；取消／未知尝试不进分母，此前已结束尝试仍计 |
| 检索无结果率 | 最终正常结束且业务无结果的检索 tool 步骤数／最终正常结束的检索 tool 步骤数 | 合法空结果算执行正常结束；失败不混成无结果 |
| 星标复用分布 | 完整复用、部分复用、命中无答案、未命中、匹配失败 | 完整命中率不是答案正确率 |
| 耗时 | 主运行与步骤耗时的中位数、P95，显示样本数 | 无有效时间数据不编造 |

统一引用共享契约第 5 节的状态与统计矩阵：执行状态和业务结果分开，合法空检索执行正常但不命中，分析输出契约错误为失败。Skill 成功率另按 kind=skill 计算，父子层级不能混算；缺底层观测时不从 Skill 推算工具调用。必要澄清一般是执行正常的 Skill、业务待补充，没有实际工具就不增加工具分母。S01—S06 手算夹具须得到工具步骤成功率 2/3、尝试失败率 2/4。

## 5. 人工审查指标

所有指标同时展示 n／N；N 为零时显示暂无可计算样本，不显示 0% 或 100%。

| 指标 | 分子／分母 |
| --- | --- |
| 路由正确率 | 路由标正确的样本数／已审查、路由适用且结论可判断的正式自动主运行数 |
| 路由部分正确率 | 标部分正确样本数／同一路由有效分母 |
| 回答合格率 | 回答标合格样本数／已审查且回答结论可判断的适用主运行数 |
| 问题理解正确率 | 理解标正确样本数／已审查且理解可判断的适用样本数 |
| 检索有效率 | 相关性标有效的主运行数／当前有效人工审查中相关性适用且已判断的主运行数 |
| 证据充分率 | 充分性标充分的主运行数／当前有效人工审查中充分性适用且已判断的主运行数 |
| 审查覆盖率 | 有当前有效人工审查的正式主运行数／选定范围正式主运行数；草稿、AI 辅助及冲突待复核不进分子 |

部分正确不折算为 0.5 个正确样本。无法判断、冲突待复核、不适用和未采集单独列出，不进对应正确率分母。各维度分别取适用且已判断样本，不能借同一份审查的其他结论补齐。人工指标取共享契约第 6 节的当前有效人工审查；旧 n.a. 和旧证据总评不直接生成新维度判断。

相关性与充分性分别保存：有效表示至少一条相关且可用证据，部分有效仅有相关线索但无可用证据，不进入有效分子；充分性只取充分进入分子。找到相关但不足以回答的资料可有效但不充分。无证据可用的样本不计有效，但不据此自动判断路由错或检索算法错，还需审查是否资料本身缺失。

## 6. 大盘页面

### 6.1 顶部范围

时间、正式／测试／评测来源、自动／指定模式、任务类型、Skill 和实际版本。显示当前统计单位、数据更新时间和缺失比例。

### 6.2 核心概览

提问量、运行状态、工具执行成功率、路由正确率及样本量、回答合格率及样本量、审查覆盖率。未有足够审查数据时显示数据积累状态，不给无依据的全量结论。

### 6.3 趋势与分布

- 提问量和运行失败趋势。
- 路由及回答审查结果分布。
- 按任务和 Skill 的调用、失败、耗时分布。
- 主要归因分布及可点击的问题会话列表。
- 常规随机样本、异常样本、用户反馈样本分别展示。

首期以表格和少量图表实现，点击统计项能进入同口径的 M10 列表；不能点进去后样本数量对不上。

## 7. 代表性与解释限制

如果主要审查失败或投诉会话，结果用于定位问题，不代表全量正确率。随机审查样本与问题样本分别报告；没有合适抽样依据时不推算总体置信范围。

不同版本的真实流量可能任务构成不同，直接比率变化只作观察。需要判断某项修改效果时，优先用固定回归集和明确的版本条件比较；不把同期其他改动一并归功于某个 Prompt。

所有比例按相同来源、模式和时间范围计算，界面避免把不同分母卡片进行直接加总或比较。

## 8. 从发现到优化的闭环

1. 从指标或审查列表发现重复问题。
2. 查看原始输入、上下文、实际 Query、路由和证据。
3. 专业与研发共同确认主要原因，归因类别按 M10。
4. 选择修改对象：资料、索引、Query、标签、路由规则、Skill 实现、解释 Prompt 或前台展示。
5. 将代表问题加入现有评测用例，定义允许路径、必要证据和回答要求。
6. 使用固定用例比较基线与候选版本，记录收益、退化和未解决项。
7. 启用后继续观察真实样本，异常时恢复相应受控配置或修复实现。

本流程不自动创建外部通知或定时任务，不要求所有问题都修改 Prompt。

## 9. 归因到修改对象

| 现象 | 优先检查 |
| --- | --- |
| 指代和省略理解错误 | M01 上下文选择、状态与改写 |
| 意图正确但 Skill 选择错误 | M06 路由规则、能力描述和契约 |
| 该连续调用却遗漏第二步 | 编排依赖、输入输出传递 |
| 已有资料没被找到 | 索引资格、同步、召回、过滤和重排 |
| 资料找到但不适用 | 条件、标签、相关性及证据检查 |
| 资料准确但表达难懂 | M07 解释方法、有限 Prompt |
| 数字口径或计算错误 | 原件、工具实现、单位和证据对应 |
| 前台显示调用而实际没执行 | 事件产生与展示逻辑 |

## 10. 对既有回归能力的复用与补充

版本化用例、附件、多轮、回放和比较已经存在，不重复立项。本轮只补齐新增链路场景、真实问题的关联及缺失版本条件；已有字段不重复建设。

复用现有 Harness，覆盖多轮、附件、版本和人工评审。每条用例至少包含输入与必要上下文、资料条件、预期任务、可接受路径、必须保留事实和禁止错误。

运行需记录代码／Skill、Prompt、模型、索引、词典和资料版本中实际可得项；缺失项明确列出。重放时外部来源发生变化、旧附件过期或原件不可得，标记不完全可比，不伪装为严格同条件试验。

执行成功、结构校验通过与专业正确分别验证；不要仅检查工具调用名称与预期完全一致，因为可能存在合理替代路径。

## 12. 依赖与待确认

依赖 M06 运行数据、M10 审查标注和现有评测平台。默认主运行、双字段终态、统计层级和人工分母按共享契约实施；具体保留期数值和抽样比例在部署前确定，后续更换主运行策略须版本化并展示差异。样本不足时先上线计数与审查覆盖，不为展示百分比编造准确率。
