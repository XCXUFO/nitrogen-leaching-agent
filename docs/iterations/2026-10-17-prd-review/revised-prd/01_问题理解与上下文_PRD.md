## 1. 背景与现状

现有规则路由已支持部分文件和案例追问，但用户表达可能包含简称、省略、指代、多个子问题和话题切换。若每个后续能力各自理解问题，容易出现比较对象改变、旧作物条件残留、关键词或标签误提取。

本模块拟在现有状态管理基础上，提供统一问题理解结果。现有上下文继承的具体覆盖范围需结合源码和真实用例复核。

## 2. 目标与非目标

目标：保留用户原意，结合相关上下文明确本轮任务、对象与条件，为星标匹配、检索和路由提供同一输入。

首期包含指代补全、意图识别、实体与条件提取、检索 Query、子问题拆分、上下文来源、必要澄清。标签候选交给 M05 映射。

不做用户长期画像、跨会话自动记忆、完整对话摘要平台，也不将猜测的用户地区或专业水平当成事实。

## 3. 使用场景

| 场景 | 示例 | 预期 |
| --- | --- | --- |
| 独立提问 | 有没有玉米水肥一体化案例 | 找案例；提取作物和管理主题 |
| 指代追问 | 它们追肥有什么区别 | 从上一轮实际案例解析比较对象 |
| 指标继承 | 那最小值呢 | 在有效文件与指标范围内继承指标，更新统计方式 |
| 条件更正 | 刚才说错了，是番茄 | 当前作物覆盖旧作物，保留仍相关的其他条件 |
| 话题切换 | 另外，折氮量是什么意思 | 解释术语，不自动绑定刚才案例中的全部条件 |
| 复合任务 | 找两个案例，再比较灌溉做法 | 输出找案例和比较两个关联子任务 |
| 指代不明 | 上轮给出三个案例后说这两个 | 针对比较对象澄清 |

## 4. 业务流程

1. 接收原始问题、当前附件以及可用的会话状态。
2. 选择与当前问题相关的历史轮次和材料锚点，不默认拼接全部历史。
3. 解析指代、省略、修正、否定与话题关系。
4. 输出意图、对象、条件和必要的子问题。
5. 生成便于匹配和检索的 Query；记录改写依据，不改写原始问题。
6. 将概念交给 M05 映射标签；将结果交给 M02 和 M06。
7. 无法确定且影响任务执行时，走澄清；不影响通用解释的缺失信息不强制追问。

## 5. 输出字段

| 字段 | 要求 |
| --- | --- |
| 原始问题 | 原样保留；本轮唯一绑定 |
| 补全后的问题 | 可独立理解，保留否定、范围和关键口径 |
| 意图列表 | 可包含知识问答、案例查找、内容解释、比较、文件计算、能力咨询、待澄清 |
| 实体与关键词 | 保留原词和规范词，按作物、地区、指标、措施等分组 |
| 条件 | 值、单位、范围、是否必须满足、来源类型 |
| 子问题 | 每项保留与原始问题的对应关系及依赖对象 |
| 检索 Query | 可多条，避免将多个不同子问题硬拼为一条 |
| 上下文来源 | 对应轮次、材料 ID 或附件 ID；标记继承、更正或新增 |
| 未确定项 | 缺失内容、歧义及是否需要澄清 |
| 理解配置版本 | 本轮实际采用的版本；未采集显示未知 |

条件来源至少区分“本轮用户明确”“历史用户明确”“上一轮已展示材料”“模型推断”。记录结构化结果和简短依据，不要求内部推理文本。

### 5.1 绑定与上下文锚点

理解结果绑定本轮 turn_id、run_id，各子问题分配 subtask_id。实际展示材料形成的锚点保存来源 turn_id、run_id、资料标识及可得版本，不能仅记“上轮第二个”。重跑保留同一轮次但产生新理解快照；用户更正后重新发送或继续追问是新轮次。网络重发复用原提交和运行，不重复生成理解结果。身份规则见共享契约第 2 节。

## 6. 关键规则

### 6.1 上下文

- 本轮明确表述优先于旧条件；修正只替换相关字段，不无差别清空。
- 已展示的案例、文献、附件和计算指标可形成锚点。仅计划检索或未实际返回的材料不能作为“刚才那个”的确定对象。
- 继承案例时不扩大范围；关闭或删除等可用性在实际使用时由资料模块复核。
- 多个候选无法消歧时提出简短追问，不自行选取。
- 明显话题切换不继承无关条件。上下文不足时允许输出独立问题或待澄清。
- 附件过期、丢失或会话状态失效，提示重新提供所需材料，不假称继续读取原件。

### 6.2 改写

- Query 是内部检索输入，不作为用户原话，不覆盖会话展示文本。
- 可补全已经明确的指代，可用已维护同义词扩展；不能新增地区、用量、土壤条件或结论。
- “没有灌溉条件”不能简化为“灌溉”；“三次合计”不能改成“每次”。
- 比较两个地区时保留两个独立对象，避免将地区条件处理为同一材料必须同时属于两地。
- 不以固定关键词数量或标签命中数量作为理解正确的判断。

### 6.3 意图与澄清

- 一个问题允许多个意图；区分主要任务与辅助任务。
- 纯能力咨询、明确文件计算等可直接进入适用分支，不强制先检索星标。
- 用户只问概念含义时，不要求先填写地区、土壤和生育期。
- 用户要求具体执行建议且关键条件不足时，才针对缺口澄清。

## 7. 页面与展示

前台不增加强制确认的“改写问题”步骤。必要澄清以正常对话呈现。

后台会话详情增加“问题理解”区域：原始问题、补全问题、意图、关键词、条件来源、Query、匹配标签及待确定项。默认展示结果，来源明细可展开；允许审查者标记错误，但不直接改写历史运行事实。

## 8. 异常与降级

| 异常 | 处理 |
| --- | --- |
| 理解服务失败或输出不合法 | 保留原始问题；可继续现有明确规则分支，记录降级 |
| 多轮解析失败 | 不套用不确定条件；必要时澄清 |
| 标签映射失败 | 保留关键词和 Query，允许无标签检索 |
| 超出支持任务 | 调用能力引导，给出支持范围 |

降级不等于理解成功。后台记录错误环节，前台不展示无必要技术报错。

## 9. 本轮变化验收与既有回归

| 编号 | 场景与预期 |
| --- | --- |
| U01 | 独立问题保留作物、否定及时间范围，改写不新增事实 |
| U02 | 上轮两个案例后比较追问，锚点准确绑定这两个案例 |
| U03 | 上轮三个对象的歧义追问触发澄清 |
| U04 | 用户更正作物，新条件覆盖旧作物，不残留旧检索限制 |
| U05 | 纯概念解释不强制要求完整种植条件 |
| U06 | 混合问题生成关联子任务，路由可使用同一理解结果 |
| U07 | 当前无标签或映射失败时仍可生成有效 Query |
| U08 | 文件追问继承正确指标，过期附件被识别并提示补充 |
| U09 | 后台显示条件来源和实际 Query，且历史版本不被新配置覆盖 |
| U10 | 首个回执丢失后用原 request_id 找回同一运行，理解结果不重复生成 |
| U11 | 原问题重跑新建 run_id 且不覆盖历史理解，编辑问题和继续追问使用新 turn_id |
| U12 | 子任务、条件与材料锚点有稳定关联；候选顺序变化不改变比较对象 |

## 10. 依赖与待确认

依赖现有会话状态、M05 标签服务和 M06 路由接口。首批意图枚举、历史选择窗口、理解预算和配置字段需结合真实会话确定。不要在缺乏样本时写固定置信阈值或上下文轮数。
