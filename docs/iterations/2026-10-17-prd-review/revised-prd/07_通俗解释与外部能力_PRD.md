## 1. 背景

内部资料尚不足以让零基础公众直接完成所有专业任务。需要一边改进资料，一边复用公开解释方法，让用户读懂术语、报告、案例和表格。解释表达改善与专业依据补充是两项不同工作，均应在运行记录和评测中可区分。

现有 `case_explanation` 已支持案例和粘贴文本解释、比较与追问，本模块优先扩展其方法和适用输入，不默认新增多个职责重叠的聊天 Skill。

## 2. 目标与首期范围

- 面向用户实际问题解释，减少依赖既有专业知识的表达。
- 保留原文事实、数字、单位、适用条件及不确定性。
- 明确指出材料缺失、冲突或无法支持的结论。
- 评估公开 Skill 中可复用的解释、证据分析与一致性方法。
- 以同题对照验证准确性和理解程度，再决定扩大使用。

首期建议采用公开方法的本地适配和小规模试验；在线外部知识服务、API 或 MCP 不视为已经选定的交付。

## 3. 对既有解释场景的增强要求

下列场景已有不同程度实现；本轮用于选择试验样本和发现解释质量差异，不将每行计作新功能。仅对实测不足调整方法或配置。

| 场景 | 要求 |
| --- | --- |
| 解释术语 | 先讲含义和相关过程，必要时举例，不只给另一个术语 |
| 读懂表格 | 说明表头、单位、分组、单次与合计，不填空值 |
| 解释案例 | 围绕用户疑问选取内容，保留地区、作物和模式 |
| 比较案例 | 按对象对照材料中可比较项，缺失项明确说明 |
| 解读粘贴文本 | 无需先保存到案例库，区分原文内容与补充背景 |
| 继续追问 | 换表达、补必要背景或例子，不重复同段答案 |
| 材料不足 | 给出能支持的解释和具体缺口，不生成无依据操作方案 |

解释可以用于星标答案、资料检索结果或用户文本，不作为只在无命中时才执行的兜底。

## 4. 输入与输出要求

输入包含用户问题、明确的理解程度要求、相关上下文、已取得证据及来源、已知缺失或冲突。没有用户水平信息时初稿默认采用简洁易懂的表达，不认定用户一定毫无基础；用户要求专业深度时调整。

输出根据问题需要组织，不强制每次填满模板：

1. 直接回应问题。
2. 解释必要术语和过程。
3. 需要时用一个恰当例子或类比，说明类比不能覆盖的部分。
4. 标出数字、条件和来源。
5. 说明未确定内容，或提出下一步必要问题。

不为简单名词解释强制生成长篇报告，也不因通俗表达删去关键限制。

## 5. 专业忠实性规则

- 事实、概念性补充和推断可以在同一回答出现，但来源和确定程度应清楚。
- 不把相关性当成已证明因果，不把材料列出的推荐量直接指定给用户田块。
- 材料没有产量、效果或完整用量时不补造。
- 检索摘要、模型记忆或其他 AI 总结不自动当作已核对原文。
- 工具计算结果以实际计算输出和原件证据为依据，不能用解释 Prompt 改数字。
- 原文与已有解释矛盾时说明冲突，进入后台问题归因；不静默“修正”原文。
- 模型辅助证据检查不等于专业审核。高质量候选方法也需要农业样本验证。

## 6. 候选来源与定位

以下为讨论中查阅的候选，状态均为“公开资料已阅读，未接入农业助手、未进行农业效果验收”。

| 候选 | 可复用内容 | 适配边界 |
| --- | --- | --- |
| [LabClaw Science Communication](https://github.com/wu-yc/LabClaw/blob/main/skills/general/science-communication/SKILL.md) | 面向非专业人士的说明、术语、类比及限制 | 内容较短，需补农业示例与对话约束；项目作者背景不等于大学认证效果 |
| [K-Dense Scientific Critical Thinking](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-critical-thinking/SKILL.md) | 结论与证据对应、假设和适用范围分析 | 医学评价框架不直接套用全部农业材料；定位辅助检查 |
| [K-Dense Scientific Writing](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-writing/SKILL.md) | 证据追溯、数字和单位一致性、不补造信息 | 取适用方法，不搬入完整论文投稿和审批流程 |
| [CDC Clear Communication Index](https://www.cdc.gov/ccindex/index.html) | 主旨、语言、数字与不确定性表达检查 | 官方沟通方法，不是现成农业 Skill；中文农业适用性需测试 |
| [FAO AGROVOC](https://agrovoc.fao.org/) | 农业术语、概念和层级关系，REST／SPARQL 访问 | 是术语资源；需与本地标签对齐，不替代专业措施证据 |
| [FAO AGRIS](https://www.fao.org/agris/) | 农业文献发现及来源线索 | 题录不等于已取得全文；不能声称每条都能访问全文或已有 MCP |

前述 Feynman 个人项目仅作为表达方法参考，不列为专业权威依据。选型以适用内容、维护来源、许可和验证结果为准，不以星数或“官方”名称直接替代效果评估。

## 7. 适配与试验流程

1. 选择最小候选方法，阅读具体文件、依赖和许可，固定来源版本。
2. 将适用指令改造成现有 Python Skill 的受控模板；保留出处和修改记录。
3. 不将外部仓库指令原样赋予整个应用，也不自动安装到编码助手环境作为产品接入。
4. 选择同一批真实问题，保留基线、候选方案及实际输入资料。
5. 专业同事检查准确性和材料忠实性，目标用户检查理解程度；记录失败类型。
6. 达到约定验收条件后，再决定启用范围、默认规则和是否增加在线资源。

首期建议样本覆盖术语、表格、案例对比、资料不足、多轮追问和单位口径。样本数与通过门槛在专业评审后确定，不预设“提升百分比”。

## 8. 在线外部资料的后续边界

若后续确定接入，应单独明确来源、访问方式、可取得内容、超时、引用、缓存和适用范围。项目 API 与 MCP 均是候选接入方式，不强制为方法类 Skill 新建 MCP 服务。

外部无结果时不能自动以无来源的专业内容补齐。外部结果与内部答案冲突时保存两边证据供审查，不把来源机构名称当作适用性判断的替代。

用户文本和即时解释不自动写入正式文献、案例或星标库。是否人工采纳仍走原维护流程。

## 9. 前后台展示

前台可展示“正在解释相关内容”“正在核对资料中的数字和条件”等实际步骤。只有确实执行外部查询时才显示相应来源查询。

后台展示解释输入、所用来源、候选方法及模板版本、检查结果和最终回答。方法名称不作为答案专业认证徽章。M08 可开放解释风格、详细程度和组织方式，专业约束保留为只读。

## 10. 本轮变化验收与既有回归

| 编号 | 验收内容 |
| --- | --- |
| X01 | 零基础表达能解释必要术语，专业用户要求可增加深度 |
| X02 | 数字、单位、单次／合计和条件在解释前后保持一致 |
| X03 | 空缺数据不补造，材料不能支持的结论被明确标出 |
| X04 | 多案例比较对象和来源清楚，不拼接不同模式 |
| X05 | 追问可换表达并继承正确对象，不重复无关长文 |
| X06 | 候选与基线用相同问题和资料比较，有专业和理解性两类记录 |
| X07 | 后台可追溯实际方法版本，未查询外部服务时无虚假查询步骤 |
| X08 | 外部包未被误认已接入 MCP，题录未被当作已读全文 |

解释、比较和一致性检查按共享契约第 5 节记录实际步骤类型和业务结果；没有实际执行的检查不显示成功。专业与易懂性评价分别记录，方法或模型检查不能自动成为共享契约第 6 节中的人工合格结论。
