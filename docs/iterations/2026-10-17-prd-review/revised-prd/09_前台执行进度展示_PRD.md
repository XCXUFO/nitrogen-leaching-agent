# M09｜前台执行进度流式展示 PRD（增量修订）

版本：V0.3｜日期：2026-10-17｜状态：审查修订，待开发验收

V0.3 补齐开发前审查 R01—R05；跨模块规则统一引用[运行、检索与审查契约](14_跨模块运行与审查契约.md)。本次是文档修订，不表示应用功能已实现或验收。

## 本轮范围摘要

| 分类 | 内容 |
| --- | --- |
| 已有基础，直接复用 | 案例 V1.1 已定义简单路由展示；已有后台运行记录与实际工具调用（B1、B4） |
| 本轮新增或调整 | 将真实步骤实时展示到本轮聊天；统一检索、工具和 Skill 的进度、失败、重试及恢复 |
| 不重复立项或暂缓 | 不把已有简单路由重新立项；回答文字逐字输出独立待定，不默认纳入首期 |

本稿以历史 PRD 和 2026-10-16 能力盘点为基线。历史需求中已定义的功能不自动视为本轮待开发项；具体部署和验收状态未重新核实。下文的既有约束用于兼容和回归，不要求重建已有模块。

## 1. 背景与现状

用户希望提问后看到系统正在理解问题、检索资料、调用工具或 Skill，减少等待中的不确定，并与后台实际链路一致。

现状已有运行轨迹，但不能据此推定已具备实时事件流。当前模型客户端未实现流式输出，因此本稿明确将执行进度流与回答文字流分开。

## 2. 目标与首期范围

首期：真实执行事件实时展示、工具和 Skill 可读名称、步骤结果摘要、异常和断线恢复、回答完成后可回看简化过程。

回答文字逐字输出作为独立后续项，评估模型客户端和接口后再排期。本期不通过模拟打字或事后补造步骤声称实时执行。

不展示模型内部推理文本，不默认展开大段输入输出、内部 ID 和错误堆栈。用户可理解的执行事实与证据是展示内容。

## 3. 页面结构

用户发送问题后，在本轮回答区域先出现“处理进度”。默认简洁展示当前步骤和已完成步骤，支持展开更多过程。最终回答单独呈现，步骤不混成最终答案正文。

| 区域 | 内容 |
| --- | --- |
| 当前进度 | 正在执行的步骤及简洁说明 |
| 已完成步骤 | 名称、结果状态、必要结果摘要 |
| 展开详情 | 实际调用能力、相关来源、失败或重试摘要 |
| 最终回答 | 回答与引用，完成后可继续追问 |

不用虚假百分比或无法估算的倒计时。并行步骤若实际存在可并列展示，不伪装成固定顺序。

## 4. 文案与状态

| 事件 | 示例 | 要求 |
| --- | --- | --- |
| 理解开始 | 正在结合前文理解问题 | 确实使用上下文时适用；独立问题可用更简短文案 |
| 星标匹配 | 正在匹配已有专业问答 | 仅实际执行时显示 |
| 星标部分覆盖 | 已找到部分解答，继续查找补充资料 | 不暗示全部问题已回答 |
| 检索开始 | 正在检索相关文献／案例 | 区分资料类型 |
| 检索无结果 | 暂未找到满足这些条件的案例 | 仍可有后续分支 |
| Skill 开始 | 正在使用「案例与措施解释」 | 显示可读名称，说明用途 |
| 计算完成 | 已完成指标极值计算 | 具体数字以实际结果为准 |
| 重试 | 文献检索暂未完成，正在重试 | 原步骤内更新，避免重复刷屏 |
| 局部失败 | 补充文献查询未完成，已保留计算结果 | 不把整轮错误概括为无答案 |
| 运行结束 | 已完成／部分完成／需要补充信息／暂未完成／已停止／中断或状态未知 | 按执行状态及业务结果映射，与后台一致，不把必要澄清称任务完成 |

计划调用的步骤不展示为正在执行；跳过的无关步骤默认不占前台空间。最终若任务范围受影响，应解释实际未完成部分。

## 5. 关键交互

- 运行中在同一轮持续更新，避免每次事件创建新的聊天消息。
- 用户可查看能力说明；是否开放原文跳转按已有资料访问规则执行。
- 公众默认看到案例标题、文献题名、工具中文名称，不显示内部定位 ID。
- 展开状态不打断输入后续问题，自动滚动尊重用户已上滑阅读的状态。
- 若应用支持取消，按钮需真正触发运行取消并显示实际停止结果；不支持时不展示无效按钮。
- 不把浏览器关闭、进度折叠或网络断开视为撤销已执行步骤。

## 6. 事件与恢复

采用共享契约第 2、5 节：客户端在提交前保留 turn_id 与 request_id，受理后绑定 run_id；用事件序号、step_id 和尝试编号更新视图。重复事件不重复显示，乱序按持久化序号恢复。必要澄清显示业务待补充；合法无结果、失败、跳过、中断分别映射，不混为成功或失败。

断连时提示“进度连接已中断，正在恢复”，不立即把工具标失败。首个回执丢失时用原 request_id 找回 run_id；已知运行后从序号补齐，或读取完整状态和结果。恢复查询不会执行任务；网络重发同一提交也由服务端幂等保护。只有用户主动重新执行才新建 request_id/run_id，并保留原轮次和 rerun_of_run_id。

若无法恢复实时进度但任务已完成，取得已保存的完整回答、引用、文件／案例证据和已记录过程；仅有答案正文不算完整恢复。结果保存失败或服务重启导致状态无法确认时显示恢复受阻、中断或未知，不编造完成，不自动重跑工具。窗口过期按 recovery_expired 显示过期，不能伪装成新请求。断开进度连接不取消已受理执行。

找回提交、读取事件、结果和取消接口均校验当前用户／访客归属；前台不直接调用开发者 Trace 接口。原件跳转继续检查当前权限，资料失效不改写当时保留的历史证据。

前端接收最终事件后停止加载。没有最终事件时以运行状态查询判定，不只靠固定时长自动判成功。

## 7. 回答文字流的后续预留

后续若接入文字流，需要明确增量文本、完成和错误事件，以及引用在完成前后的显示方式。工具进度与回答文本可以共用运行关联，但不能混淆状态。

在文字流能力未完成前，用户可以先看到实时步骤，再看到完整回答；界面应如实呈现这一行为。

## 8. 可访问性和展示质量

状态同时使用文字和图标，不只靠颜色；长工具名或来源名不挤压主要内容。移动端可折叠，键盘可展开。结果摘要适量，详细证据在引用和展开区查看。

工具原始错误转换为面向用户的说明，后台保留可定位的错误分类。展示层失败不应覆盖已得到的最终回答。

## 9. 验收标准

| 编号 | 验收内容 |
| --- | --- |
| F01 | 工具开始后即可看到执行中，完成后状态改变，不等待整轮结束才补步骤 |
| F02 | 实际未调用的 Skill 不显示执行成功 |
| F03 | 星标部分覆盖、检索无结果、工具失败有不同文案和后续表现 |
| F04 | 重试归并展示，后台仍可查各次尝试 |
| F05 | 断线后补齐事件不重做任务，不出现重复步骤和重复回答 |
| F06 | 局部失败保留成功计算或材料结果，前后台终态一致 |
| F07 | 过程折叠后可重新查看，名称和来源可读，公众不依赖内部 ID |
| F08 | 未接入模型文字流时不展示模拟逐字输出为真实模型流 |
| F09 | 有取消入口时确实停止可取消执行；状态未知时不虚报完成 |
| F10 | 首个受理回执丢失仍能凭原提交标识找回，首回执恢复不重复执行 |
| F11 | 最终结果完成但前端未收到时可恢复完整答案与引用；保存受阻时如实提示 |
| F12 | 网络重发、主动重跑、编辑问题及继续追问分别保持正确的提交／运行／轮次关系 |
| F13 | 跨访客或跨账号恢复被拒绝；恢复窗口到期不能自动创建新任务 |
| F14 | 必要澄清显示需要补充信息；S01—S06 的进度和后台状态一致 |

## 10. 依赖与待确认

依赖 M06 的真实事件、持久化运行状态和现有聊天界面。需确认断线恢复机制、可取消范围、旧会话展示兼容及前端实现协议；无需先建设全部大盘才能上线真实进度。
