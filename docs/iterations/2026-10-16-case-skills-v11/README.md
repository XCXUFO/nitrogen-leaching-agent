# 案例模块 V1.1

需求日期：2026-10-16。

## 使用方式

在“案例与措施”的问答区，默认选择“自动识别”，直接输入问题；选择“案例与措施参考”或“案例与措施解释”可分别验证指定能力。切换模式会开启新对话，避免两种验证互相影响。支持手动“新对话”。

- 查找案例 → 参考；解释已有案例或粘贴文字 → 解释。
- “找两个案例并比较措施差异” → 先参考，匹配成功后解释。路由展示实际完成的调用；无匹配时不会执行无依据的第二步。
- 答案按标题、地区、作物指代案例，不显示内部 ID；结构化引用仍保留 ID 供追溯。
- 对话逐轮展示。支持“第一个”“这两者”等追问；每轮重新读取案例库，已关闭或删除的案例不可继续引用。解释单个案例后仍保留此前的比较范围。
- 无匹配时明确说明证据缺口，可补充场景或粘贴材料解释，不编造案例或效果。

## 维护入口

列表页点击“查看待补充需求与重复检查”。无匹配的案例需求持久化到案例库数据库，按问题及背景聚合次数，维护人员可据此补充资料。该清单是人工维护提醒，不会自动抓取资料、生成案例或向外发送通知。列表最多展示最近/最高频的 100 条。

完全重复的标题、正文结构、解释、补充信息和来源在调用时合并；管理页仍保留原始记录供人工核查。解释、地区、作物或表格结构不同的记录不会自动合并。指定多个重复 ID 时也只提供一个副本给模型。

本地 `backend/var/case-library/cases.sqlite3` 核查：共 6 条未删除记录；天津为番茄与黄瓜两条，山西为玉米与高粱两条，作物和措施不同，未发现完全重复项，未删除原始资料。若需求所指为另一运行环境的重复数据，应在该环境使用重复检查入口核对。

## 实现与边界

继续使用可审查的规则路由，案例相关性由模型依据本次开放材料判断；尚非通用语义分类器。仅支持现有小规模案例库容量（30 条 / 24000 字符），超限明确报错。多轮会话遵循现有运行时有效期；本期未新增跨会话长期记忆。

新增响应字段：`case_route`（实际执行顺序）、`case_match`、`case_gap_recorded`。新增认证接口 `GET /api/case-library/coverage`。自动建立 `case_gaps` 表，无需手动迁移。

测试使用合成案例和模拟模型，覆盖真实调用顺序、无匹配、关闭案例、比较追问、精确去重、需求持久化及页面交互；不代表真实模型的农业解释质量已完成人工验收。
