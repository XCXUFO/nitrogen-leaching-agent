# 轻量会话审核与资料维护

本轮按“主要由负责人审核，师兄协助整理资料、偶尔复核”的实际分工调整。描述当前工作区代码，部署状态另行确认。

## 每天怎么用

1. 登录 `/evaluation` 或打开 `/evaluation/runs`，默认看待审核会话。
2. 打开会话顺着看完整问答。符合预期，点“通过并看下一条”；备注不必填。
3. 某轮回答有问题，在回答旁点“标记问题”，写“哪里有问题，希望怎么改”。保存后进入“需修改”。
4. 通过引用的资料链接修改原文、标签、解释；也可以在新标签页打开文献、案例或 Prompt 迭代。Prompt 入口自动带入原问题和已保存的文字上下文。
5. 修改后点问题下方“修改后重新验证”。新回答与原回答在同一会话中保留。核对后点“确认解决”，再通过会话。
6. 原问题依赖附件或旧记录缺少请求时，页面会说明无法直接重答。回前台补传原件验证，在原问题下填写手动确认依据，再确认解决。
7. 师兄需要参与时，用自己的账号进入同一会话，在“补充意见 / 协助复核”留下判断；也可以直接标记问题。单人审核立即有效。

三个现有账号角色均可访问会话及提交人工审核。旧的执行所有权与开发者专用原始 Trace API 权限保留；新会话入口提供团队共享审核视图。新审核记录统一标为 `human`，实际操作人由服务端身份决定。

## 页面取舍

主导航五个入口：运行记录、文献管理、案例与措施、星标问题、Prompt 迭代。标签、能力说明、线上看板和原任务/用例/审核/回归入口收在“更多工具与历史记录”。历史记录、路由和旧 API 保留。

会话列表保留筛选和页码，运行状态、耗时等筛选折叠。回答默认展示问答和修改意见；路由、工具、上下文状态和配置折叠。文献编辑把摘要和结论移到常显区域，与 PDF 对照；标签维护可从分类区打开。问答使用状态说明资料是否已同步，技术详情折叠；同步中的状态自动刷新。已有资料保存、标签校验与案例开放逻辑继续使用。

## 保存与复查规则

- 审核、意见、标记与确认追加保存，原回答不可覆盖；审核人和时间自动记录。
- 状态只有待审核、已通过、需修改。未解决问题优先显示需修改。
- 通过操作只覆盖当时明确看过的连续回答。后来追加的轮次保持待审核，页面显示已审到第几轮。
- 多人同时修改时校验修订号；冲突要求先刷新，输入保留。问题说明与补充意见另存在本账号、当前标签页的草稿中，刷新后恢复。
- 验证复用持久运行管理器，按提交标识防重复，独立会话执行，来源为 `test`，关联原 Run；不会修改前台原会话或把验证运行再塞进日常待审队列。
- 验证使用提交时的表达配置与当前资料，带原请求保存的文字历史；不声称复现已失效的文件或全部历史运行状态。
- 生成出验证回答不自动解决问题；只有人工确认后才更新。直接核对或在其他入口验证时需要填写确认依据。

## 工程入口

- `GET /api/eval/sessions?review_status=pending|passed|needs_changes`：在分页前按审核状态筛选。
- `GET /api/eval/sessions/{id}`：问答、问题、意见历史和验证结果。
- `POST /api/eval/sessions/{id}/reviews`：通过、问题标记、意见、确认解决、重新打开。
- `POST /api/eval/sessions/{id}/retests`：使用原请求重新验证，返回 202，刷新会话读取进度。
- 数据沿用 RunStore 的 SQLite，新建审核状态和追加事件两张表；打开旧数据库时自动创建，不改写旧审核分类。
