# 跨模块运行、检索与审查契约

版本：V0.3｜日期：2026-10-17｜状态：审查修订，待开发验收

本文件收敛开发前审查 R01—R05，供 M01—M11 引用。以下是本轮目标契约，不表示应用已实现。字段名是语义名称，落地时可映射既有字段，但关联、状态和计数含义必须一致；本文与各模块的 V0.3 条款共同生效。

## 1. 已核实的开发基线

- 案例当前采用全量可用材料整体传入模型；`CaseStore.available()` 查询开放、未删除记录，自动范围做内容去重后检查数量与材料 JSON 容量。超过 30 条或 24000 字符返回 `413/case_capacity`，并非静默取前 30 条。显式选择较小范围仍需通过容量检查。
- 聊天请求当前没有稳定轮次和幂等提交标识；运行 ID 在执行时生成，最终 Trace 在退出执行时保存。已有 Trace 不能直接满足逐事件持久化和完整对客响应恢复。
- 现有评分绑定评测 execution，存在执行者与不可覆盖校验。正式会话直接审查、审查修订及新增维度需要适配；复用平台不等于这些接口已经存在。
- 上述结论依据 2026-10-17 审查时工作区静态阅读及案例容量复现，不代表线上部署或农业效果验收。

## 2. 提问、提交与运行身份

| 语义标识 | 规则 |
| --- | --- |
| owner | 服务端从登录身份或签名访客身份取得；客户端不能指定其他人的归属 |
| conversation_id | owner 范围内的会话；会话关闭或过期后不复用其命名空间 |
| turn_id | 一次用户提问；提交前由客户端生成并保留，网络重发和主动重新执行均保留该轮次 |
| request_id | 一次执行提交的幂等标识；网络重发不变，用户主动重新执行时新建 |
| run_id | 服务端受理后分配；同一 owner、会话和 request_id 只能关联一个运行 |
| rerun_of_run_id | 主动重新执行时指向原运行；原运行必须属于同一 owner、会话和轮次 |
| step_id / attempt_no | 一项逻辑动作及它的尝试编号；重试沿用 step_id 并递增尝试，独立调用另建步骤 |
| subtask_id / evidence_id | 本轮子任务和实际证据的稳定关联，引用不能靠列表位置推断 |

“继续追问”和编辑问题后重新发送均是新轮次，不能沿用旧 turn_id；对原问题点击“重新执行”才是同轮次的新运行。原运行尚未终止时，不并发创建该轮次的主动重跑；返回其状态。回归回放保留原运行关联，但 source 为 evaluation 或 test，不冒充原正式轮次。

M01 的理解结果绑定 run_id、turn_id 和 subtask_id，上下文锚点记录实际来源轮次、运行和资料标识。重跑产生新的理解快照，不覆盖原快照；尚未返回的计划材料不是可继承对象。M02 的覆盖记录逐子任务绑定采用内容及未覆盖任务，不能因答案顺序改变而串位。

### 2.1 受理与幂等

1. 执行前校验身份与请求契约，计算规范化请求指纹。指纹包含用户输入、历史／上下文引用、附件引用、指定能力和原运行关联等影响语义的提交内容；只做契约规定的规范化，不把两个含义不同的问题合并。原始输入另存，附件访问凭据不进入公开事件。
2. 持久化 owner、会话、轮次、request_id、指纹、run_id 和已受理状态，再调度工具。唯一约束及并发控制在服务端生效；受理失败不执行工具。
3. 同一提交标识与同一指纹再次到达时，返回已有运行或已保存结果，不重复调度；同一标识携带不同输入返回 `409/request_conflict`。
4. 受理回执包含 run_id、turn_id、request_id 与恢复入口。首个回执丢失时，可用原 request_id 找回受理结果；查询不存在时只返回未受理，客户端才可用原标识重发，仍由幂等约束处理竞态。
5. 运行的 source（formal/test/evaluation）、mode（auto/specified）由可信入口确定，不能仅信任普通聊天客户端传值。记录 actual_config_version，后续配置修改不改变已受理运行。

历史没有这些关联时标记未采集；不能按相同问题文本或相邻时间猜测轮次、重跑关系及来源。旧同步聊天接口可兼容保留，但不声明支持完整恢复，相关请求不混入要求完整身份字段的新指标分母。

### 2.2 事件、结果与断线恢复

- 事件在动作实际发生时产生；记录 run_id、单调递增 sequence、step_id、父步骤、subtask_id、attempt_no、时间、执行状态、业务结果、错误分类和证据关联。持久化后投递，传输可重复，不能用展示去重掩盖重复执行。
- 最终完整对客结果包含答案、引用题录与定位、案例来源、文件证据、章节、告警和状态。完成引用整理后，结果快照、终态及结束事件在同一提交中保存；不能只保存答案正文后声称可恢复完整回答。
- 结果保存失败时保留运行及已持久化步骤事实，记为恢复受阻或状态未知；不得通过重新执行工具补做一次“保存”。可用内存中的结果不伪称已持久化。中断窗口内无法确定外部动作是否完成时，明确未知，不承诺跨进程故障的外部调用恰好一次。
- 网络断开、折叠进度和关闭页面均不取消已受理运行；执行任务的生命周期独立于进度连接。取消须经真实取消接口，仍保留已发生动作；不可取消步骤结束后才确认停止位置。
- 客户端用 request_id 找回 run_id，以 sequence 补取事件或读取完整状态和结果。恢复查询、订阅及轮询均不执行任务；乱序按序号归并，重复事件不重复展示。
- 进程重启后，已保存结果原样恢复；未完成运行只有在能证明安全续接时继续，否则标中断，动作完成情况不明时标未知，禁止自动重放。事件保留不足但结果仍在时返回完整结果并提示过程不全。
- 幂等、事件、结果和会话的保留窗口在部署前配置并向恢复接口声明。幂等记录／墓碑在会话命名空间有效期内保留；恢复窗口过期返回 `410/recovery_expired`，不得把旧提交当新任务。过期会话不重新受理，客户端另建会话和新标识。

### 2.3 读取权限

找回提交、读取状态／结果、订阅事件和取消运行均验证 owner 与会话归属；不能凭 run_id 取得他人数据。跨归属请求按既有防枚举规则拒绝。公众只获取对客事件和结果；开发者 Trace、Prompt、原始工具输入输出、内部错误和人工审查意见继续走后台权限。恢复结果中的原件链接每次访问仍执行当前权限与可用性校验，不重写历史证据。

## 3. 案例候选与材料预算

候选搜索覆盖全部有资格记录，材料预算只限制进入本次模型调用的内容，不能再用“全部开放材料能否整体装下”决定搜索是否可用。选择检索技术仍按规模和实测，不强制引入向量基础设施。

排序和选材保留案例标识、标题、片段、版本／指纹、截取范围、未采用原因及预算。表格保留表头、单位、分组和单次／合计关系；一项必要材料无法完整取用时显示预算不足，不称无案例。显式指定和追问锚定的案例不得被自动换成其他对象。候选生成后和进入回答证据前复核开放、删除与访问状态。

验收包括：31 条去重后独立开放案例；不足 30 条但材料 JSON 超过 24000 字符；显式小范围可用；同一相关案例处于排序前部和后部；单条关键材料本身过大。验证自动候选可找到相关记录，且预算不足时说明真实原因，不要求用户关闭其他真实资料。

## 4. 适用条件与资料标签的关系

用户的硬条件是资料必须满足的语义条件，不等于数据库必须已有某个标签。候选阶段先执行访问权限、停用／删除等资格约束，再合并标签与正文／语义候选，最后核对适用性。缺少标签或未经核对的 AI 标签不能成为该语义条件的唯一排除依据；核对来源及版本须留痕。

| 资料对硬条件的证据 | 判定 | 检索与回答行为 |
| --- | --- | --- |
| 标签缺失，但正文明确满足 | 满足 | 保留正文候选，核对后可作为严格匹配证据 |
| 可靠正文明确不满足 | 不满足 | 排除该条件的答案依据；不能靠相近标签改回满足 |
| 标签与正文冲突 | 待核对 | 保留冲突记录；可由可定位的原文核对确认，未解决前不称严格匹配 |
| 标签与正文都不能确定 | 未知 | 可留在候选核对阶段；不作为满足硬条件的证据，不以模型猜测补齐 |
| 只有模型推断或近义标签 | 未知或辅助信号 | 可辅助排序，不能单独确认满足或不满足 |

一个比较任务按对象分别核对条件，不能把两地要求同时施加到一条材料。业务条件无严格匹配时说明缺口；如另列通用或条件未知资料，须明确其限制，不静默扩大范围。标签服务失败可改用正文核对，但不放弃用户条件和资料访问约束。若用户明确要求“只查带某标签的记录”，该任务才可直接按标签成员关系筛选，并记录这是显式标签筛选。

每条候选保存 condition_id、判定、核对依据、条件来源、实际过滤阶段和采用／未采用原因，M10 展示实际记录而非重新推断。

## 5. 执行状态、业务结果与计数矩阵

执行状态描述动作是否正常执行；业务结果描述动作得到什么。二者分开保存。步骤执行状态为待执行、执行中、正常结束、失败、取消、跳过、中断、未知；正常结束的业务结果可为有结果、无结果或需要澄清。结果 Schema 不合法是失败；合法空检索不是失败。

运行也分别保存执行状态与业务结果（完整回答、部分回答、待补充、未完成、未知）。正常生成必要澄清时是执行正常结束、业务待补充，前台显示“需要补充信息”；不能称原任务已完成。一个分支失败但已形成可用部分回答时，运行正常结束且业务为部分回答，同时保留失败步骤。取消、中断、未知按实际状态优先展示。

### 5.1 固定统计层级

步骤创建时声明 `kind=skill|tool|service|container`；kind 由实际执行边界确定，不由是否恰好记录到子步骤临时改变。Skill 统计注册能力调用；tool 统计有真实输入输出契约的底层操作，如本地计算或检索；service 统计前置理解、星标匹配等服务；container 仅组织步骤。父 Skill 与子 tool 各进自己的指标，不能相加作为同一个“工具总数”。

没有记录底层 tool 时只能报告 Skill 指标和工具观测缺失，不把父 Skill 推算成若干成功工具。旧 Trace 仅有 skill tool_calls 时可单列历史 Skill 口径，不补造新层级。一个逻辑步骤的重试只计一个步骤，逐次尝试另计。

| 目标工具步骤情形 | 步骤成功率分子 | 步骤成功率分母 | 尝试失败率 | 其他处理 |
| --- | --- | --- | --- | --- |
| 实际开始并正常结束，有结果 | 1 | 1 | 每次已结束尝试按事实计 | 检索有结果可计命中 |
| 实际开始并正常结束，无结果 | 1 | 1 | 正常尝试不是失败 | 检索无结果分子与分母均加 1 |
| 实际开始后失败，包括输出契约错误 | 0 | 1 | 失败尝试进分子与分母 | 不算正常检索无结果 |
| 失败后重试正常结束 | 1 | 1 | 失败及成功尝试分别计 | 不掩盖尝试级不稳定性 |
| 计划后跳过或尚未开始 | 0 | 0 | 无尝试不计 | 原因可为无材料、预算不足或依赖失败 |
| 实际开始后取消 | 0 | 0 | 取消尝试不计；此前已结束尝试仍计 | 单列取消，不撤销之前的事实 |
| 中断、未知、历史未采集 | 0 | 0 | 仅已明确结束的尝试可计 | 报缺失数量，不推断成功或失败 |
| 必要澄清 | 按目标步骤 kind 及实际执行状态计 | 同左 | 同左 | 程序澄清通常为 skill，无 tool 调用则不进工具指标 |

工具执行成功率＝正常结束的已开始 tool 步骤数／执行状态为正常结束或失败的已开始 tool 步骤数。工具尝试失败率＝失败 tool 尝试数／正常结束或失败的 tool 尝试数。仅统计选定主运行及统一 source、mode、版本和时间范围内的步骤／尝试。

检索无结果率＝最终正常结束且业务无结果的检索 tool 步骤数／最终正常结束的检索 tool 步骤数。一个检索步骤有结果不等于证据已被人工判相关或充分；失败、取消等单列。Skill 成功率另用相同执行规则按 kind=skill 计算，不与工具指标混合。

| 样本 | kind 与事实 | 工具步骤成功 n/N | 工具尝试失败 n/N |
| --- | --- | --- | --- |
| S01 | tool：第一次失败，第二次正常有结果 | 1/1 | 1/2 |
| S02 | tool：检索正常结束，无结果 | 1/1 | 0/1 |
| S03 | tool：计划后跳过，未调用 | 0/0 | 0/0 |

## 6. 正式 Run 审查与历史评测兼容

复用原认证、列表、问题跟踪、评测用例和回放能力，新增正式 Run 的直接审查关联，不为每条正式问题伪造评测 execution。审查对象为 run_id，并保留 owner／会话／轮次关联；跨运行对比另关联，不把多个运行合成一个正确样本。

### 6.1 审查记录及修订

- 保存 review_id、目标 run_id、revision、修改人／身份、时间、前版关联、source、sampling_source、方法类型（人工／AI 辅助）、依据与结构化维度。source 继承目标运行，不由审查表单改写。抽样来源至少区分随机、失败、用户反馈、专题和回归；随机标识须关联实际随机抽样记录，来源不明记未知，不能把异常样本改称随机。
- 每个 Run 只有一份当前生效的人工作业审查，可含各维度的独立状态；AI 辅助记录另存，不自动成为人工结论。需要领域专家签核的结论沿用现有角色控制。
- 提交使用服务端校验的提交标识和 expected_revision。重复提交返回原结果；并发旧版保存拒绝并保留表单内容，不静默覆盖。修订追加历史、原子切换当前版本；不修改原始用户输入、回答和 Trace。
- 审查意见冲突记待复核，保留各方依据；解决后产生新版本。待复核不进正确率分母，也不算已完成审查覆盖，单列数量。
- 可先保存草稿；只有完整保存必需维度（路由、回答、主因及依据，允许按规则填写无法判断／不适用）的人工审查才是当前有效审查。额外维度未填不进入对应指标分母。
- 正式 Run 审查按现有后台角色授权；审核者无需是原执行者，需有该正式会话的审查权限。旧评测执行者自评及已提交不可覆盖规则继续保留，新适配不能放开旧接口访问限制。

### 6.2 逐维度字段

每个维度独立记录 `applicability=applicable|not_applicable|unknown`、`judgment_status=judged|unjudgeable|uncollected`、结论与依据。只有适用且已判断时允许有效结论；不适用不填结论，无法判断必填原因。冲突状态由审查记录控制。未采集不等于不适用。

| 维度 | 适用且已判断时的结论 | 独立含义 |
| --- | --- | --- |
| 问题理解 | 正确、部分正确、错误 | 条件、指代、换题和子任务是否保持原意 |
| 路由 | 正确、部分正确、错误 | 能力、顺序、遗漏及合理替代路径 |
| 标签与筛选 | 合理、部分合理、不合理 | 实际映射及条件核对是否合理 |
| 证据相关性 | 有效、部分有效、无有效证据 | 有效＝至少一条相关且可用证据；部分有效＝有相关线索但尚无可用证据，不混入有效分子 |
| 证据充分性 | 充分、部分充分、不充分 | 对当前任务所需范围是否足以回答，与相关性独立 |
| 工具结果 | 正确、错误 | 对照实际原件与口径，不能由执行成功自动填正确 |
| 回答质量 | 合格、部分合格、不合格 | 事实、覆盖、引用、条件和易懂性 |

证据相关但不足可记“有效＋不充分”。确认检索正常返回空集且无其他可用证据时，可记“无有效证据＋不充分”；若 Trace 或原件不足以作判断，记无法判断并说明原因。不能用空结果自动证明算法错误或路由错误。

旧 route_correct 的 yes/no 可保留映射为正确／错误；其他 yes/partial/no 仅在原字段含义等价时映射。旧 n.a. 的原因不明时只保留原值与未采集状态，不能推断为不适用或无法判断。旧 evidence_correct 不同时回填相关性和充分性。历史多 Run 合并评分不能复制到每个正式 Run，当作多条新人工审查。

## 7. 主运行和指标分母

本修订采用“同一正式轮次首次已受理运行”为默认主运行，受理时固定 primary_run_id；失败、取消、未知不被成功重跑替换。网络重发复用原运行，工具重试不增轮次；主动重跑沿用 turn_id 但新建 request_id/run_id，重跑恢复效果单列。预受理校验拒绝不算已受理正式轮次，拒绝请求另计。

默认正式提问量按 owner、会话、turn_id 去重，归属时间取首次受理时间；主运行及其步骤均按该时间进入同一统计窗口，尝试级诊断若另按实际动作时间报告须单列口径。筛选 Skill 时使用主运行实际开始的 Skill；同轮多 Skill 分组不可相加为总提问量。来源或关联未采集的历史记录单列，不猜测主运行。

各人工指标独立取同一范围内当前有效人工审查、适用且已判断的主运行作分母。路由正确／部分正确的分母只含 formal＋auto；回答、理解、相关性、充分性分别按当前选择的来源和模式，页面展示该范围，不混用自动与指定模式。部分结论不折算分数。

相关性分子只取“有效”，充分性分子只取“充分”，两个维度缺一项不借另一项补齐。覆盖率＝有当前有效人工审查的正式主运行数／该范围正式主运行数；待复核、草稿、纯 AI 辅助不进覆盖分子。各维度无法判断或未采集仍可出现在已保存审查中，但不进该维度正确率分母。

审查修订更新当前统计，并显示更新时间与审查版本；旧报表快照如保留，应附口径版本和截止时间。分母为零显示暂无可计算样本。状态缺失、取消、待复核、无法判断、不适用、未采集各自展示；图表跳转使用相同过滤和去重键。

任何采用其他主运行策略的后续变更须独立版本化，并展示与默认口径的差异，不回写原主运行关系。没有足够结构化字段时先展示可证明的计数，不从自由文本备注或工具成功状态生成专业正确率。
