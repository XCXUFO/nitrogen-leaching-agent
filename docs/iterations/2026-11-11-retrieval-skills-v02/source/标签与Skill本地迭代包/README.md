## 2. 从哪里开始使用

| 文件 | 用途 |
|---|---|
| `taxonomy.json` | 程序读取的标签全量快照：原标签 ID、完整路径、父子关系、状态、直接关联数 |
| `标签全表.md` | 人工查看和检查全部 101 个标签 |
| `skills.json` | 七项能力的用途、边界及本次页面状态；详细说明来自归档代码，来源字段已区分 |
| `intent_skill_mapping.json` | 意图到 skill 的本地建议映射，可继续调整 |
| `aliases.proposed.json` | 别名、口语表达及相关主题的本地候选配置，全部保留待审核标记 |
| `match_keywords.py` | 无第三方依赖的本地初步匹配器，接收上游已提取的关键词与意图 |
| `examples/` | 五组输入和实际生成的匹配结果：玉米、陕西歧义、WHCNS、排除条件、N₂O |
| `原实现同义词.json` | 从已有代码原样提取的同义词配置，供比对 |
| `原实现参考/` | 原有问题理解、标签映射、路由、文献和案例检索代码及相关 PRD |
| `线上标签页面原始行.json` | 本次页面采集原文与校验值，便于追溯 |
| `本地校验结果.json` | 数据及匹配边界的本地检查结果 |

本包是本地匹配数据和参考实现，**不是网站批量导入文件，也不包含文献正文、PDF 或数据库备份**。`tag.id` 保留线上真实值；页面没有暴露线上维度 ID，因此 `dimension_key` 使用本地键 crop、region、topic、variable、method，`source_id` 留空。不要将这些本地维度键写成线上维度 ID。`display_index` 是采集时的页面顺序。

在本包目录运行（Python 3.9 及以上）：

```sh
python3 match_keywords.py 玉米 氮淋失 --intent knowledge --with-proposed-aliases
python3 match_keywords.py 陕西 小麦 --intent case_search
python3 match_keywords.py --input examples/排除条件.input.json --with-proposed-aliases
```

也可以在本地项目中调用：

```python
from match_keywords import Matcher

matcher = Matcher(with_proposed_aliases=True)  # 服务启动时构建一次并复用
result = matcher.match(
    keywords=["玉米", "氮淋失"],
    intents=["knowledge"],
)
```

示例中，“玉米”匹配 `T-74ce41cce69c`，“氮淋失”通过本地候选配置匹配“氮淋溶” `T-5e6cb0404324`；意图 knowledge 对应 knowledge_search。“氮淋失”候选配置仍是待审核辅助信号，不代表线上已有这条同义词规则。

匹配器**不从整句自动抽取意图**，也不执行检索或 skill。它承接上游结果，用字典索引做精确查找、规范化和歧义保留。没有开关 `--with-proposed-aliases` 时只使用现有名称及完整路径。已提取的多任务意图可重复传入 `--intent`；未知意图会原样返回。

## 3. 建议采用的处理流程

1. **理解本轮问题。** 保留原问题，并提取任务意图、关键词、否定条件、数值单位、比较对象；结合相关历史解析“它”“那两个”等指代。不要把示例文件中人工填写的意图当成模型已完成抽取。
2. **分别匹配两类候选。** 意图回答“要做什么”，用于选择 skill；标签回答“关于什么”，用于定位资料。两者独立保存。
3. **合并召回。** 标签命中资料与原问题的关键词／语义候选取并集，再做适用性核对及排序。匹配器返回候选 ID 和层级展开，不自行判断文献结论是否支持问题。
4. **保留兜底。** 未匹配关键词继续检索。标签无结果、歧义未解决或候选不足时，保留原问题检索路径；资料访问约束始终执行。
5. **记录本轮依据。** 保存原词、规范词、标签 ID、路径、匹配方法、否定性、条件来源、对象分组及配置版本，以便回看误匹配。

上游建议结构：

```json
{
  "original_query": "排除玉米，找小麦的氮淋失研究",
  "intents": ["knowledge"],
  "keywords": [
    {"term": "玉米", "polarity": "exclude", "source": "current_user"},
    {"term": "小麦", "polarity": "include", "source": "current_user"},
    {"term": "氮淋失", "polarity": "include", "source": "current_user"}
  ]
}
```

本地匹配器保留 polarity、condition_id 和 object_group，不擅自把否定变成正向召回。最终检索实现应按它们执行并留痕，不能只拼接所有 term 后检索。

## 4. 首轮迭代规则

- **稳定标识用 ID。** 名称、完整路径用于解释；改名后不重新生成标签 ID。
- **停用状态沿祖先检查。** 使用 `effective_enabled`；父节点停用，后代自身即便启用也不能参与新匹配。
- **有歧义就保留多个 ID。** “陕西”对应两个现有分支，不按名称覆盖。明确说“西北 / 陕西”才解析到该路径。
- **普通主题词默认辅助召回与排序。** “玉米案例”是语义范围；没有玉米标签但正文明确符合的资料仍应参与核对。标签命中也不能替代正文验证。
- **只有用户明确指定标签成员筛选，才启用标签硬筛选。** 上游设置 `explicit_tag_filter: true`，且本地匹配唯一、名称或完整路径精确命中时才输出该用途；别名候选和歧义不能静默转为硬筛选。
- **显式标签筛选可复用同维度 OR、跨维度 AND，并展开父标签的有效后代。** 比较两个地区应按对象分组分别检索，不能要求同一篇材料同时属于两地。语义条件按各自适用性核对。
- **相关词与严格同义分开。** N₂O 对应氧化亚氮相关主题；硝态氮淋失比氮淋溶更具体；“氮损失”可能涉及多种途径，不直接等同于氮淋溶。
- **保留 skill 边界。** “WHCNS模型是什么”属于知识问答；“上传的 WHCNS 表最大值”才涉及附件检查与结果分析。题目出现 WHCNS 标签不意味着要运行模型仿真。
- **资料状态运行时复核。** 页面关联数不能证明记录已经开放、完成全文索引或适合本轮问题。

## 5. 本次发现的具体整理项

**优先核对旧作物标签。** `T-067d23c4868a` 现在叫“已废弃”，说明仍写“适用于【玉米】这一作物类型”，页面显示直接关联 **80 篇文献、4 条案例**。有效的新玉米标签 `T-74ce41cce69c` 显示 24 篇文献、0 条案例。应逐项核对旧关联是否需要迁移；这两组计数可能重叠，不能直接相加，也不宜自动迁移全部记录。首期检索必须给未迁移资料保留正文召回入口。

**陕西存在两个 ID。** `黄土高原 / 陕西` 为 `T-24799bce23b7`，直接关联 6 篇文献；`西北 / 陕西` 为 `T-cafd9629e04b`，显示 0 篇。它们目前是不同分类路径。可以后续研究统一地理概念 ID 与分类路径的关系，当前先保留歧义并合并候选，不删其中一个。

**“桂平”“南宁”处于停用地区分支。** 两者自身显示启用，但父标签“已废弃”停用，故本包不让它们参与新匹配。是否移到现有有效分支，另作数据整理。

**活跃标签页面的案例关联数全部为 0。** 这不能推出没有案例，而说明当前有效标签不足以单独充当案例检索入口；已废弃作物标签仍显示 4 条案例关联。

**复合抑制剂标签需要保留原名。** “硝化/反硝化/脲酶抑制剂”内部的斜杠不是层级分隔符；本包只将带空格的 ` / ` 解析为层级，并将三个单独词列为相关主题候选。以后是否拆标签，结合材料和检索需求决定。

## 6. 已有代码能复用什么

参考文件来自本机此前归档，Git 提交为 `a95b797b4ea0da19cac198167d24d434055816d2`，本次检查工作区无已跟踪文件修改。它们不是此次 SSH 重新下载的线上源码；每个参考文件的哈希已记录。

- `understanding.py` 已包含问题意图、原词／规范词、同义表达、条件来源、多轮指代、标签映射和正文条件核对。
- `routing.py` 已区分知识、案例、文件分析、组合请求和澄清。
- `query_intent.py` 已区分“影响最大”这样的定性问法与数值极值请求。
- `case_retrieval.py` 和 `literature_index.py` 有可复用的资料适用性及状态核对逻辑。

归档实现中的标签映射会逐个概念检查启用标签；文献管理索引和案例检索路径仍存在遍历候选并计算词项分数的处理。**“已有标签映射”不能直接说明“标签已形成提速索引”。**

下一步在完整本地项目中优先建立并维护 `规范词 → tag_id`、`tag_id → paper_id/case_id` 两类倒排索引，文献分片保留 paper_id 关联。资料状态、打标、停用和删除时更新索引；标签改动刷新词典缓存。先用标签索引快速产生候选，再与关键词／语义候选合并并复核正文。

参考代码依赖完整项目，不能把“原实现参考”当作独立可运行服务；本包中可独立运行的是 `match_keywords.py`。
