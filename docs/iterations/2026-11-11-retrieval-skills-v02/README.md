## 功能增量

| 环节 | 本轮行为 |
|---|---|
| 星标前置 | 全部请求先做轻量适用性判断。能力咨询、当前文件计算、真实案例/材料操作、指定执行和查新要求记录不适用，不强制查询无关星标。正式标签匹配在星标之后；理解阶段仍可读取目录辅助识别实体。 |
| 完整覆盖 | 同义问题与适用范围核对后，直接返回参考答复及来源；标签匹配标记 skipped，无重复 Skill、资料检索或模型调用。 |
| 需求点覆盖 | 单个 subtask 内仍检查独立需求。SQ-024 的原因可复用，结构、输入输出、耦合、验证等构建需求继续处理，不因答案非空就结束整轮。未采用任何答复时保留原任务，不把推断的需求改写强加给用户。 |
| 范围保护 | 不用规划平台的五项功能回答当前助手能力；WHCNS 背景介绍不回答版本、全剖面、地下水、几百米、精度或实际仿真执行。当前作物、地区、数字和否定条件继续参与核对。仅有词项相近不等于可复用。 |
| 空答案及冲突 | 空库、服务不可用、服务异常、命中空答案、内容未就绪及冲突分别留痕；全部继续后续可用路径。相同需求有不同维护答复时也不任意取第一条。 |
| 剩余任务上下文 | 原始理解完整保留；后续使用 execution_context 视图，只带未满足需求的条件、关键词和子任务。已覆盖玉米题的条件不污染另一个小麦任务。 |
| 案例与附件 | 一般概念答复不能替代真实案例。复用知识部分后仍检索并核对案例；已有文件数值不能替代本轮附件单元格计算。 |
| 合并与失败 | 保留已有答复及真实后续结果。后续失败时返回 partial 与未完成原因，不把整轮写成成功或丢弃已采用内容。同一问答覆盖两个任务时，答案及证据去重，并保留两个任务关联。 |
| 历史与来源 | 采用项保留业务 ID、revision、内容指纹、答案快照、来源、覆盖需求及未覆盖需求。修改后新运行读取新值，旧运行保持原快照。未采集专业审核信息统一为 unknown。 |

本轮没有新增第八个 Skill，也没有引入逐步骤理解模型调用。首批匹配以规范题、明确维护的同义问法和少量受控需求规则为准；规则无法确认覆盖时继续现有检索，不以分数冒充语义或专业审核。

## 数据与页面

现有星标表新增 `reuse_json`，保存 `reuse_status`、`coverage_scope`、`excluded_scope`、`source_refs`、同义问法与来源范围。`eval_starred_sources` 保存批次、SQ 编号、真实业务 ID 和来源指纹；业务 UUID 正常生成，SQ 编号没有被用作业务主键。

旧版 question/answer/revision 接口继续有效。旧客户端编辑不传 reuse 时保留原范围信息；范围修改也受同一 revision 冲突保护。新页面可以查看、编辑状态、可覆盖范围、未覆盖内容和来源；导入资料的匹配配置在编辑时保留。没有自动把导入材料标为已专业审核。

入口仍为 `/evaluation/starred-questions`。既有运行详情新增“星标前置”摘要和“星标后剩余需求上下文”；完整覆盖与部分覆盖、采用来源和未完成原因可展开核对。历史字段缺失显示未知。

## 录入工具

`backend/scripts/import_starred_batch.py` 默认仅在内存副本中预览，不改业务数据库。`--apply` 先备份，再在事务中重新核对并创建或绑定缺失记录；存在冲突则停止，不覆盖已有答复。重复执行保留已绑定的问题及人工修改。

```bash
# output 每次使用新目录；默认数据库为现有本地 agent_trace_db。
backend/.venv/bin/python backend/scripts/import_starred_batch.py \
  --output backend/var/handoff/starred-preview-new

backend/.venv/bin/python backend/scripts/import_starred_batch.py --apply \
  --output backend/var/handoff/starred-import-new
```

本轮已经完成本地录入，无需再次执行。后续可直接在已有星标页面维护。未就绪答案继续留空或保持 pending/conflict，补齐范围与依据后再改为参考答复。
