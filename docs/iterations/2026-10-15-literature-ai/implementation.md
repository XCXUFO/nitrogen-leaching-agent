# 文献 AI 打标与结论录入

日期：2026-10-15

## 页面行为

- 文献编辑页的“分类标签”提供“AI 一键打标”。根据上传 PDF 和表单中的标题、摘要、结论匹配现有启用标签，填入表单后仍可手动调整，通过原有保存按钮入库。
- 已有标签优先保留；单选维度不追加冲突标签，同一分支不同时增加祖先和后代标签。模型返回的未知、停用或冲突标签会被过滤。
- “来源与补充说明”新增可换行的“结论”文本框和“AI 解析结论”按钮。解析只填入空白结论；已有内容通过原有解析建议面板选择覆盖。
- 上传后自动解析与“AI 解析字段”同样包含结论。结论从论文结论章节提取原文；无法识别时留空，允许手动填写。
- 详情页展示保存的结论。AI 请求失败保留表单和标签；取消编辑或更换 PDF 后，不应用旧请求的返回结果。

## 接口与存储

- 新增受现有后台登录保护的 `POST /api/literature/suggest-tags`。目标可以是当前用户未消费的 `upload_id`，或已有的 `paper_id`。接口仅返回建议，不修改文献或标签目录。
- 文献创建、编辑、读取和 `POST /api/literature/extract` 增加可选 `conclusion` 字段，最多 20,000 字符。
- 结论存储在已有文献 JSON 字段中，无需数据库结构迁移。旧记录读取时补空字符串；旧客户端编辑时省略此字段不会清空已有结论。
- 使用现有服务配置中的 LLM。打标未配置模型或调用失败时提示重试；基础字段解析继续保留原有本地提取回退。
- PDF 提取读取前 3 页及末尾最多 10 页，在文末优先定位结论章节并送入模型，总文本上限 40,000 字符。扫描 PDF 无可选文字时提示手动填写；本次未增加 OCR。

## 验证

- 后端 `test_literature_extract.py`、`test_literature_tagging.py`、`test_literature_http.py` 共 21 项通过，覆盖文末结论读取、结论持久保存与清空、历史记录兼容、权限、标签约束、AI 异常及推理期间标签停用。
- 浏览器用例 `frontend/tests/literature-ai.spec.ts` 与 `literature-review.spec.ts` 共 3 项通过，覆盖结论填入与人工覆盖、标签保留、AI 和保存失败后的输入保留、保存刷新后的展示，以及原有上传和并发编辑行为。
- 前端 TypeScript 类型检查、变更文件 ESLint 和 `git diff --check` 通过。
- 模型返回使用测试替身；测试结果用于验证操作链路，不代表真实模型在全部论文上的提取和分类准确率。
