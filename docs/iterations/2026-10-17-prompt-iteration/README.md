# Prompt 版本与全局表达

将“解释方法对照”改为“Prompt 迭代”，保留原路由 `/evaluation/explanation-trials`。

- 左侧选择已保存版本，只读查看；右侧可选择历史版本或编辑新增版本。两侧默认 Markdown 渲染，可切换原文或编辑；历史快照同样支持 Markdown。保存和执行仍使用未经转换的原始文本。
- 输入区并排、Prompt 面板缩短，重复模块标题移除；对照材料折叠，减少空白和重复内容。
- 版本可独立保存，不需要先填问题或生成回答。新增版本另存，历史原文不覆盖。
- 同题对照使用同一问题、固定材料、模型与生成参数。保存实际使用的两份 Prompt、内容指纹及对应回答，历史没有原文的记录明确提示无法还原。
- 两个内置版本分别保留原有的表达偏好原文，以及该原文加上原有 `METHOD_PROMPT` 的增强版；不重写这两份原始表达指令。各任务的证据、引用、输出格式契约仍由原任务提供。
- 保存和对比不改变全局版本；选择已保存版本并点击“设为全局生效版本”后，新受理的回答使用所选版本。SQLite 中只有一个全局选择，重启保持选择。
- 文献问答、机制分析、案例参考及解释的模型生成统一读取受理时的版本快照。版本切换不改变正在执行的回答，也不改写历史回答。程序计算与已有维护内容保持原来的生成方式。
- 移除逐题评价和程序数值检查的界面，保留旧评价数据。
- 对照只使用固定材料，不自动重新检索 RAG；可粘贴相同的检索证据进行表达对比。

接口复用原对照入口，新增认证 `/api/eval/prompt-versions`（GET/POST）及 `/api/eval/active-prompt`（GET/PUT）。初始全局版本为增强版，之后启动不重置人工选择。

验证：相关后端回归 159 项通过；TypeScript、ESLint 与隔离生产构建通过。最终浏览器 2 项通过，覆盖 Markdown 标题、粗体、表格、代码块、原文保存、唯一标题、版本操作、刷新保留及手机宽度无横向溢出。已备份数据库并重启前后台；运行构建与页面资源校验见 `live-verification.json`。
