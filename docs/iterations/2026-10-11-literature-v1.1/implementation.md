# 文献后台 V1.1（2026-10-11）

## 依据

用户提供 `文献后台1011.pdf` 第 2–3 页「版本 V1.1」。原 PDF 为图像页，逐页阅读确认：

1. 维度作为分类起点，各级标签保留父子关系；选择广西应包括南宁、桂林及县级等全部后代。
2. 标签维护轻量化，展开后逐级新增，减少复杂操作。
3. 检索模块紧凑排列，可逐级选择标签，参考多列级联选择样式。

## 实现

- 后台与 showcase 共享 `literature-taxonomy.tsx` 的层级组件。
- 标签管理采用嵌套树，支持节点展开/收起、展开全部、收起全部及保留祖先的路径搜索。
- 每个节点提供「新增下级」，同一位置填写名称并保存；新增一级标签有独立入口。第五级不显示新增下级。后端继续强制最大五级、同级名称唯一、禁止循环及非法跨维度移动。
- 说明、移动、启停及排序仍可通过节点「编辑」操作维护；父子关系使用稳定 ID 保存，未改动现有数据模型。
- 列表常用筛选保持展开；发表信息、人员、日期收进「更多筛选」。每个维度使用级联面板逐列展开，浏览分支与勾选独立。
- 筛选父级包含全部下级；同维度多个分支为或，不同维度为且。选择下级替换同一路径上级，可缩小范围；保留完整路径展示、标签搜索及已停用标签历史查询。
- 录入打标也使用级联面板；单选维度最多一个，多选维度选择祖先/后代时替换同一路径冲突标签。
- 公共 showcase 新增地区示例「广西 → 南宁 → 示范县」与「广西 → 桂林」，使用既有 3 篇合成论文，不写入正式文献库。
- 原有 90 篇文献保持全局、未打标，不为正式资料自动建立示例维度或添加标签。

## 2026-10-12 AI 解析故障修复

实测后端日志显示模型连接错误。服务环境的 `HTTP_PROXY`/`HTTPS_PROXY` 值将多行 DNS 地址误当作代理地址；直接连接 DeepSeek 也超时。原调用使用 60 秒超时和重试，前端代理先返回 500。现在单次字段增强最多等待 18 秒；模型异常时接口返回本地 PDF 字段建议（HTTP 200），并在页面明确提示 AI 暂不可达。同一进程内失败后 60 秒内直接使用本地结果，避免连续操作重复等待。PDF 文字输入限定为前 3 页、最多 12,000 字符，以减少模型上下文和等待时间。

本地字段提取依据 PDF 自带元数据与首页的字号、文本块位置和显式“题目/作者”标记，抽取标题、作者、DOI、年份、发表载体、语言及可确认的摘要；字号过滤用于去掉英文作者姓名后的上标单位字母，不把单个元数据作者冒充完整作者列表。现有 90 篇 PDF 的只读检查：89 篇标题与旧登记标题相似度至少 0.9，77 篇提取到作者列表，87 篇提取到 DOI，87 篇提取到年份，79 篇提取到摘要；旧登记年份有在线发表年与期刊卷期年的差异，不能直接作为唯一真值。用户仍需对照右侧原文确认后保存，解析接口不修改文献记录。

外部方案调研：学术论文的题录字段可参考 [GROBID](https://github.com/grobidOrg/grobid) 的页眉结构识别；复杂版面和扫描件可评估 [Docling](https://github.com/docling-project/docling) 或 [MinerU](https://github.com/opendatalab/MinerU)。目前 90 篇均有文字层，优先使用现有 PyMuPDF 和有界本地提取，避免为本次字段登记引入模型权重、Java 服务或额外部署。扫描版仍明确提示需补 OCR。

### 7890 代理配置与在线解析恢复

用户确认代理端口为 7890 后，实测 `http://127.0.0.1:7890` 可连接 DeepSeek。此前模型客户端忽略系统代理变量，且未配置 `DEEPSEEK_PROXY`，因此实际走的是超时的直连路径。已在被 Git 忽略的本地 `backend/.env` 配置正确代理。

代理恢复后，原字段提取请求仍出现 JSON 解析失败；新增字段提取专用 `chat_json` 请求，按 DeepSeek 官方参数启用 JSON 输出并关闭思考模式，普通对话调用保留既有设置。同一篇真实文献实测：PDF 读取约 0.146 秒，模型返回经校验的字段约 2.466 秒，包含标题、5 位作者和 DOI。此数值为单篇样本，非全库延迟保证。模型客户端与文献提取相关测试共 20 项通过。
