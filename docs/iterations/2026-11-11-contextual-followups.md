# 按话题和回答推荐追问

旧逻辑仅根据知识问答、案例两类路由和对话轮数轮换固定题库，导致农业模型展望也显示农田机制、影响因素等追问。

新逻辑在前端使用当前问题、明确的上下文承接、实际回答和引用情况筛选并填入追问：

- 模型及模型展望围绕模型适用性、输入、验证或发展方向；回答提到人工智能时才出现对应追问。
- 农业过程只追问回答中已出现的具体机制、因素及适用条件；当前没有文献引用时不默认声称上述结论有文献依据。
- 案例按实际引用的案例推荐；缺少案例时仅引导补充检索条件，案例不可用时不推荐继续解释。
- 点击案例追问时，发送实际展示的 `case_ids`；单案例文案保留“上面这个”的指代。提交恢复、失败重试、重新回答和账户历史都保留这组 ID，避免标题检索引入未展示的其他案例。
- 换话题立即重新选择，不因同属 knowledge 路由沿用旧主题；只有明确的上下文追问可以承接前一个主题。
- 最多三条，排除已经问过的问题；话题不明确、回答信息不足或没有合适候选时不显示。不会增加模型调用，也不会改变后台回答问题的范围。

验证：追问与账户历史的 11 项浏览器回归通过，覆盖模型展望、人工智能提及条件、同路由换话题、无实质回答、实际引用条件、知识与案例多轮点击、案例缺失、文件回答、手机布局，以及案例 ID 在失败重试、重新回答和历史恢复后的保留。TypeScript 和相关 ESLint 检查通过。
