# 检索与 Skill 链路改造 V0.1：本地实现

本轮以收到的 PRD 为增量改造依据，保留当前项目已有的统一理解、星标覆盖、概念解释、案例助手、附件分析、外搜和历史审核能力。包内旧实现用于核对差异，没有覆盖当前代码。

## 来源与范围

`receipt.json` 记录 ZIP、PRD、校验清单指纹及本地基准提交。清单 32 文件全部校验通过；ZIP 33 项，多出校验清单本身。单独提供的 PRD 与 ZIP 内一致。原件在 `source/`。

标签快照包含 101 个标签、97 个有效节点、5 个维度本地键。标签历史 ID 和两个“陕西”分支保留。包内没有线上维度 ID，测试使用明确标为 fixture 的维度适配，没有将 dimension_key 导入业务数据库。候选别名原样进入版本文件 `backend/data/retrieval/aliases.json`，待审核状态未改为已审核。

线上部署代码版本没有核实。本次未上线，也未进行标签合并、旧关系迁移或正式审核状态修改。此前八条会话的原资料、旧运行和审核结论保持原状。

## 增量实现

| 需求 | 当前实现与边界 |
|---|---|
| F01 理解快照 | 路由、标签、知识及案例取材共用本轮理解；保留原问题、补全问题、条件来源、否定、更正、对象组、子任务及依赖。没有新增理解模型调用。规则不确定时沿用澄清和原文检索。 |
| F02 名称与标签 | NFKC、大小写、完整路径、原有受控别名、候选相关主题分别处理；缓存名称和后代索引。当前状态变化刷新缓存，旧运行冻结其映射配置。语义条件核对正文；显式标签严格执行成员关系，同维度 OR、跨维度 AND。歧义、未知标签和待确认别名不静默放宽。 |
| F03 任务与 Skill | 现有 Skill 边界继续有效；计划记录候选、输入要求、依赖状态及版本，实际调用单独记录。当前案例能力已统一为 `case_assistant` 的 search/explain/compare/evidence 模式，保留旧入口兼容，没有恢复旧包中的双 Skill。WHCNS 名词介绍不进入附件计算。指定入口记录 specified。 |
| F04 本地索引 | SQLite FTS5 + 标签成员倒排 + 文献片段行号关系。源表、关联表及全文同步表触发器维护脏队列；请求处理前增量刷新。改标不改变正文同步版本，停用和删除重新核对当前状态；索引构建使用事务保存点，失败保留旧索引并回到旧扫描路径。 |
| F05 多路召回 | 原词/全文、标签、现有语义召回按子任务及对象生成请求；单任务不重复召回。各路按名次融合，不裸加 BM25 与向量分数。默认每路及合并候选预算 160；小案例库和不足候选有有界扩展。记录实际路线、预算、采用与过滤依据。 |
| F06 证据返回 | 正文冲突不会因标签而改成满足，未知单独保留；无标签正文仍可采用。比较对象优先保留各自证据，模型上下文缺对象时说明缺口并返回 partial。生成后再次检查资料资格和条件，标签变更也会触发检查。原附件数值成功、机理失败的部分结果链路保留。 |
| F07 运行详情 | 既有 MQ 详情增加计划与依赖、索引版本/候选/增量数/耗时/回退摘要；原有 JSON 明细保留。召回候选与实际送入模型的片段分别记录，不能以 selected 候选冒充实际采用证据。版本清单包含三个开关与别名文件指纹。 |

缓存和本地索引只生成候选；资料访问资格仍以当前业务表为准。参考文献列表在正文索引构建时剔除，数量在诊断记录中保留，不占最终证据预算。常规正文检索只读取有限候选；标签召回及受影响片段的更新通过关系索引定位，避免对 FTS 资料 ID 列作隐含全表扫描。

## 切换与重建

`.env.example` 已补充三个独立配置：

```dotenv
UNIFIED_ROUTING_ENABLED=true
RETRIEVAL_STRATEGY=indexed
RETRIEVAL_FUSION=rrf
```

分别改为 `false`、`scan`、`legacy` 可回退理解路由适配、SQLite 候选路径和融合策略；重启服务生效。开关影响运行版本指纹。回退不删除新运行、不回灌旧库。它们是检索策略开关，不用于还原整段历史代码。

首次查询会建立本地索引；之后只处理脏资料。维护时可在项目根目录运行以下命令（路径换成实际数据库和原件目录）：

```bash
backend/.venv/bin/python backend/scripts/rebuild_local_retrieval.py \
  --literature-db /path/to/library.sqlite3 --literature-root /path/to/files \
  --case-db /path/to/cases.sqlite3
```

工具要求数据库已存在，可只指定其中一库。重建幂等，使用保存点切换；不重新向量化，不更改资料 ID。SQLite 无 FTS5 或索引故障时，检索诊断显示 degraded/scan；访问资格不会随回退撤销。

## 性能与真实复测

离线工具 `backend/scripts/benchmark_retrieval.py` 固定此前收到的 35 篇文献、原件指纹、问题、理解条件及 TopK，交替运行旧扫描与新索引，记录冷建库、暖查询、各路数量和耗时。仅测本地文本召回，不测模型生成、外搜或生产向量库。候选排序变化不以 TopK 交集冒充 Recall@K。

真实工具 `backend/scripts/replay_material_handoff.py` 使用当前正常运行时与现有 DeepSeek 配置，隔离副本包含 35 篇文献和 6 个案例。固定历史目标轮沿用原历史，三轮保留样本采用前轮新回答形成后续上下文。全过程没有按题号指定命中文献或生成答案。最终批次及测量结果见本目录验证记录。

本轮结果：

- 固定 8 个查询，各策略各运行 3 次，TopK=20。暖检索中位耗时：旧扫描 **2415.956 ms**，新索引 **319.462 ms**；冷建库 35 篇 **2581.069 ms**。这是关联文献子集的本地文本检索阶段测量，不能当作整个回答或生产全库的加速比例。
- 新索引批次 `backend/var/handoff/2026-11-11-retrieval-skills-live-02`：8 条目标、10 轮全部完成执行。FIX-01 采用菜地 N₂O 专题 `P-4C4F471B773A9FF4`；KEEP-03 后续请求对象均属于前轮实际展示对象，没有恢复未展示候选。专业结论仍待人工核对。
- 真实复跑之后还有一项小修正：检索规范化保留原问句标点，仅在排除词有字符变体时处理字母数字。对涉及文献检索的 5 轮逐项离线核对，关键词和 Top5 片段一致；未将这项核对写成新的真实模型调用。实际批次与交付代码的区别记录在 `validation.json/post_replay_patch`。
- 后端完整回归 **881 passed、4 skipped、0 failed**；前端 TypeScript、相关 ESLint 及运行详情浏览器检查通过。隔离库的手动原子重建命令也已执行通过。详细结果见 `validation.json`。

逐题新旧候选答案在 [real-replay-review.md](real-replay-review.md)，可直接按原审核意见核对。机器可读摘要、各路诊断、原件范围和性能逐次数据在 [validation.json](validation.json)。更早的实验批次保留，不混入最终性能口径。

本轮默认使用 indexed + rrf，本地验证通过后仍需在实际全库和有效向量/重排环境中检查未打标召回、失效资料排除和代表性问题。标签相关主题的审核、旧标签关系治理及独立专业验证集属于后续资料工作，当前没有自动迁移。
