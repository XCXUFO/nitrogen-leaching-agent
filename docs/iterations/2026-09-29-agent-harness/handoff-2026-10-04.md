## 1. 当前结论

**聊天修复、文件规则、回答证据约束及评测工作台的基础闭环已实现并有自动验证；测评后台尚未全部做完，也不只是剩人工核验。**

目前贯通的是 `Task → Case 执行 → Run/证据 → Review → Issue → 回归复测`。
工作台仍以单页中的基础面板为主。任务批量管理、审核队列、Issue 完整状态流转、持久化重放队列、
备份恢复等仍可继续开发；跨版本趋势、配置中心与发布门槛还需要进一步定义规则。
这些工作中，一部分是当前交付收尾，一部分是将基础工作台扩展为完整后台，不能把两者都记成已完成。

已实现、自动测试通过、人工体验通过、领域专家签核是四种不同状态。历史人工结果、
AI 辅助核查和隔离测试中的合成评分都要保留各自身份，不能互相替代。

### B. 测评后台的完整管理能力

| 模块 | 已有基础 | 尚未完成的工作 |
|---|---|---|
| Task | 冻结版本、选择任务、关联执行、单任务统计；接口可收最多 50 个 Case 版本 | 专门的列表/详情、多 Case 选择、批量执行与进度、任务状态和人员分派 |
| Case/资产 | JSON 草稿修订、不可变发布版本、本地路径登记与配对记录 | 表单编辑、检索筛选、批量导入、资产上传和管理界面 |
| Run/证据 | 执行事件、Trace 字段说明、原始 JSON、比较视图 | 面向审核的证据检索、筛选和浏览；标准化导出 |
| Review | 独立开发评分、AI 辅助/专家身份与历史 | 待审核队列、任务分派、多审核人协作与分歧处理 |
| Issue | 原 Run/Review 关联、负责人字符串、复测与最近结论 | 待处理/处理中/待复测/关闭等显式状态、筛选和处理历史 |
| 回归任务 | 当前进程内异步重放，最多并发 2 项；人工步骤停止 | 持久化队列、服务重启后的恢复/续跑策略；当前重启只标记中断 |
| 运维/身份 | 文件配置 tester/developer/reviewer 三种角色，服务端权限校验 | 用户与密钥生命周期界面、数据备份恢复工具；现有评测权限不等于主聊天已有完整账号隔离 |

建议先做 **Task 列表/详情与多 Case 选择 → Case 管理 → 待审核队列 → Issue 状态流**，
每批保留旧执行、旧评分和版本约束。工作台多文件执行若要建设，需另定 Case/事件/重放规则，不能直接套主聊天规则。

### C. 待规则和指标明确后再建设

- 可比批次的跨版本趋势、按 Case 版本及审核人群过滤的指标。
- 配置编辑、校验、发布与回滚中心；当前只有运行配置快照。
- 发布门槛：先确定独立审核标准、样本、分母和阈值；当前不启用自动通过或自动发布。
- 跨文件联合计算：先定义输入输出配对、字段/时间对齐和证据表达，再实现计算。
