# 多文件会话规则 v1

日期：2026-10-04。新增需求版本；不改写第四批 UI07 的单文件历史验收结果。

1. 一次可选择或拖入多份 `.xls` / `.xlsx`，每份最多 10 MiB；会话最多保留 5 份、原始文件合计最多 40 MiB。每份单独显示上传进度、格式错误或可用状态。一份失败不取消其他成功上传。
2. 上传成功的文件进入本会话文件列表；首次成功上传时选中它。已有选中文件时，追加上传不自动切换。相同文件名可并存，以文件摘要区分。未选中文件的令牌不会随提问提交。
3. 每轮最多选一份文件作为分析目标。选择另一份文件时，前端截断提交给模型的旧文件问答历史；后端按新的 `file_id` 清除继承的指标。切换回来也需重新明确字段，不能把另一份文件的“那最小值呢”续到当前文件。
4. 发送后，该文件从“待用于提问”变为“本会话可引用”。主动移除选中文件后，当前选择为空；不自动选择列表中的其他文件。新对话清空整份列表。过期或服务重启导致当前令牌失效时，只清除该文件，其他文件不受影响。
5. 问题写出不同于选中文件的 `.xls` / `.xlsx` 文件名时，后端不计算，要求用户选对文件。多份同名文件仍以界面选中的摘要/令牌为准。一次比较两份文件、跨文件汇总和配对输出包暂不作为单文件极值执行，另定义 Case 与结果契约。
6. 文件列表不构成已核验的模型输入输出配对。每份的 SHA-256、格式、解析状态和数值来源独立保存；文件来源与配对证据由数据资产记录管理。

验收：旧 UI07 的观察保持在 `acceptance-04.md`；新增 `UI07@2` 检查两份文件、逐文件错误、选择/切换/移除、新对话及请求 `file_id`。自动测试只核对行为，人工验收结果另记。
