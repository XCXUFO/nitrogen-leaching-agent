## 本批可用行为

1. 聊天统一经过 Runtime 和五个 typed Skills：文献问答、文件检查、文件分析、追问和能力引导。
2. 带附件问一般知识走知识路径；不读取文件，失效附件也不阻塞与文件无关的问题。
3. 已明确且成功计算一个字段后，同会话/同附件下“那最小值呢？”可继承字段。
   不从历史回答推导数值；换附件、移除、过期、会话变化、话题变化或冲突后保守追问。
4. 明确作物更正进入当前任务约束；知识调用重复携带约束，防止截断历史时丢失。
   这只是上下文处理，尚不能表述为作物证据正确率已验证。
5. “1”、能力介绍和部分明确域外问题返回能力说明，不调用模型或生成引用。
6. 返回统一 Evidence、run_id 和 trace_saved；SQLite 追加记录成功/失败的执行摘要。
   文件 token 不落库，异常只保存分类码。存储失败不吞掉成功答案，也不标记保存成功。
7. 前端清空生成新会话 ID；移除、更换和过期后清除旧附件重试状态。
8. 22 条原始 Case 导入 v1，步骤与标准原文保留；F05/X01/X02 和新增引导 Case 单独放入 v2。
   六份本地测试材料均有 SHA-256 绑定；没有创建人工 Review 或填充虚构指标。

## 启动及演示

保持现有依赖和 RAG 配置；后端使用一个 worker。

```bash
# backend/
.venv/bin/python -m uvicorn src.main:app --host 127.0.0.1 --port 8000
# frontend/，另一个终端
pnpm dev
```

如已有占用端口的旧服务，需要在结束原测试后切换到新代码；本批没有停止或重启既有服务。
启动时默认将运行记录写入 `backend/var/agent/runs.sqlite3`。
评测前设置 `AGENT_BUILD_VERSION` 为实际代码/工作区快照标识；`AGENT_TRACE_DB` 可指定其他位置。

演示顺序：

1. 发送“1”：应显示能力与示例，没有引用。
2. 上传 Nbal_out.xls，问“leak_NO3 最大值及对应日序”，随后问“那最小值呢？”。
3. 保留附件，问“氮素淋失主要受哪些因素影响？”：应进入真实知识服务；未配置时显示知识服务错误。
4. 经过知识话题后直接问“那最大值呢？”：应追问字段，避免将知识话题误当成原文件指标。
5. 清空后问文件极值：要求重新上传，不承接旧指标。
