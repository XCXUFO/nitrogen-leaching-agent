## 已实施

1. **主聊天多文件。** 每会话最多 5 份、单份 10 MiB、合计 40 MiB。逐文件上传状态与错误独立显示；每轮只携带选中附件的 `file_id`。切换选中文件、移除当前文件或新对话会阻止沿用旧文件的数值上下文。点名其他文件或同时点名多份时，服务端澄清而不以选中表冒充其他表。完整行为见 [规则](multi-file-rules-2026-10-04.md)。旧 UI07 的单文件结果保留，新口径见 [UI07 v2](ui07-v2-2026-10-04.md)。
2. **Task 仪表盘。** 按一个冻结 Task 的 Case 版本及关联执行计数，分别显示通过、部分、不通过、受阻、待评分，受阻与待评分不进有效评分分母。AI 辅助与领域专家审核计数分开。严重回归仅在基线和候选都有独立开发评分、且总体由通过变不通过或证据/答案由“是”变“否”时列出；该标记仍待人核查。
3. **资产和 Case 目录。** 工作台可登记文件路径、来源和 SHA-256，记录模型输入/输出候选配对；审核人可用独立身份和证据资产核实配对。开发者可复制 Case 成草稿、保存修订、查看历史并发布更高版本。发布时再次校验结果表原件指纹；旧 Case、执行和评分保持冻结。新发布 Case 的附件可从冻结快照恢复进行回归重放。
4. **运行版本清单。** 启动时记录 Agent、Prompt、Retriever 源码、`uv.lock`、回答相关配置、本地知识索引和模型文件身份；清单摘要进入 `config_version`，完整清单进入 Run Trace、`/api/eval/config` 和 Task 快照。索引/模型目录超过 256 MiB 时仅记录路径、文件大小和修改时间的摘要，明确标为 `metadata_only_size_limit`；外部 LLM 仅记录声明模型名，不声称验证服务商权重。清单是启动时快照，不能证明运行中外部服务未改变。

## 仍需人工与后续判定

- UI07 v2 仍需人工体验验收。主聊天虽可选多文件，跨文件计算尚无定义好的字段配对与证据合同，因此点名多文件时要求澄清；工作台执行仍按当前 Case 一次处理一个附件。
- 资产“专家核实”记录能追踪审核人、证据文件和指纹，但系统无法自动判断该文件是否真正证明模型输入与输出配对。测试使用合成证据，不能替代真实材料核对。
- PR07–PR09 的专业解释、来源适用性和独立领域专家结论仍待审核；本轮自动测试未将其判通过。当前 Task 仪表盘也不能当作专业正确率。
- 自动发布门槛暂未启用。需要先确定可比 Case 批次、人工审核标准及足够多的独立复测，再定义 Release Gate 阈值。
