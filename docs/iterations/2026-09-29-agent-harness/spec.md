## 迁移路径

```text
POST /api/chat（兼容原请求和响应字段）
  → AgentRuntime
  → StateStore + Context（附件显式传入、作物约束、必要历史）
  → RouteDecision（当前为保守规则；不宣称已有模型语义分类器）
  → SkillRegistry：knowledge_search / file_inspector / whcns_analyzer
                   clarification / capability_guidance
  → 旧 ChatResponse + 统一 Evidence
  → SQLite RunTrace
```

第二批实现有限语法 COMPOSED，例如“硝态氮最大值是多少，为什么可能这么高？”。
先检查完整请求能否支持，再分别执行文件统计和一次机理检索/生成。额外时间窗、
多指标或其他无法识别的要求仍追问，不删去要求后只答局部问题。复杂语义分类尚未实现。

上传返回 pending，仅说明格式可读；首次分析再校验字段、单位、数值及日序。
待分析原件在内存保存，总量 64 MiB、最多 32 份、30 分钟有效期；访问时清理过期项。
每次临时解析文件结束即删除，业务校验后释放内存原件并缓存摘要或诊断。

## 状态和证据规则

- 客户端每次显式传入当前 `file_id`。省略意味着本次没有当前附件，不能从历史找旧文件。
- 仅上一项工具为成功文件计算、同一会话、同一有效附件、追问符合有限省略语法时继承指标。
- 新会话、附件更换或移除、过期、冲突/不支持的文件请求、转入其他话题后不得盲目继承。
- “只讨论玉米”等明确约束进入 State；组合机理检索按作物关键词筛选片段，
  尚不能替代人工判断试验背景和适用性。普通知识链路仍使用原有上下文策略。
- 单进程最多 256 个任务状态；同会话同时发送返回 409，其他会话可继续；过期状态访问时清理。
- `Evidence.status=computed` 表示程序计算结果，`retrieved` 只表示检索片段，
  不表示人工确认支持结论。组合回答已有逐结论关联和摘录原文匹配检查，全文/页码增强待后续。
  摘录核对仅规范空白及中文断行，展示内容取自原文；机理链路过滤疑似文献目录。
- 组合回答通过 sections 区分文件观察、文献机理和局限。机理生成不接收文件数值，
  不把一般机制认定为本次极值原因。任一步失败保留成功部分并返回 partial；
  Trace 的 HTTP 执行状态与 outcome 分开保存，不能以 HTTP 200 统计全部成功。
- 文件 token 和原始异常详情不进入 Trace；会话和附件关联标识使用摘要。
  Trace 保存用户问题、答案、结构化状态、实际工具、证据、错误码、耗时和配置版本，
  不保存原始提示或思维链。
- Trace 写入失败时成功答案保留，但 `trace_saved=false`，不能当作已保存评测样本。
- 状态和附件仍非持久化，单后端 worker；刷新不恢复会话，重启不恢复附件。
  SQLite 持久化运行记录不等于会话恢复或用户鉴权。

## 评测存储方案

- SQLite 单实例起步；已落地 `agent_runs`、`eval_cases`、`eval_executions`、
  `eval_events`、`eval_reviews`、`eval_regressions` 和 `eval_replays`。
- `eval_cases` 以 `(case_id, version)` 唯一且不覆盖，Review 独立主键且追加保存；
  多轮执行关联有序 Run 与 Event 列表，Review 冻结该版本用例快照及全部 Run/事件序号。
  上传检查用例可以按真实上传事件评分，不虚构聊天 Run。
- 身份通过服务端密钥摘要配置验证，Tester 仅访问自己的执行，Developer 可看结构化 Trace。
  `/evaluation` 工作台已实现；后台默认禁用，身份配置错误不降级匿名访问。
- 评分提交后冻结该次执行，复测新建执行；原始专业审核状态保持 pending。
- 四层指标分别给出有效样本数；blocked 单列，n.a. 不入该层分母，partial 与 yes 分开。
- `manual_cases.v1.json` 保留旧步骤/标准；`harness_cases.v2.json` 定义第一批升级行为，
  `harness_cases.v3.json` 定义分阶段上传与组合问答，
  附件数值断言通过 fixtures 绑定文件 SHA-256。O02 的超大副本需执行时另行准备。
- 所有自动结果、真实服务验证、人工引用核查、受阻和未执行项分别报告。

工作台操作见 [使用说明](evaluation-guide.md)，历史交付见第三、第四批实施记录。
