# 账户历史会话

六个现有账户沿用原有身份与密码。前台普通问答按经过认证的账户保存到现有
`AGENT_TRACE_DB`，通过 `GET /api/chat/history?limit=30&offset=0` 分页读取。

- 服务端受理时保存问题，运行完成时在同一事务中保存完整回答、引用、计算结果或失败状态。
- 历史表与运行恢复窗口独立，过期恢复记录清理后仍可阅读历史并发送新问题。
- 重试不重复问题，重新回答按原轮次展示最新结果；未完成请求可在新窗口找回。
- 登录账户取消十个临时会话限制，提供“加载更早的对话”；游客继续使用原有临时会话逻辑。
- 账户退出和切换时卸载原会话视图，后端始终按认证身份查询，不接受客户端指定历史所有者。
- 文件上传仍是临时能力，历史保存文件名与已生成的回答依据；过期原件需要重新上传。

现有数据迁移前已备份至
`backend/var/service/runs-before-account-history-20261018T033330Z.sqlite3`。
共接入 16 个会话、26 个逻辑轮次（29 次运行，包括重跑）：开发者账户 15 个会话，
`cau_tester2` 一个会话。其他账户当前没有可归属的旧会话。
不将游客记录、测试记录或评测执行分配给账户。

旧记录缺少原始浏览器会话标识时，生成新的历史会话标识用于阅读与后续提问；
只有原运行仍在恢复窗口内、且原会话标识匹配时，才提供原运行恢复和重新回答。
没有完整回答快照的早期记录从已保存正文与证据重建展示，缺失的 token 用量记为零。
