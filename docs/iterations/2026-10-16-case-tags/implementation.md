# 案例与措施接入共享标签

- 一级列表新增分类标签列与筛选器，支持父级包含后代、维度内或/维度间且、未打标，以及原有标题和开放状态筛选。
- 二级详情展示标签完整路径与停用状态；新增/编辑复用文献的 TagCascader，选择后随案例保存，保留原有 revision 并发冲突保护。
- 复用标签管理的维度与标签 ID，不复制分类树。案例标签选填，不套用文献“登记必填”；详情页支持人工选择已有标签；总览批量 AI 打标见 [批量打标](../2026-10-16-case-batch-tagging/implementation.md)。
- 标签管理展示案例直接关联数与“关联案例”跳转；标签删除、维度改单选、标签移动均检查案例关联。停用标签允许保留/移除，禁止新增关联。
- CaseStore 启动时增量增加 tag_ids JSON 列，既有数据默认为空数组，正文、开放状态和 revision 不变。旧客户端 PUT 未传 tag_ids 时保留已有标签。
- 案例写入标签与标签结构修改共用文献库写事务锁，先锁分类库再访问案例库，避免跨进程的删除/关联校验竞态；案例内容和标签在案例数据库同一事务保存。

接口：GET /api/case-library/taxonomy；案例创建/更新增加 tag_ids；列表增加 tags 与 untagged 筛选，列表及详情返回 tag_ids。共享 GET /api/literature/taxonomy 增加标签 case_count。

验证：

- 后端案例标签、案例库/富文本、文献接口/标签/批处理回归：88 passed。
- 浏览器案例与文献效率用例：14 项最终全部通过（首轮 13 passed、1 项在首次 Next 编译时 page.goto 超时；编译完成后该项单独重跑通过）。覆盖列表/详情展示、修改保存及刷新、停用标签提示、层级与未打标筛选，并回归案例原有 AI 草稿、冲突保护、富文本和问答。
- TypeScript、修改文件 ESLint、git diff --check 通过。
- 使用隔离数据库和模拟 API 的独立前端测试服务；未修改现有案例记录或生产分类树，未部署。旧数据库在后端启动时自动迁移。
