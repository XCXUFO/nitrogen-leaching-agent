# PRD A：Skill 能力与回答策略改造

版本：1.0；日期：2026-11-09；状态：可进入本地开发。与 PRD B 共用候选配置、运行记录和验收数据。现状依据见 01，真实反馈见 04。

## A0. 背景、目标与范围

真实用户会只输入一个词，不熟悉农业术语，也不知道平台内部能力。现在几个不同问题统一进入 knowledge_search：WHCNS 短语只被追问，光合作用被专题论文片段替代，新手应用场景被整体排除。菜地 N2O 问题还可能存在检索覆盖与资料充分性判断问题，不能把所有缺陷归结为表达。

本次目标：先理解可合理确定的意图，直接回答可回答部分，按需取得真实证据，保留专业条件与能力边界。不同任务可独立优化；维护者能知道一次修改影响什么、一次运行实际用了什么。

首期必须交付：概念解释、相关领域联网取证、案例 Skill 合并、任务 Prompt 范围、可验证的版本传递、能力说明同步、历史兼容。轻量 zero/few 对照在核心链路可用后完成。

不在首期：独立实验中心、自动专业裁判、流量 A/B、任意通用聊天平台、自动制定田块施肥处方、增加 WHCNS 模拟运行能力。

## A1. 能力组织

下列 ID 是建议；已有合适命名和实现可沿用，需留下对应关系。

| 能力 | 类型 | 主要职责 | Prompt 归属 |
|---|---|---|---|
| concept_explanation | 业务 Skill，新增 | 概念、含义、入门、简单区别；先解释再引导 | 概念任务 Prompt |
| knowledge_search | 业务 Skill，保留重构 | 专业规律、机理、文献证据与条件比较 | 专业问答任务 Prompt |
| case_assistant | 业务 Skill，合并 | 查案例、解释案例或粘贴材料、比较、核对效果证据 | 一个案例任务 Prompt，按模式补充必要规则 |
| local_retrieval | 共享取证能力 | 本地文献、案例及会话材料查询、筛选、证据返回 | 有模型改写/筛选时才设相应策略 Prompt |
| web_search | 共享取证能力，新增 | 相关领域外部搜索、正文获取和来源记录 | 检索策略；最终解释仍归业务 Skill |
| file_inspector / whcns_analyzer | 确定性工具，保留 | 附件有效性、已支持输出表的计算和原件位置 | 不增加模型 Prompt |
| clarification / capability_guidance | 程序文案，保留 | 必要缺参追问、实际能力和使用示例 | 改程序/模板；不能只改表达 Prompt |

“RAG 的 Prompt”落实为专业问答任务策略及必要的检索策略。RAG 是取证方式，不作为与概念、案例互斥的用户意图。若现有注册系统要求联网也登记为 Skill，可以登记，但需标明它是可被业务 Skill 调用的取证能力。

共通编排承担任务判断、工具调用、上下文传递、混合请求整合；不新增一个需要日常维护的总控后台。

## A2. 路由与意图理解要求

| 输入类型与例子 | 目标处理 | 不能出现的行为 |
|---|---|---|
| “WHCNS模型”“氮素淋失” | 默认解释概念；不依赖问号或“是什么” | 仅因为问题短就要求写完整句 |
| “菜地 N2O 排放规律” | 按规律问题取证、概括可支持部分 | 只给 N2O 定义，或一律转概念 Skill |
| “解释下光合作用” | 相关基础知识；本地不足时补充联网 | 用专题论文零散提及代替基础解释 |
| “有哪些水氮管理案例” | 案例检索模式 | 虚构案例或把案例用量当用户处方 |
| “上面案例为什么这样做” | 承接已展示案例并解释 | 清空案例上下文、无提示替换案例 |
| “你能做什么” | 实际能力引导 | 承诺只注册但不可用的功能 |
| “最大值是多少，为什么可能这么高” | 保留计算和机理两个子任务 | 只做其中一项；以一般文献认定具体峰值成因 |
| 缺少实际执行必需的文件或字段 | 先完成可做部分，再准确请求必要信息 | 反复问已在上下文确认的信息 |

A2.1 判断基于任务语义、当前历史、已确认对象及文件状态；不只按关键词硬编码八条测试输入。允许合理改写，不能补造用户未提供的地区、作物、时间、参数。

A2.2 对可直接说明的基础概念，第一段给“是什么、主要涉及什么/有什么用途”。随后按问题需要补充，不强制每次固定长模板。后续方向可用简短选择引导，不能成为先回答的条件。

A2.3 对“模型”这类新手指代，先结合上下文说明可能指本问答助手或农业模拟模型，回答已有依据的实际用途；确需区分时再问一个简短问题。不能擅自认定一定指 WHCNS，也不能把“工作应用场景”整体等同于预测个人就业结果。FIX-05 的两条历史必须带入。

A2.4 范围包括农业、水氮、土壤、作物及相关基础生物知识；职业语境中的平台使用场景也可解释。个人何时考试/求职成功等不能预测，简要说明后可引导到真实支持的任务。无关请求不因新增联网而一律外搜。

A2.5 前端和管理端保留旧路由展示兼容；评测以行为和证据为核心，不能把旧 KNOWLEDGE/COMPOSED 字符串当作所有新实现的唯一正确路径。

## A3. 概念与专业回答

A3.1 概念回答的最低结构是直接说明、必要背景、按需补充用途或例子；适用条件与不确定性放在相关结论附近。不能为了减少前置条件而删除重要事实限制。

A3.2 只有可能改变回答实质或实际执行的歧义才优先澄清。无需田块条件即可介绍的概念，不要求先填写作物、土壤和管理参数。

A3.3 专业问答先列可支持的规律或结论，再列对应条件和真实缺口。检索未命中、材料不充分与知识不存在须区别记录；不能把一次未命中写成“没有任何研究”。

A3.4 FIX-01 应检查首轮查询与第二轮命中文献的差异。第二轮出现的 P-4C4F471B773A9FF4 是候选材料，核对正文后才认定能支持什么。不得把第二轮的未审核数字直接变成第一轮黄金答案。

A3.5 术语解释可比专业综述简短。KEEP-02 保留“短语也能先回答、条件不乱外推”的质量，不要求复制旧答案长度或所有段落。

## A4. 本地与联网取证

### A4.1 触发和选择

1. 优先复用当前会话已取得且相关的有效材料，以及本地可用资料。
2. 当相关基础知识在本地缺少充分支持，或专业问题需要补充资料时，可调用外部检索；用户明确要求联网时应实际使用可用能力。
3. 本地已有充分支持，不强制联网。明确只使用上传材料/本地资料时遵守来源范围。
4. 没有能力、依赖不可用、超时、无结果、获取失败、正文不足、来源冲突分别记录；回答保留可支持部分。

### A4.2 最小证据契约

复用现有来源模型，必要时补齐以下逻辑信息，不强制新表：来源类型、本地对象 ID 或真实 URL、题名/机构、片段或正文位置、支持内容、获取时间、资料版本或内容摘要值、获取状态。外部网页不能伪装成本地论文；用户材料不能伪装成已发表研究。

最终结论应能关联实际读取的材料。正文获取成功才可声称读过正文；标题、目录和参考文献列表不能直接证明机制。仅搜索摘要可用时，明确证据级别，只使用它实际支持的内容。

外部基础解释优先教材、大学、科研、政府或可信专业机构资料；按正文支持判断，不只按域名评分。出现冲突或场景差异时保留条件，不拼成一个确定结论。

### A4.3 对外呈现

回答中给可辨认的来源标题和可访问链接，沿用现有引用样式；用户不需要看内部 chunk_id 或调试字段。本地文献继续使用现有引用入口。开发者详情记录检索查询、来源、失败原因和结论对应材料，便于定位。

不得输出编造 URL、虚构检索过程或检索耗时。来源内容作为数据，不能改变平台规则、权限或工具调用范围。使用现有 HTTP/检索库的网络访问约束，不允许网页诱导访问本机/内网敏感地址。

### A4.4 预算与失败

首期采用服务端统一默认预算，不增加普通用户配置页：建议最多 2 轮检索、读取 5 个正文页面、外部阶段总预算 30 秒；本地实现可按服务能力调整默认值，并在配置和测试说明写明。禁止无限重试，单次失败保留原因，已有可靠材料可形成部分回答。

本 PRD 不绑定某个供应商。提供商配置与密钥沿用现有服务端配置机制，日志不记录密钥。没有外部服务配置时，界面准确显示未就绪，本地可测失败回退；不能把模拟搜索当作线上已接入。

## A5. 案例 Skill 合并

A5.1 对外一个案例能力，内部支持 search、explain、compare、evidence 四种模式；可沿用原函数而只统一入口和上下文。不是要求新建四套页面或四套独立 Prompt 管理器。

A5.2 必须保留原 case_explanation 的表格、粘贴文本、指定材料解释与比较。材料不是库内案例时，也能准确标记来源而执行解释；不得只合并菜单后丢失能力。

A5.3 上下文至少能区分已检索案例、实际展示案例、用户指定案例以及资料来源。后续“上面”默认承接实际展示对象；用户更换对象时明确更新，不能串会话。

A5.4 叙述做法、解释可能理由、证明效果分别处理。缺少对照、产量、节水节肥或氮损失数据时，不推断有效性和最优性；推荐量是材料记录，不能直接作为用户田块用量。

A5.5 KEEP-01 的单轮会话与 KEEP-03 三轮会话分别保留。后者使用本次第一轮的新回答继续第二轮，再用新上下文继续第三轮；旧答案只能作对照，不能注入替代本次实际回答。

A5.6 历史 run 保留 case_reference/case_explanation 原标识。新运行记录实际新 Skill 和模式。旧 ID 通过兼容适配执行对应模式；兼容层不能改写历史记录。旧用例绑定迁移说明，新的用例版本采用行为验收。

## A6. Prompt 范围、版本与执行

### A6.1 分层

共通事实/来源/数字/权限约束 → Skill 任务规则 → 必要模式规则 → 可选示例 → 运行问题、历史、资料和工具结果。默认表达偏好是其中可调整的一层，不能覆盖专业约束或程序工具结果。平台已有“原版解释 v1、增强解释 v2”是表达偏好，不把它们误当作所有 Skill 的任务 Prompt。

概念、专业问答、案例各有可独立修改的任务规则。程序文案与确定性计算没有模型 Prompt 编辑入口；页面明确显示改动归属。

### A6.2 复用现有编辑页

在现有 Prompt 同题对照和版本机制增加“适用 Skill / 模式 / 配置范围”，默认由原 run 带入。保留保存、左右对照、保存结果、切换生效分开。旧全局表达版本可以继续查看和回退。

每次保存产生可引用版本；旧运行引用的内容不可被编辑覆盖。预览显示最终组合后的内容及各层版本，可折叠高级信息。用现有变量注入方式，缺少必需变量在运行前提示，不能默默生成空 Prompt。

### A6.3 候选必须真正进入调用

候选配置可以先是轻量引用清单，不必新建配置中心；至少关联 Skill/任务 Prompt、共通表达、示例、模型参数及有影响的检索/代码版本。服务端执行入口解析明确候选，后台试验不能靠临时切换线上全局版本实现。

运行结果记录实际解析版本，不只记录用户提交的候选名。候选修改后旧结果仍指旧版本；新的内容需要新验证。代码无法在一进程切换时，使用独立本地/预发布构建测对应提交，并记录提交号，不能宣称仅靠 Prompt 选择已切换代码。

### A6.4 启用与回退

验证、启用与部署分开；启用沿用已有正式操作，不因“保存/生成对照”自动切换。全局配置切换记录新旧版本。代码、Skill 或数据依赖不兼容时，不提供看似可用的单 Prompt 回退；记录需整体恢复的版本组合。上线范围以实际验证版本为准。

## A7. 能力说明

A7.1 capability_guidance 继续采用程序文案或现有模板；以当前已启用、依赖就绪且用户有权使用的能力为依据。注册、依赖就绪、实际开放三者分开。

A7.2 输出简短功能概览和 2—3 条真实可执行例子；按当前状态准确描述联网、概念、案例、文件功能。暂未开放的能力不宣传为已可用。

A7.3 当前 whcns_analyzer 页面声明仍为单字段整表极值。FIX-04 认为描述过时，但没有独立证据证明已开放更多分析能力；本地先核对代码和配置，再更新文案。不能凭“过时”意见增加支持范围，更不能承诺执行模拟或自动施肥处方。

## A8. zero-shot / few-shot 最小实现

复用现有同题对照页。一侧任务规则不含示范问答，另一侧保持相同规则并加少量确认合格示例。资料和工具仍可使用；zero-shot 不等于关闭检索。

示例先随 Prompt 版本保存，注明来源用例与修订；不新增示例中心。两侧实际模型、检索或代码不同，标记为多因素比较，不能把结果只归因于示例。

本批 8 条已用于诊断和调试，属于开发/回归集。用于示例的原题及近似改写不能算独立泛化测试。需修改的旧答案不能直接作为合格示范；通过答案也应按实际专业核验范围选用。少量结果逐题判断，不预设 few-shot 更好，不计算全平台准确率。

## A9. 验收与依赖

| 编号 | 验收 |
|---|---|
| A-AC01 | FIX-02/KEEP-02 的名词输入能先解释；规则适用于合理改写，不只原词 |
| A-AC02 | FIX-03 在本地材料不足时真实取得外部证据并直接解释；离线模拟仅验证流程 |
| A-AC03 | FIX-01 核对检索和资料充分性；有支持先答，无支持部分不编造 |
| A-AC04 | FIX-05 保留两条历史，先给可理解用途，不把所有工作场景拒绝 |
| A-AC05 | KEEP-01 和 KEEP-03 不退步；表格、粘贴材料和比较能力保留 |
| A-AC06 | 历史 Skill ID 可追溯，旧入口兼容，新运行记录实际模式 |
| A-AC07 | 候选在真实调用中生效，保存/试验不误切全局；版本可查 |
| A-AC08 | capability_guidance 对齐实际开放能力；正常入口得到更新说明 |
| A-AC09 | 外部检索无结果、超时、正文不足均有准确回退，不伪造来源 |
| A-AC10 | zero/few 对照保留配置、示例与逐题结果，不自动上线 |

行为、程序、来源链和版本关联可先本地验收；新增专业结论与具体文献支持需真实材料核对。FIX-01/02/03 没有本包新编且已专家确认的标准答案，不能用未经确认的文字当硬编码答案。
