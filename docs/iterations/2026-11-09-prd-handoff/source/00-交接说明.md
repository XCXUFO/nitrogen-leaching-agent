# 氮素淋失问答平台：本地开发交接包 v1.0

交接日期：2026-11-09。面向另一台无法读取线上服务器数据的开发主机。产品负责人主要独立维护，当前用户和已审核样本均少。

## 1. 本次开发目标

提升真实问题的回答质量，并让维护者完成两件日常工作：

1. 从运行记录发现问题，修改对应 Skill、Prompt、程序文案或取证逻辑，直接复测并确认改进。
2. 大版本发布前，一键运行常用历史用例，看到修复、退步、已知问题和待核验项，满足预期后沿用现有发布方式上线。

新增概念解释、相关领域联网取证，合并案例能力，按任务封装 Prompt；复用现有用例、执行、基线和同题对照能力。首期不建设多个管理中心。

## 3. 证据与设计的区分

- **线上事实**：2026-11-09 通过已登录页面读到的状态，以及 2026-10-19 至 10-31 的历史会话。它不是服务器全量数据库备份。
- **原审核意见**：保留原文、目标轮次和原审核结论。原回答即便已通过，也不自动等于每个专业细节均经独立专家核验。
- **产品要求**：本包两份 PRD 和验收清单规定的目标行为，不代表线上已经具备。
- **实现建议**：逻辑字段、建议 Skill ID 和执行契约，用于帮助落地；不是已确认的数据库表名或现有 API。
- **待核实**：需要在本地主仓库查代码、迁移文件或执行最小验证的事项。不能以猜测填成线上事实。

## 4. 本地开发可直接开始的范围

本包已经包含问题复现所需的原问题、目标轮次、必要固定历史、审核意见和保持标准。可先在本地建立隔离数据，完成问题展示、候选版本传递、执行结果关联、报告汇总、状态流转和 Skill 路由测试。

本包未包含完整生产知识库、全部案例正文、模型密钥、线上数据库、WHCNS 原始附件和服务器部署信息。没有这些材料时，可以使用明确标注的本地测试数据验证流程；不能把测试数据或模拟调用的通过结论当作真实检索、专业内容或生产发布验收通过。缺失只阻塞相应验证项，不要求所有开发停下。

## 5. 交接后的第一项工作

在本地实际代码库中确认已有数据与执行接口，对照 01 的复用清单标出“直接复用 / 小改 / 确实缺失”。随后按 05 的顺序实现。不要为了匹配本文建议命名，先整体重写已经可用的模块。

## 6. 当前执行状态

本轮只读取线上页面、整理资料并生成本地交接文件。未改线上 Skill、Prompt、审核状态、资料或发布版本；未启动模型复测和自动回归。文档中的新版本结果均为“未运行”，专业修正版参考答案仍需依据真实材料确认。
