## 第四个开发增量：案例能力合并与对象承接

统一注册能力为 `case_assistant`，内部四模式 `search / explain / compare / evidence`。查找并解释或比较现在由同一次取材和模型调用处理。`case_reference`、`case_explanation` 保留兼容调用和详情入口，默认能力目录只展示一次案例能力；既有 run 的旧标识与内容保持原样，新运行记录统一能力及实际模式。原案例表达偏好、任务 Prompt、案例库与引用契约继续复用。

请求新增可选 `case_mode`，与旧 `case_skill` 同时指定时返回 422，旧字段仍可用。模型输入包含实际模式、来源类型、用户材料及本次新回答形成的历史。模型输出仍使用受校验的 answer、used_case_ids、outcome，不能引用未提供的 ID。最终返回前继续核对案例开放状态与内容版本。

案例状态区分用户指定对象、检索候选和实际展示对象。后续“上面案例”“案例中的效果”等优先承接实际展示范围；序号和前后者基于展示顺序解析。回答缩小到一个对象后，不再拿较早的两个对象填补“这两者”。关闭、删除或更新的对象按当前记录复查，不转而采用库内其他对象；无法确定对象时要求指定，不从历史回答猜造材料。

文字和表格仍可独立解释与比较，不要求入库或依赖案例库。用户粘贴内容及后续追问标记为 user_text，保留空白、表头、单位、单次与合计等既有约束；案例做法不作为效果证据，无对照或效果数据不推导有效或更优。最近对话仅辅助承接，库内事实仍需本次重新读取。

前台案例验证改为一个任务模式选择器，切换模式保留对话，只有“新对话”重置。回答卡显示实际模式，并兼容旧记录的两种 Skill 名称。统一能力详情可调整既有表达配置；旧详情带统一入口链接。会话 MQ 明细与交接复测结果增加案例对象/模式信息，原历史缺失字段不补造。

## 第五个开发增量：可选外搜、正文引用与充分性

新增共享取证模块 `backend/src/retrieval/web.py` 和问答装配层 `backend/src/agent/web_evidence.py`。首个适配器为 SearXNG JSON 搜索，协议参考 [SearXNG 官方 Search API](https://docs.searxng.org/dev/search_api.html)。沿用已安装的 HTTPX，不增加依赖。外搜默认关闭，无配置不发送网络请求，能力页准确显示未配置；普通用户没有新的配置页面。

配置写在 `.env.example`：`WEB_SEARCH_ENABLED`、`WEB_SEARCH_URL`（完整搜索 endpoint，例如公开部署实例的 `/search`）、`WEB_SEARCH_TIMEOUT_S`、`WEB_SEARCH_MAX_QUERIES`、`WEB_SEARCH_MAX_PAGES`、`WEB_PAGE_MAX_BYTES`。实例须允许 `format=json`；当前适配器不支持需要额外认证头的供应商。配置搜索 URL 不自动证明提供商可用，启动后仍需真实连接验证。

默认最多两轮查询、五个页面、合计网络阶段 30 秒；每次 DNS/HTTP/重定向/读取最多 6 秒，每页原始响应最多 1 MB。网络总时限包含并发等待，生成回答仍沿用既有问答超时和模型设置。网页仅抽取可见文本，不执行脚本，不支持 PDF、浏览器渲染或压缩响应正文。每个重定向重新验证公网地址，只允许 HTTP(S) 的 80/443 端口；拒绝凭证 URL、私网/回环/链路本地及混合 DNS 结果。实际连接固定到已验证 IP，同时保留原 Host 与 TLS SNI，避免二次 DNS 解析转向内网。客户端不继承环境代理。

已接入概念与专业问答的 answer 路径：优先保留本地可用回答；用户明确要求联网时调用已配置能力；本地无材料或不足时可补充外搜。有本地引用时，可用模型作一次充分性路由提示，该提示不充当专业正确判定。明确只用本地/上传材料时不外搜，后续明确解除限制时服从新要求；无关问题不因为出现“联网”就发送外部请求。原本地检索失败与外搜失败分开记录。

失败区分未配置、提供商不可用、总/单次超时、空结果、正文不足/读取失败和生成/摘录核对失败。搜索摘要保存在 Trace 作线索，不能冒充已读正文，也不进入最终正文引用。外部失败保留本地内容，概念可提供明确标记的一般知识；部分页面超时保留已读依据并标记部分完成。空检索进度为 no_result，不显示已取得证据。模型返回格式不合格时不会无限重试。

回答引用只使用实际读取的来源：逐条校验 claims 原句出现在回答中、引号摘录是对应页面的连续原文、编号存在且有对应 claim。最终链接由程序从真实来源生成，模型不能生成任意 URL。每个网页来源保存标题、实际 URL、机构/域名、获取时间、页面字节摘要、抽取位置、获取状态和证据级别；来源有冲突时保留条件与各自出处。机械摘录校验不证明专业结论正确，仍需按实际内容核验。失败生成的已知 token 用量也保留。

引用契约新增 web 来源类型，沿用现有编号、Evidence 和界面。网页引用展示摘录与打开来源链接；本地文献的预览/下载保持原有行为。Trace 的 `web_retrieval` 展示本地充分性、查询、逐页状态、内容版本与结论对应摘录。构建指纹包含新增检索代码及非秘密配置，搜索 endpoint 只记录摘要而不将原始连接字符串写入 manifest。

当前范围：概念和专业 answer 路径支持补充外部证据。严格文件数值+机理组合保留原本地契约，尚未接入网页机理，不作为本轮外搜通过项。案例助手仍按开放案例与用户材料取证。当前会话已取得网页材料的复用缓存及更深入的专业覆盖判定尚未交付。不能把本增量称为全部 A4 或发布验收完成。

## 第六个开发增量：DeepSeek Search / Fetch

已按 [DeepSeek 官方 Search & Fetch 文档](https://api-docs.deepseek.com/guides/search/) 新增 `backend/src/retrieval/deepseek.py`。通过现有 `DEEPSEEK_API_KEY` 鉴权，固定调用官方 `POST /v1/tools/search` 与 `POST /v1/tools/fetch`。不修改问答模型或复用自定义 RAG 转发地址，避免将凭证发送到未知搜索 endpoint。

配置增加 `WEB_SEARCH_PROVIDER=deepseek|searxng`。默认值保持 searxng 以兼容既有配置；`.env.example` 给出 DeepSeek 示例。DeepSeek 模式不需要 WEB_SEARCH_URL，继续复用现有 Key 与显式代理配置。空代理按 None 处理，与原 RAG 客户端一致。工厂 `create_web_search` 已接入实际启动流程，预算、引用、充分性、失败回退与 Trace 仍复用现有链路。

DeepSeek 查询最长 128 个 Unicode 字符，含第二轮查询提示也不超限。Search 仅取得发现信息（need_content=false），正文必须实际调用 Fetch 才会成为引用，摘要与正文严格区分。Fetch 的 Markdown 保存内容摘要、来源与获取方式；API 未提供最终跳转 URL，不宣称独立核实了最终地址。来源链接使用实际请求的 URL。

DeepSeek Fetch 在远端解析与读取页面，因此不使用本机代理/TUN 的假 IP DNS 来验证目标站点。应用本地只连接固定官方 API；仍在本地拒绝私网字面 IP、回环、链路本地、非法协议、凭证 URL、内部/本地域名和异常数字 IP 写法。目标域名解析、重定向及远端地址安全策略由 DeepSeek Fetch 处理（拒绝时返回 403）。SearXNG 的直连抓取仍保留原有 DNS 固定策略。官方 API 的鉴权请求不跟随重定向。

明确区分 401 鉴权、402 余额、429 限流、无正文、超时与格式错误。鉴权/余额/限流失败不循环重试，也不继续对后续页面重复调用。提供商错误正文与 Authorization 不进入报告。默认测试禁用真实外搜；显式 live 检查通过独立 CLI 执行。

真实验证：复用本地已有官方 Key，Search 与 Fetch 均返回 HTTP 200，取得中科院植物研究所页面《那些年我们一起追过的（死记硬背过的）光合作用》。只验证连接、权限、结果解析与正文取得，没有运行专业回答生成或新增专业通过结论。初次失败由本地空代理造成，请求尚未发送；首次 Search 后的本地假 IP 地址拦截也未调用 Fetch。最终分别完成一次成功 Search 与一次成功 Fetch。

验证工具为 `backend/scripts/check_deepseek_search.py`，每次最多一次 Search 和一次 Fetch；`--fetch-url` 可只读取已发现页面。报告位于忽略目录 `backend/var/handoff/deepseek-provider-check.json`，原始结构诊断与正文读取报告分别保存，不包含 Key。

本地 `backend/.env` 已设置 WEB_SEARCH_PROVIDER=deepseek、WEB_SEARCH_ENABLED=true，未修改 Key、RAG 或问答模型配置。新启动或重启后端时生效；没有部署线上或重启未知运行中的服务。回退可将 WEB_SEARCH_ENABLED=false，或选择 searxng 并配置原 WEB_SEARCH_URL。
