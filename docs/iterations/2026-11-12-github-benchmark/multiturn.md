# 多轮对话测试（2026-11-12）

在单轮批次 52 轮结束后开始，使用同一现有服务及 `cau_tester3` 测试账号。初始 8 组、29 轮；看到文件自然语言问题反复澄清后，增加一组原始列名对照，共 9 组、32 轮。所有旧记录保留，没有修改 Agent 提示词、路由或模型。

| 组 | 轮数 | 检查目标 |
| --- | ---: | --- |
| MT-01 | 4 | 记住作物、土壤、总施氮量和次数；180 改成 150 后更新每次用量及汇总 |
| MT-02 | 4 | 区分 A/B 两地块；只更改 A 时不得改变 B |

| MT-05 | 4 | 新会话不能读取 MT-04 文件；随后依据当前文本数据计算并处理更正 |

MT-07/08 来自 [MT-Bench-101 作者仓库](https://github.com/mtbench101/mt-bench-101)的固定提交 `bc18b3e2c18c99164e11528f1a79c92083db5953`，论文发表于 [ACL 2024](https://aclanthology.org/2024.acl-long.401/)。原始用户问题不改写，题库的参考 bot 仅留在本地，不能作为本 Agent 的上一轮回答。其他组是本产品自编的诊断场景，不声明为官方基准成绩。

实际历史按轮累积，使用本 Agent 的真实回答。若前轮失败，只传真实的用户问题，不伪造 assistant 答案；这类后续轮只能评估失败恢复，不能冒称已经验证成功对话的记忆。每个组使用独立会话，同一组沿用相同会话。MT-05 在 MT-04 结束后启动，且不提供其历史或附件。

文件与文档只上传到本次测试会话，不进入文献、案例或星标库。结果表来自已有 `data/demo/Nbal_out.xls`，原件不修改；最大／最小参考由 `xlrd` 独立读取原始单元格计算，保存在本地 manifest。合成摘要明确标注非真实观测，且未提供淋失量、产量变化或统计检验。

## 已定位的问题

- MT-04 成功读取 352 行表格，但前三轮连续要求明确字段，没有计算用户已经指定的硝态氮淋失极值；第四轮正确要求上传另一份新文件。
- MT-05 对跨会话文件和默认值请求没有编造结果，但给出三条明确文本观测后仍要求上传表格，未完成对文本数据的比较。
- MT-06 的文本附件被送入表格解析，在 `backend/src/agent/file_chat.py:64` 访问不存在的 `report["columns"]`，触发 `internal_error`；日志与对应 Run 均有证据。
- MT-09 原始列名对照三轮均计算正确：最大值 `3.659263849258423 kg N ha-1`，模型日序 283，`Nbal_out!C284`；最小值 0，首次模型日序 2，`Nbal_out!C3`，共有 191 条并列；第三轮正确切回同一最大值。与独立读取的原始单元格一致，证明成功计算后这类限定指标追问可以工作。
- 专业记录与若干公开对话首轮仍有检索超时，因此成功首轮之后的上下文保持能力存在覆盖不足；不能用这些失败或追问宣称多轮记忆通过。

最终逐组与逐轮初评以本地 `report.md`、`per-question.csv` 为准；未代用户提交后台人工审核。
