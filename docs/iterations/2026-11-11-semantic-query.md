# 统一问题理解与 Query 改写

## 问题与处理

原入口主要依赖规则解析、同义词归一化与字面重合。单个问题检索还没有消费任务里的 `retrieval_query`，星标候选只相近就会继续检索。“措施”也可能被提前归类为案例工作，从而跳过星标匹配。

现在生产入口在规则提取明确条件后，先调用模型理解每个问题的实际意图、资料来源与上下文指代，生成独立问题和检索 Query。第一次模型调用不提供旧规则猜测的意图、来源，也不提供星标答案，避免这些内容引导理解结果。

完成理解和改写后，再召回星标候选并单独调用模型核对答案覆盖范围。当前小型库整库送审；超过 48 条时通过已有 BGE 向量召回候选，不设字面重合门槛。数值、作物、明确条件与否定约束仍由程序保护；空答案、待审核和冲突状态仍不能由模型批准复用。

完整覆盖时复用维护答案，跳过文献和联网检索；部分覆盖时保留参考答案，继续处理缺口。完整答案优先于相关的局部答案，局部内容不同不再被直接视为冲突。要求已验证效果或用户田块处方时，项目计划答复不能完整替代。

文献向量、文献正文、案例索引与联网查询消费改写结果；回答与来源限制继续接受原问题约束。模型缺失、超时、输出无效时回退原问题与明确规则，并记录降级状态。

## 运行记录

`understanding.semantic` 保存模型、用量、意图、独立问题、有效检索 Query、改写接受状态、候选来源与覆盖理由；语义入口先于 `starred_match` 执行。两次模型调用的用量汇入响应用量。页面“本轮执行概览”新增“问题理解与 Query 改写”，历史记录缺失与当前降级分别说明。

## 验证

离线回归覆盖统一入口、明显不同的表述、实际向量/正文检索收到改写结果、范围保留、模型超时和非法输出、星标可用性、冲突、部分覆盖及“措施”误分类。浏览器检查覆盖新记录展示、旧记录兼容和窄屏布局。

使用当前真实模型与本地 25 条星标的只读快照回放：

- 原问题“怎样通过‘数据—模型—应用’实现氮素淋溶智慧管控”完整命中原维护答案。

- “已经验证的减排效果是多少”和“我的玉米田该怎么……施肥”均未采用项目计划作为完整答复。
