# 标签先确定文献范围

标签从召回线索提升为检索范围：已审核的标签名称、路径或精确别名可靠匹配后，先确定当前已同步、可用的文献集合，再进行正文检索、向量召回和重排。SQL 在截取候选前限制文献 ID；Chroma 在向量召回前限制元数据；引用前再次核验范围和正文版本。

- 同一维度内取并集，不同维度取交集；比较对象保留各自的条件组合，父标签包含子标签。未审核、待消歧或非精确别名不自动缩小范围。
- 用户侧不提供范围扩大的授权开关，也不展示检索策略文案。策略由系统内部处理，管理端运行记录保留标签、范围数量、扩大原因、有效片段数和检索耗时。API 请求不再提供该开关。
- 首轮优先保持标签范围。专业问题无可用正文、比较对象缺资料，或充分性核对指出具体必要解释缺口时，系统最多扩大本地检索一次。扩大仅放开标签成员资格，正文中的作物、地区、否定条件和来源资格继续核验。用户明确指定的标签范围始终保留。
- 检索失败不视为资料不足，不由此扩大范围；标签已覆盖全部可用文献时不重复补查。没有可靠标签匹配时直接使用本地正文与语义检索。
- 基础概念和通用解释不因缺少标签文献而扩大检索，可以直接使用明确标记的一般知识，不伪造本地引用。比较问题仍需逐个核对对象覆盖。
- 外搜继续仅用于确认必要解释缺口后的兜底；专业内容先补查本地。充分性核对限时 10 秒，超时或非法输出时不触发扩大或外搜。固定文件计算与机制证据合同继续执行各自的来源校验。

只读检查现有资料：玉米问题可将 223 篇可用文献限定为 102 篇；广西与玉米组合当前为 0 篇。该数字是当时的同步资料快照，用于核验范围，不代表完整请求耗时已经获得固定幅度的提升。

边界和评估指标：

| 维度 | 判断和观察指标 |
| --- | --- |
| 标签可靠性 | 只接受已审核、精确且无歧义的匹配；不使用未经校准的固定相似度阈值 |
| 条件正确性 | 明确范围突破、引用正文条件冲突和失效来源采用以 0 为硬目标 |
| 答案覆盖 | 核对实际问题和比较对象；标签或片段数量不能单独代表充分性 |
| 检索效率 | 范围缩减比例、有效片段比例、检索及整轮 P50/P95，分别观察基础问答和专业问答 |
| 补查收益 | 补查触发率、增加的有效证据及回答覆盖、额外耗时；无收益补查用于调整策略 |
| 外搜约束 | 基础解释已充分时外搜次数为 0；其余记录具体必要缺口，不以低标签命中率触发外搜 |

召回质量与耗时需用同一批标注问题和基线回放对比，避免只追求范围变小而漏掉必要资料。当前已有日志支持范围、有效片段和检索耗时观察；分位耗时与补查收益仍需汇总回放验证，不能把范围缩减当作已测得的提速比例。

验证包括真实 Chroma 在重排前过滤、默认内部补查、显式范围保留、检索异常、基础解释直答，以及补查本地后才考虑外搜。运行与请求回归 130 项通过，最终范围与外搜专项 58 项通过（有重叠）；前端聊天与运行展示 15 项通过，TypeScript、ESLint 和 diff 格式检查通过。
