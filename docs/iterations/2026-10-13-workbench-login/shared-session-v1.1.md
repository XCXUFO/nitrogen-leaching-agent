# V1.1 前台与工作台共享登录

需求日期：2026-10-13。完成第二项“前台登录打通”，沿用已有六个账号和三类角色，不改变账号密码与业务权限。

## 使用流程

- 前台点击“内部人员登录”，输入账号密码后自动返回前台，显示账号、角色、“管理工作台”和“退出登录”。也可直接在工作台登录，再返回前台。
- 当前标签页窗口中，前台 `/`、公开展示 `/showcase` 与管理工作台 `/evaluation` 共用一个登录状态，页面切换、直接输入站内地址及刷新均保持身份。
- 登录凭据使用 sessionStorage 保存，不存密码，不写入 localStorage；普通关闭标签页后清除，新开的独立窗口不会自动获得该标签页凭据。
- 恢复页面先向后端验证会话和角色，再展示内部功能。网络故障保留凭据并提供“重新验证登录”；401 清除共享登录状态。
- 前台或后台退出都会撤销同一后端会话，当前窗口所有页面随之恢复未登录状态。账号切换时重建前台对话，避免把前一个身份的历史或附件带入新身份。

## 身份与会话机制

根布局挂载 AccountSessionProvider。窗口每 5 分钟通过 `/api/eval/me` 续期，重新获得焦点时也验证；后端改为每次有效访问续期，取消原固定登录起算的 8 小时截止点。连续打开和正常运行的窗口可以跨越 8 小时保持登录。后端仍清理超过 8 小时没有任何续期的会话（例如设备长期休眠或断网），服务重启、主动退出或凭据变化后需重新登录。

前台聊天、附件上传、状态检查和释放均携带会话。后端验证会话后以已有 tester_id 记录内部操作人，并按内部身份隔离对话及附件。不采信请求正文伪造的内部人员 ID；公开访客机制和工作台 Execution 的原有身份归属保持兼容。未授权或已退出会话返回 401，不悄悄降级为访客完成操作。
