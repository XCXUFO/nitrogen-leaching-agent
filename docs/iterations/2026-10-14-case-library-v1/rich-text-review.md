# 示例材料驱动的功能优化与复查

本记录补充此前 V1.0 实现，范围限于案例库；工作区其他迭代不在本次复查范围内。

## 行为变化

- 正文采用 Tiptap 3.32 编辑器，支持段落、小标题、列表、Word HTML 表格粘贴、单元格编辑、增删行列、撤销和重做。保留空白单元格和单位符号；不还原 Word 字体、颜色、分页。
- 新增 `body_format=plain|html`；旧数据库启动时增量迁移，既有正文保持纯文本及原 revision。新富文本通过服务端标签白名单、结构和长度校验，去除事件、样式等属性，保留单元格跨度。详情使用编辑器的只读视图，不执行原始 HTML。
- 保存、解释草稿和两个 Skill 均传递完整的表格 HTML；列表摘要单独提取可读文本。容量限制包含 HTML，超限明确返回，不截断原始材料。
- 电脑端正文、解释并排；窄屏上下排列。新案例不再要求补充信息字段；旧案例已有补充信息继续展示、编辑和传给模型。
- AI 草稿改为结构化输出并校验非空文本，复用现有 `chat_json` 关闭模型思考模式，避免输出预算被思考消耗后返回空草稿。草稿仍需采用并保存，失败不改变正文或已有解释。
- 两个 Skill 共用事实约束：区分处理模式和计量口径、空白不补值、合计不拆算、保留条件和例外、无效果数据不评价优劣、冲突交人工核对。参考默认只挑相关案例，直接解释文本不强制检索。

## 复查与验证

工程检查：

- 后端相关回归 147 项通过：富文本校验、数据库迁移、表格 HTTP 往返、草稿和 Skill 输入、并发修改、关闭删除、会话与文件问答隔离、构建指纹。
- Chromium 4 项流程通过：原有增改查删和冲突恢复、Word 表格粘贴、空白保留、行列增删、单元格修改、草稿采用、保存刷新及窄屏可用。
- TypeScript、改动文件 ESLint、`git diff --check` 通过。

真实模型人工试跑使用隔离数据库，只将副本开放；没有把试跑回答写入本地正式案例，也没有改变本地案例开放状态。临时案例 ID 不对应本地录入 ID。

发现并处理的问题：

1. 首轮草稿返回空文本，修正为结构化非思考输出；新增空、错误格式及非文本草稿拒绝测试。
2. 直接解释三次合计时额外给出假设平均数；收紧约束，复测不再计算分次用量。
3. 参考回答罗列所有案例；限制为相关内容和少量案例，减少原文重复。
4. 模型将同为折氮量的两种做法说成不同计量口径，或给未命名基础做法冠以“常规”；补充区分规则。
5. 草稿混入本案例未出现的“三次合计”术语；明确约束不是事实、不得套用，复测清徐草稿不再混入。
6. 冲突回答偶有“以正文为准”的确定性措辞；明确要求先指出不一致并交人工核对，禁止替人工确认正确值。

7. 后续试跑曾把肇东复合肥产品用量误写成折氮量。增加逐案例核对计量口径的约束，并以温度 0 调用；定点复测见 [用量口径复测](material-probe-units-followup.json)。该发现也说明提示词约束不能替代专业核验。

原始试跑结果保留在 `material-probe-before.json`、`material-probe-round2.json`、`material-probe-round3.json`；最终结果见 [全问题试跑](material-probe-final.json)。这些是人工观察用的样本记录，不是自动评分平台，也不证明模型每次都能忠实解释。专业同事仍需核对生成内容，尤其是条件遗漏、模式命名和与原文矛盾的情况。

## 本地验收入口

`http://localhost:3000/evaluation/case-library`

沿用现有账号登录。建议先打开清徐玉米，确认第二次尿素为空、7 张表及第六次例外可见，再进入编辑生成解释，人工修改后保存。确认内容后开放案例，即可在详情页用两个 Skill 验证；关闭后新请求不可调用。
