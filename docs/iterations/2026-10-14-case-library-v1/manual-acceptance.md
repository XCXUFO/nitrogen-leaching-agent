# 案例与措施库人工验收

使用少量由专业同事确认的真实材料。建议至少覆盖：有多条措施的案例、只有案例但没有明确措施的材料、未记载结果且无来源的材料。不能为凑齐字段补造事实。

## 录入与协作

1. 仅填标题和正文保存，来源、解释、补充信息留空，默认不开放。
2. 保存带段落、编号和多条措施的正文，核对完整性；按标题搜索、开放状态筛选、翻页。
3. 未保存时生成 AI 初稿，核对读取的是当前原文及补充信息，数据库内容没有提前改变。
4. 已有解释时重新生成，旧解释不变；分别试放弃、采用、修改、保存。
5. 修改原文后看到一致性提示；AI 失败后仍可手填、保存。
6. 编辑中点击侧栏、取消、返回、刷新，验证未保存提示；拒绝离开后输入保留。
7. 两个窗口编辑同一案例，后保存者收到冲突且输入保留。取消“加载最新版本”保留输入；确认加载后使用最新内容和 revision 再编辑保存。

## Skill 效果

1. 开放案例后问“有没有类似案例？”：检查相关性、措施解释、适用差异、案例 ID 和来源。
2. 对无措施的案例，检查未将模型建议描述成原文措施；对无结果、无来源材料，不编造效果或引用。
3. 用“解释”问库内案例：检查人工解释被参考，与原文矛盾时以原文为准。
4. 直接粘贴专业文字，无论是否包含冒号或“措施”一词都可解释，不要求先录库；再问“详细解释它”，检查原文没有丢失。
5. 问一个缺关键条件的问题：具体追问应保留；连续补充作物、灌溉等条件后仍使用这些条件。
6. 先引用案例 A，再明确解释案例 B（ID 后直接跟中文也应识别），确保不继续引用 A。
7. 问“有没有其他可参考案例”，确保仍寻找参考而不是误识别成解释旧案例。
8. 问无合适案例的问题，应明确说明，不编造。
9. 关闭或删除已引用案例，再追问“解释刚才那个”：新请求不得继续调用。删除前提示标题，删除后列表不显示。
10. 开放内容或指定 ID 数量超过单次容量，明确提示缩小范围，不静默截断或返回通用内部错误。
