# 开发者全库一键打标

入口：管理工作台 → 标签管理（`/evaluation/literature-tags`）→ 全库一键打标。

- 仅开发者可以查看任务、发起任务、重试；后端对全部接口校验角色。
- 处理发起时全部未删除的已保存文献和案例，包括文献草稿、停用文献和未开放的案例；不受列表筛选或每页数量限制。未登记的临时上传文件不属于已保存资产。星标问答、会话附件目前没有共享标签关联，不在本次处理范围。
- 默认补充标签并保留已有选择；可选择重新打标、替换原选择。重新打标无匹配时清空原标签。文献根据 PDF 正文及标题、摘要、结论分类，案例根据正文及解释等字段分类，只选现有启用标签。
- 使用发起时的标签规则快照。规则变更、资产版本变化或删除时跳过并记录原因。可以按新标签重新发起任务；旧任务未完成项会被新任务接替，旧工作协程无法覆盖新结果。
- 有效标签要求标签本身、所属维度和全部祖先均启用；打标建议、保存校验和 Query 标签匹配共用这一规则。补充打标保留已有停用关联，禁止新增停用分支关联；旧停用关联不能满足文献登记的必填维度。
- 三个后台工作协程逐项领取任务，单项最多 90 秒；资产和成功回执在同一事务提交。任务、修改前后标签及发起人持久化。离开页面后可返回查看最近 10 次任务，每次分页查看全部结果。
- 失败可重试，成功项不重复处理。超过五分钟没有进展的未完成任务可手动恢复。重复提交运行中的任务会返回已有任务，避免重复打标。
- 仅更新标签及资产修改版本、修改人、时间；保留正文、登记状态和 Agent 使用状态。原有检索脏数据触发器会让后续检索读取更新后的关联。

接口（开发者登录）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/literature/asset-tag-jobs` | `{"mode":"merge"}` 或 `{"mode":"replace"}`，返回 202 |
| GET | `/api/literature/asset-tag-jobs` | 最近 10 次任务 |
| GET | `/api/literature/asset-tag-jobs/{id}?offset=0&limit=50` | 统计及逐项回执，单页最多 100 项 |
| POST | `/api/literature/asset-tag-jobs/{id}/retry` | 重试失败或中断项 |

验证：相关后端测试 37 项通过；浏览器测试 6 项通过（开发者发起、刷新恢复、失败重试、其他角色隐藏入口及标签删除回归）；TypeScript 和相关 ESLint 检查通过。测试均使用隔离数据库或模拟接口，没有调用真实模型批量修改现有资产。
