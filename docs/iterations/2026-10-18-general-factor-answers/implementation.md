# 全量文献检索衔接与一般影响因素回答

## 根因与文献数量

“氮素淋失主要受哪些因素影响？”在正式聊天返回固定的正文证据不足提示，Prompt 迭代却能生成解释。运行记录中的零片段是筛选后的结果，不能据此认定用户没有提供正文。最初仅添加通用知识兜底未解决文献衔接问题。

实际核对到的资料：

| 范围 | 篇数 | 原有索引状态 |
| --- | ---: | --- |
| 历史迁入文献 | 90 | 旧向量库有 12,472 个片段，但管理记录与索引未接通 |
| 后来新增文献 | 134 | PDF 已保存，尚未进入聊天全文索引 |
| 合计 | 224 | 224 份原件均存在；全文同步表为空 |

管理记录当时为 223 条题录草稿和 1 条已登记。旧逻辑一旦发现历史原件存在管理记录就拒绝旧向量片段，同时正文同步又要求登记，导致已有文献整体被排除。题录登记完成度被误用为正文能否检索的门槛。

## 最终行为

1. 启动时逐篇核对历史原件 SHA-256、已存在的向量片段和正文位置，把核对成功的片段关联到当前文献记录。沿用现有向量，不需要重新上传或重新计算历史向量。
2. 为全部已保存、启用且未删除的 PDF 自动建立正文文本索引。题录可继续保留草稿；不会伪造作者或发表信息，也不会自动完成登记。
3. 后台定期同步新保存或变更的文献，涵盖单篇和批量录入。元数据变更可复用原件正文；更换 PDF 时重新核对指纹和提取正文。失败记录保留具体原因，使用已有入口明确重试。
4. 停用、删除或内容变更立即使原证据失效。历史关联不覆盖已有同步状态，也不会恢复已停用、删除或待核对的版本；回答生成后仍复核来源。
5. 一般影响因素问题优先从已同步正文取材并使用当前表达 Prompt 展开解释。没有正文匹配时才继续向量检索；确实没有可用正文时，通用知识说明明确标注并且不添加虚构引用。
6. 指定论文和文件峰值归因继续执行已有证据校验。文献可用性筛选在重排前执行，避免为不能引用的片段做推理。

前端全文检索说明同步更新为自动同步，并展示历史向量接入模式。

## 真实资料副本验证

在真实文献数据库的隔离副本上验证，原件与原有向量库只读，未修改正式数据库：

- 历史 90 篇、12,472 个片段全部通过原件和位置核对；第二次接入新增 0 条。
- 新增 134 篇中 133 篇成功提取正文，1 篇无可读文字。
- 共 223 篇就绪、27,272 个片段；检索候选包含新增的全部 133 篇可读文献。
- 唯一未就绪原件为 `Leaching and Transformation of Nitrogen Fertilizers.pdf`，共 8 页，第一页无文本且包含图片，需文字识别；当前环境未安装 Tesseract，未把它标记为就绪。
- 原问题能检索到直接讨论灌水量、施氮量、土壤质地、根层氮素含量及剖面分布的正文。

Prompt 迭代原记录约 9～15 秒；正式聊天曾耗时 69.160 秒，其中检索占 69.016 秒，尚未调用答案生成。全量正文文本检索最初耗时 22.494 秒；将逐字符 Python 正则检查替换为等价的重叠双字提取后，相同副本、相同问题测得 2.981 秒。后者只是正文检索耗时，不是完整回答耗时；未宣称真实模型端到端速度已经验收。
