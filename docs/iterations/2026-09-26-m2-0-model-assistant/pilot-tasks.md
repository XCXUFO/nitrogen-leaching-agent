# M2.0 十个试评任务草案

状态：仅为任务设计，全部待资料确认与专业审核。不能直接作为有标准答案的测试集。
使用统一、版本明确且允许展示的 WHCNS 材料及同一套真实案例。

| ID | 用户任务 | 拟核对要点 | 依据与审核状态 |
|---|---|---|---|
| p01 | 我没有模型基础，WHCNS 能帮助研究什么？ | 简明用途、例子、条件与限制 | 版本说明/手册；待审核 |
| p02 | 给定一个研究目标，判断这个模型是否适合 | 目标与能力对应；缺信息时指出缺项，不武断判定 | 手册/审核情景；待审核 |
| p03 | 解释案例中的一个术语，并追问其含义 | 初学者可理解；追问指代正确；依据可定位 | 手册/案例；术语待选 |
| p04 | 开始该案例前需要准备哪些资料？ | 必需与可选条件分开，含义和单位正确 | 输入规范；待审核 |
| p05 | 用户只提供部分资料，请指出还缺什么 | 已提供项不重复索取；未知不猜测；下一步明确 | 审核后的缺项情景；待审核 |
| p06 | 更正一项已提供信息，再刷新继续准备 | 状态更新和恢复；原推断不冒充事实 | 任务状态记录/案例；待审核 |
| p07 | 用选定工具处理一份真实案例文件 | 输入检查或结果读取二选一；结果与文件定位一致 | 原文件及工具规则；待材料选择 |
| p08 | 处理同一案例文件的一个已知格式或单位问题 | 明确指出位置和原因；不产生误导性成功结果 | 保留原件的派生错误样本；待审核 |
| p09 | 对案例输出中的多个指标逐项解释 | 必答项齐全；数值、单位及计算可复核；说明专业含义 | 输出文件/手册；指标待选 |
| p10 | 判断能否把案例结论用于另一个条件不同的情景 | 区分可支持与不可支持结论；指出还需什么依据 | 限制说明/审核情景；待审核 |

## 每题在试评前补齐

- 题目版本、关联的三个首批任务之一、初始状态与允许使用的材料。
- 精确题面、用户操作、预期追问与任务完成条件。
- 必答要点；每一点对应来源 ID 和页码/章节/单元格。
- 不能得出的结论、可接受的不确定表述、错误或遗漏的判定。
- 专业审核人、日期、审核状态；未审核不得算正式评分依据。

不要求长篇标准答案。不要将模型生成答案直接填为事实或审核结果。

## 冻结回答与评审记录

每次试评保存任务与问题版本、run ID、代码/模型/资料版本、完整任务上下文、
冻结回答、引用证据快照及定位、工具输入哈希和结果、生成时间。
评分引用这个快照，保留审核者、时间、修订记录与具体错误位置。

建议四维试评分档（试评后完善，正式比较前冻结）：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 正确性 | 关键事实错误 | 部分错误或表述需修正 | 核心事实正确 |
| 完整性 | 缺失核心必答项 | 部分必答项遗漏 | 必答项完整 |
| 证据支持 | 关键结论无依据或矛盾 | 部分依据不充分或定位不清 | 关键结论均有对应依据 |
| 可理解性 | 无法理解或继续任务 | 需要额外解释 | 能理解并知道下一步 |

每维也可选“无法判断”或“超出专长”，不换算成通过分数；报告已评分分母。
严重专业错误单列，不用其他维度的高分抵消。

专业审核与新手试用分开记录。新手另记任务完成、是否需要帮助、耗时、卡点、
先验经验及满意度；“觉得好用”不替代“任务做对”。这些题可用于调试，
正式比较需要另设未参与调参的测试任务。
