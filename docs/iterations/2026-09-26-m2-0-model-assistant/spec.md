# M2.0 — 模型认知与使用辅助版

日期：2026-09-26。状态：范围已定义，功能待实现。此文替代旧的“完整 Agent”下一阶段目标。

## 1. 目标与首批任务

用户无需土壤与模型基础，也能在助手引导下理解模型用途、判断使用条件、
准备必要资料，并解释一个真实案例的结果；整个过程有依据、可复核，不依赖原平台在线。

WHCNS 为第一个重点模型，必须具备实质资料和完整案例。其他模型沿用统一资料结构，
后续再加入。独立运行指核心流程不调用原平台；现有 DeepSeek API 依赖仍需说明。

首批任务：

| 任务 | 用户输入 | 完成标志 |
|---|---|---|
| 认识模型 | 我不了解 WHCNS，帮我理解它能做什么 | 能用自己的话说明用途、适用条件和至少一项限制，并找到依据 |
| 准备使用 | 我想研究某个问题，还需要准备哪些资料 | 得到与目标及已提供信息对应的资料清单、缺项和下一步；未知条件保持未知 |
| 解读结果 | 帮我看懂这份案例输出 | 关键数值能对应文件位置、单位和工具记录；区分支持与不支持的结论 |

功能优先级由是否帮助完成上述任务决定，不以工具数量或框架复杂度判断完成度。

## 3. 范围与设计约束

### 3.1 首页与分层回答

首页提供“认识模型／准备使用／解读结果”入口和可直接开始的示例任务。
回答先给简明解释及必要例子，再按问题需要补条件、限制、依据和下一步；
详细原理可展开，不强制每轮生成长报告。

对多指标问题，建立“用户要求项 → 证据位置 → 答案覆盖”的检查：
每个项目区分已找到且已回答、证据不足或存在冲突。用户未要求的事实不随意补充；
缺项需明确说明。检查需覆盖一般问题，不按题号、固定答案或预期数字编写补丁。
保留 q06、q14、q18 作回归，并增加未参与该修复的类似问题。

### 3.2 模型档案与引用

统一记录模型 ID、版本、用途、适用条件、输入要求、输出含义、常见错误、
限制及逐项证据。模型版本不明时明确待确认，不能混用不同版本的参数要求。
资料目录字段及首个资料包见 [materials.md](materials.md)。

来源区分论文、手册、案例；展示真实标题、版本或年份、页码或章节。
不存在的元数据保持未知，不编造定位。优先为核心模型资料和案例补定位，
检索分数移至调试区。引用片段是证据候选，不自动证明整个答案正确。

### 3.3 任务状态

独立保存任务 ID、目标、模型及版本、用户已提供信息及来源、已确认项、
待确认项、缺失项、当前步骤、下一步、关联案例和工具记录。
用户可查看、更正和清空；刷新页面后应能恢复该任务。
实现可采用轻量本地或服务端持久化，选型随实现记录，不需要完整用户体系。
明确区分用户陈述、程序校验结果、审核资料与模型推断。
历史回答不能自动变成已确认参数或专业证据。

### 3.4 一个真实案例与一种工具

先取得版本一致、经同门确认且允许展示的真实输入输出，定义案例清单与预期结果。
工具选择依赖材料：格式稳定的输入文件优先输入检查；输出资料更完整时优先
结果表读取与数值核对。第一版仅实现其中一种，不以合成数据冒充真实案例。

程序负责格式、字段、单位和运算；专业范围阈值必须来自审核材料，不能自行猜测。
记录原始文件哈希、工具与规则版本、参数、结果及错误；结果关联表、行、列或单元格。
不可解析、缺单位、缺列或版本不匹配时提供具体错误，不输出貌似成功的结论。
原文件保留，派生输出可复算。专业解释由对应资料支持，不能从一次案例外推所有地块。

### 3.5 轻量评审入口

评审对象为冻结的问题、任务上下文、回答、证据和工具结果。
保存 run ID、代码版本、模型与配置、语料/案例版本、回答标识、审核者标识和时间。
刷新恢复评价，修改保留修订记录；不能每次打开重新生成回答。
支持正确性、完整性、证据支持、可理解性评分，以及错误位置、无法判断、超出专长。
不要求复杂用户权限；具体开放方式与资料可展示范围一并确认。

## 4. 相对四周计划

起点为实际启动日，不沿用旧月份。每周专业短审核需先约定人员；资料延迟明确记录依赖。

| 周 | 工作 | 可检查交付 |
|---|---|---|
| 1 | 固定基线、真实问答计时、定义范围、收集资料、准备试评 | 复现记录、备份清单、资料目录、三个任务和 10 个试评任务草案 |
| 2 | 首页、分层回答、引用、WHCNS 档案、任务状态 | 新手能连续完成用途—条件—下一步引导；状态可恢复和更正 |
| 3 | 做通真实案例，交付一种工具 | 从实际文件到结果解释，数值可定位、运算可复算、错误可诊断 |
| 4 | 开放评审入口、专业审核、新手试用、修复与冻结 | 评审与用户任务记录、已知问题清单、版本及完整演示 |

## 6. 评测与发布验收

三组资料分别管理：M1.6 回归集、10 个试评任务、未参与调参的正式测试集。
试评可用于改进，不宣称独立验证；正式题目与评分规则在比较前冻结。

专业审核者判断正确性、完整性、证据与边界；新手完成任务后记录完成与否、卡点、
耗时、是否需要帮助和满意度。无法判断、超出专长、缺资料单列，不能计为正确。
任务完成依据预先确认的要点核对，满意度单独统计。

正式比较优先回答：

1. 同样资料与模型条件下，新版相对原 RAG 是否更少遗漏、适用条件更准确？
2. 初学者相对只看相同版本手册，是否更容易完成指定任务？

记录参与者先验经验；平衡任务顺序或使用等价任务，减少学习效应。
样本量、评分规则和分母随报告发布；四周试用不承诺统计显著性或预设提升百分比。

M2.0 发布须具备：

- 三个任务均有可复现流程，至少一套经专业确认的真实案例。
- 原平台不可用时核心流程仍可演示；外部 LLM 等依赖明示。
- WHCNS 关键用途、条件、参数和案例结论均可追溯；未审核项明确标记。
- 一种工具有成功、缺项及错误格式的验证，关键数值与原文件一致。
- 任务状态可恢复、更正和清空；评审回答冻结、评分和版本可保存。
- 有实际专业审核与新手试用记录；阻碍核心任务的错误修复并复核。
- 保留 M1.6 回归结果，新旧差异逐项解释，不能靠重新降低评分口径消除回退。
- 提供版本标识、演示步骤、已知限制和完整演示记录。
