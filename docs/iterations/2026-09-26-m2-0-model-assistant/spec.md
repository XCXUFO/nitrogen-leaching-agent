# M2.0 — 单一对话窗口中的农业模型助手

更新：2026-09-28。本版替代“教学引导、三个入口、普通用户评审页面”的旧规划。
已实现本地结果读取器；本轮接入网页上传、聊天分流及文件证据。手册检索仍待实现。

## 1. 产品范围

用户提出问题或提供文件 → 系统分析问题 → 检索资料或调用工具 → 在对话中返回结果；
信息不足时追问。只保留一个对话入口，围绕问题解决能力验收。

- 面向农业模型相关问题；专业解释按需提供，不承担课程或系统学习流程。
- WHCNS 为首个重点模型，核心能力独立于原平台；文献问答仍有 LLM API 依赖。
- 在线执行 WHCNS、自动校准、自动施肥决策不作为当前交付前提。
- 专业审核是研发验证流程，不进入普通用户界面。
- 不将文件读取成功称为案例已复现；模型版本、输入输出配对、日期及部分字段语义待确认。

## 2. 保留基线

M1.6：FastAPI、Next.js、DeepSeek、本地论文检索、重排、数值证据增强、
最近 12 条消息及引用。90 篇论文、历史索引 12,472 片段。
24 题中 21 题演示可用为参与调优后的开发侧自评，只作回归基线，不作独立准确率。
已有 CLI 结果读取器与原件登记保留；原件与派生数据不入 Git，不执行 WHCNS.exe。

## 3. 本轮最小闭环

验收问题：上传 `Nbal_out.xls` → “硝态氮淋失最大值及对应日序” →
程序计算 → 同一对话返回数值、单位、日序、数值/日序单元格及文件来源。

实现契约：

- 聊天输入支持一个当前附件，可更换、移除或清空；附件存在时后续问题继续使用它。
- 接受 XLS/XLSX，按字节判断格式；仅支持已登记的 `Nbal_out`/`WtaBal_out` 严格结构。
- 后台校验字段、精确单位、有限数值及连续正整数日序，拒绝静默丢列、日期猜测。
- 支持整表单个显式字段的最大值、最小值及模型日序；并列时显示首条并注明数量。
- 字段不清、缺文件、总量/时段/解释等超出本轮规则的问题先说明范围并追问。
  不承诺通用自然语言理解；不从聊天历史猜测缺失字段。
- 带附件走确定性工具；无附件的一般知识问题保留 RAG。失效附件不回退为虚构文件回答。
- 答案先给结论，再给必要说明和证据；检索分数、健康探针、session 信息不展示在普通界面。
- 上传不超过 10 MiB。摘要仅单进程暂存 30 分钟、最多 32 份；原始临时文件解析后删除。
  刷新或后端重启后重新上传；本轮不承诺持久任务状态。
- 文件通路无需 API key、向量索引或执行模型；原有文献问答依赖不变。

2. 完成本轮上传 → 工具计算 → 回答和文件证据，处理失败与追问。

   每一类有可测试决策，不以复杂 Agent 框架为验收条件。
5. 扩展回答覆盖、引用与追问回归，再进行专业审核和用户任务验证。

## 5. 测试与验收

- 合成表覆盖数值、单位、非 1 起始日序、并列极值、单元格与哈希一致性。
- 上传覆盖坏文件、公式、缺字段/单位、容量、格式、过期 token 和路径文件名。
- 文件链路在无 RAG/LLM 条件下通过；知识问答原接口、历史和错误契约保持回归。
- 实际收到的两份输出表作本地核对，独立检查关键值和坐标，不把合成表当真实案例。
- 前端 lint 和生产构建通过；演示需说明附件生命周期、明确支持的问题范围和未确认信息。
- 研发记录区分 M1.6 回归集、试评任务和未用于调参的正式测试集；
  专业正确性、完整性、引用支持、追问合理性分别评估。
- 报告明确自动测试、真实文件核对和真人浏览器验收各自做了什么，不能相互替代。
