# 每轮运行的可读概览

入口：管理工作台 → 运行记录 → 会话详情。每轮回答下方默认展示“本轮执行概览”；原“展开本轮 MQ 明细”、各组底层字段和“完整运行记录”继续保留在下方，按需展开。

概览分为四部分：

1. 关键词与标签：关键词、已匹配关键词数、去重标签数、歧义候选及用途；星标已覆盖而未进入后续映射的关键词单独说明。
2. 资料召回、排序与采用：每次检索的问题、关联子任务和 Skill；按资料去重展示候选来源、排序位置、送入模型的位置和最终引用状态。具体检索批次用 `retrieval_id` 关联，避免同一轮多次检索混淆。语义检索可展开查看实际重排前、重排后和本路返回的名单。
3. 实际调用的 Skill 与步骤：实际 Skill 调用、服务和工具执行状态、耗时及工具所属 Skill；计划候选保留在底层明细。
4. 最终输出：区分星标直接复用、星标答复加后续处理、文件结果加文献说明，以及单路生成；展示输出段落和最终证据来源。多个检索来源或多个准备步骤不直接等同于组合输出。

新运行新增的追踪字段：

- `retrieval[].semantic.rounds[]`：每路语义检索的实际召回名单、`rerank_status`、重排名单、返回名单；不重复保存正文。
- `retrieval[].ranked_candidates`：融合、条件核对后进入上下文预算选择的排序；案例记录预算选择前的相关度排序及逐项筛选原因。
- `retrieval[].stage = model_context`：实际进入提示词的片段标识及来源名单。会话上传文档也记入候选。
- `retrieval[].skill`、`skill_step_id`、`subtask_ids`：对应的执行能力和任务。
- `answer_assembly`：实际输出组织方式、段落类型、来源类型、能力调用和结果。
- 文献候选补充标题，最终文献证据补充已有的文献 ID，便于直接打开管理页。
- 召回来源兼容旧字符串列表与实际融合结果的 `{route, rank}` 对象列表，显示每路召回及其排名。
- 新文献引用和案例引用保存 `retrieval_ids`，最终证据保留该批次；文献按篇合并时，同时保留实际引用过的 `chunk_ids` 与全部来源批次，未引用候选不参与合并。

引用批次的兼容规则：有来源批次时按该批次关联实际取材；历史记录只有在送入模型的确切片段能唯一定位批次时才标记“已引用”。同一来源可能属于多个检索批次、或只有文献级匹配时显示“批次未确认”，不计入已确认引用数。已排除或未送入模型的候选不因其他轮次引用了同一篇文献而被标记为已引用。

兼容规则：旧记录缺失阶段时显示“未记录”；未启用重排时明确说明；不把筛选通过当作已送入模型，也不把送入模型当作已引用。新增字段只用于观察执行，不改变检索、排序、提示词或答案组织行为。原始记录仍可完整展开核对。

验证：检索、执行链路和星标输出相关后端回归通过；11 项浏览器用例通过，覆盖多轮隔离、重排前后名单、实际取材与引用、原始 JSON 展开、星标完整与部分覆盖、旧记录、手机布局及原有审核流程。TypeScript、相关 ESLint 和 diff 格式检查通过。

Review 修复验证：相关后端回归共 292 项、追问 / 账户历史 / 概览浏览器回归共 18 项通过。新增用例覆盖真实的对象型召回来源、被排除的同篇候选、重复片段的显式批次归属、历史记录的批次歧义，以及引用合并时保留多个实际来源批次。
